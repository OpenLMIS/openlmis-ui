# OpenLMIS UI

Web frontend for OpenLMIS.

## Quick Start

Requires Node 24 (see `.nvmrc`) and pnpm 12 (pinned via `packageManager` in `package.json`).

```bash
cp .env.example .env
pnpm install
pnpm dev
```

## Architecture

### Data Fetching Pattern

- **TanStack Router** owns the route structure and navigation
- **TanStack Query** manages all server state
- Data is fetched at the route level, consumed at the component level

Navigation should not wait on data. The loader starts the request and returns; the page
shell renders straight away and only the part that needs the data suspends.

```
Route loader (prefetchQuery, not awaited)
  → shell renders immediately
  → <Suspense> boundary around the data-dependent subtree
    → Component (useSuspenseQuery)
```

Block the transition only when the route genuinely cannot render without the data, such as
a detail page that must 404 on a missing record. In that case `return` the
`ensureQueryData` promise so the router awaits it and shows the route's pending component.

Because `useSuspenseQuery` throws rather than returning an error state, wrap suspended
subtrees in a `CatchBoundary` so a failed query degrades that section instead of the whole
page. See CLAUDE.md for the full pattern.

### Feature-Based Structure

Each feature is self-contained with its own queries, components, and types.

```
src/
  index.tsx                        # Entry point
  globals.css                      # Global styles + OpenLMIS theme tokens
  route-tree.gen.ts                # Auto-generated by @tanstack/router-plugin, committed, never edit
  integrations/
    axios.ts                       # HTTP client (bearer token + 401 handling)
    i18n.ts                        # i18next setup (ICU, HTTP backend, language detection)
    tanstack-query.ts              # QueryClient instance
    tanstack-router.ts             # Router instance + type registration
  types/
    i18next.d.ts                   # Type-safe translation keys
  routes/
    __root.tsx                     # Root layout + devtools
    index.tsx                      # / -> redirects to /dashboard
    login.tsx                      # /login (public)
    (protected)/
      _protected.tsx               # Protected layout (sidebar + auth guard)
      _protected.dashboard.tsx     # /dashboard
  features/
    auth/
      api/api.ts                   # Token exchange + logout
      hooks/use-auth-actions.ts    # login() / logout() with toasts
      lib/types.ts                 # Login schema + response types
      store/login-data.ts          # Persisted auth store (zustand)
  components/
    text-direction.tsx             # Syncs <html lang/dir> + Base UI direction with the language
    workspace.tsx                  # Compound page layout (title/description/actions/content)
    app-shell.tsx                  # SidebarProvider + sidebar + header
    app-sidebar.tsx                # Icon-collapsible sidebar driven by NAV_GROUPS
    app-header.tsx                 # Top bar: trigger, breadcrumb, search, notifications, user
    command-palette.tsx            # Ctrl/Cmd+K navigation palette
    notifications-menu.tsx         # Notifications popover
    nav-user.tsx                   # User dropdown, takes its own trigger
    logo.tsx                       # Brand lockup (mark + wordmark)
    ui/                            # shadcn generated components (not linted)
  hooks/
    use-mobile.ts                  # Shared hooks
    use-mobile.test.ts             # Tests next to what they test
  lib/
    config.ts                      # App configuration + supported languages
    key-factory.ts                 # TanStack Query key factory
    types.ts                       # Shared types
    utils.ts                       # Shared utilities (re-exports `cn`)
  tests/
    setup.ts                       # Global test setup only
public/
  locales/
    en.json                        # English translations (flat, sorted keys) - source of truth
    pt.json                        # Portuguese translations
    ar.json                        # Arabic translations (RTL)
scripts/
  sort-messages.mjs                # Sorts translation keys alphabetically
```

### App shell

The protected layout is an icon-collapsible sidebar (`Ctrl/Cmd+B`) plus a top bar, adapted
from the `@7ovr/app-shell-1` block. `NAV_GROUPS` in `src/lib/config.ts` is the single
source for both the sidebar menu and the `Ctrl/Cmd+K` command palette; entries with
`to: '#'` are placeholders that render as non-navigating buttons and are left out of the
palette, which only lists real routes.

### Right-to-left (RTL)

Arabic is a supported language, so **every screen has to render in both directions**. This
is a standing constraint on new code, not a later migration.

- `components.json` sets `"rtl": true`, so `shadcn add` emits logical classes. Existing
  components were converted with `pnpm shadcn migrate rtl`.
- `SUPPORTED_LANGUAGES` (`src/lib/config.ts`) declares a `dir` per language;
  `getTextDirection()` resolves it and lets region subtags fall through (`ar-EG` is `rtl`).
- `TextDirectionProvider` (`src/components/text-direction.tsx`) wraps the app. It writes
  `<html lang>`/`<html dir>` in a layout effect, so the first frame is never painted LTR,
  and passes the same direction to Base UI's `DirectionProvider` so portalled menus,
  popovers and tooltips flip with it.
- `AppSidebar` reads `useDirection()` and anchors itself to the inline start.

**When writing components:**

| Instead of | Use |
|---|---|
| `ml-*` / `mr-*` | `ms-*` / `me-*` |
| `pl-*` / `pr-*` | `ps-*` / `pe-*` |
| `left-*` / `right-*` | `start-*` / `end-*` |
| `border-l` / `border-r` | `border-s` / `border-e` |
| `rounded-l-*` / `rounded-r-*` | `rounded-s-*` / `rounded-e-*` |
| `text-left` / `text-right` | `text-start` / `text-end` |
| `space-x-*` | `gap-*` on a flex/grid parent |
| `slide-in-from-left/right` | `slide-in-from-start/end` |

Icons that point along the reading axis get `rtl:rotate-180` (`ChevronLeft`, `ArrowRight`,
`LogOutIcon`, `PanelLeftIcon`). Icons whose meaning is not reading-order do not
(`RotateCcwIcon`, `SearchIcon`, chart marks such as `TrendingUpIcon`).

Base UI floating components take logical `side` values - use `"inline-start"`/`"inline-end"`
on `TooltipContent` and `DropdownMenuContent`. `Sidebar` and `Sheet` are the exception:
their `side` is physical, so the rules keyed off `data-[side=...]` are physical too.
CLAUDE.md lists those exceptions in full.

To check a change, run `pnpm dev`, switch the language to العربية, and walk the screen.

### Authentication

`/login` posts to the OpenLMIS auth service (`POST /api/oauth/token?grant_type=password`).
The service authenticates the *client* over HTTP Basic first, so the request carries a
`Basic base64(VITE_AUTH_SERVER_CLIENT_ID:VITE_AUTH_SERVER_CLIENT_SECRET)` header on top of
the user's credentials.

The resulting access token lives in a persisted zustand store
(`src/features/auth/store/login-data.ts`, `localStorage` key `login-data-storage`). It is
readable outside React so two non-React callers can reach it:

- the axios request interceptor, which attaches `Authorization: Bearer <token>`
- the router `beforeLoad` guards - `_protected.tsx` bounces anonymous users to `/login`,
  and `/login` bounces authenticated ones to `/dashboard`

A `401` from any request clears the store and routes back to `/login`.

In development nothing talks to the API directly: the Vite dev server proxies `/api` to
`VITE_API_PROXY_TARGET`, which keeps the browser same-origin and avoids CORS.

### Build Optimization

`vite.config.ts` defines `vendorChunks` to split large, stable libraries (React, TanStack) into separate cached chunks. Browsers don't re-download them when only app code changes. Other deps land in the default vendor chunk - splitting small packages costs more (extra HTTP requests) than it saves.

wrapper element.

## Conventions

- **File naming**: kebab-case (enforced by Biome)
- **Types**: `type` over `interface` (enforced by Biome), always use named `Props` types (e.g. `type UserCardProps = { ... }`)
- **Imports**: Auto-sorted by Biome, always use `@/*` aliases
- **Path aliases**: `@/*` maps to `src/*`
- **Data fetching**: `ensureQueryData` in route loaders, `useSuspenseQuery` in components
- **HTTP**: Use `client` from `@/integrations/axios`, `async/await` over `.then()`
- **Auth**: `beforeLoad` in `_protected.tsx` for route-group-level authentication
- **Tests**: Colocated with source files (`foo.ts` → `foo.test.ts`), `src/tests/` is for global setup only
- **i18n**: Always flat keys (never nested) in `public/locales/<lang>.json`, sorted alphabetically, ICU MessageFormat, type-safe `t()` calls, `SUPPORTED_LANGUAGES` in `src/lib/config.ts`
- **RTL**: Logical CSS properties only (`ms`/`me`/`ps`/`pe`/`start`/`end`/`text-start`), never `ml`/`mr`/`pl`/`pr`/`left`/`right`/`text-left`. See [Right-to-left](#right-to-left-rtl)
- **Package manager**: pnpm

## Deployment

`openlmis-ui` runs as a container inside an existing OpenLMIS stack, beside the
legacy `reference-ui`, serving a URL prefix (`/v2`) so both UIs are available at
once and users choose per screen. Routing comes from Consul KV, so the shared
nginx gateway needs no change.

```bash
docker compose up --build   # Consul + the real gateway, then http://localhost:8080/v2/
```

See [docs/deployment.md](docs/deployment.md) for how the routing works, why the
prefix is a build input rather than runtime config, and the snippet to add to
`openlmis-deployment`.
