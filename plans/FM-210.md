# FM-210: Onboarding Tour: Administration Editors And Detail Pages (Generic Tour)

https://openlmis.atlassian.net/browse/FM-210 · Parent: [FM-199] Guided onboarding tours for new users
(React Joyride, isolated module)

Stacked on FM-209 (PR #162).

## Scope

- **In:** one generic editor tour for the Administration pages opened from the lists:
  - Facility (new, edit), Product (General, Programs, Facility Types, Kit Unpack List), Requisition
    Template, Edit User Roles;
  - Reason (new, edit), Requisition Group (new, view, edit), Supervisory Node, Supply Partner.
- **In:** a short tour for the two CSV pages, Equipment Catalog and Ideal Stock Amounts.
- **In:** `data-tour` attributes on loaded parts, plain wrappers, new keys in `TOUR_ANCHORS`; reuse of
  the shared `list-*` anchors (FM-207) and `onboarding.list.*` copy (FM-209).
- **In (shared module):** the runner takes the first *shown* match of an anchor, not the first match
  (decision 3).
- **Out:** the Rejection Reason and Category detail routes (they redirect to a dialog over the list,
  which the list tour covers); dialogs, which steps describe; restructuring screens (no switching remove
  buttons to `RowActions`, no shared form-grid component), per the block rule: tours only.

## Summary

Every Administration editor gets a Show Guide button. One guide serves them all, because they share the
same shape: the record's details, tabs where the record has several parts, lists of linked items with
an Add button and row actions, and Cancel and Save at the bottom. A page plays only the steps for the
parts it has, so a short editor such as a Supply Partner shows a few steps and a Facility shows more.
Two pages add their own step: dragging columns into order on a requisition template, and importing
roles from another user on Edit User Roles. The CSV pages get a three-step guide: instructions,
download and upload. Legacy has no guide.

### Rules

- **Anchor only where the part works** (vault A70): no Add or Save anchor on read-only pages (Product
  without the right, Requisition Group view); Facility's always-shown Add Program counts as usable.
- **Loading:** an anchor never sits on a skeleton; pages whose loading view is not marked busy get
  `aria-busy` (decision 4) so the guide waits.
- **First shown match** (decision 3): Requisition Group keeps both tab panels mounted, so the first
  `list-table` can be the hidden Programs list while Facilities is open.
- **Copy:** generic, true on every page and in both layouts; names labels each page shares (Cancel,
  Save); "where shown" for parts some pages lack.

### Risks

- **Products' tabs are routes:** the tabs step explains switching; no `select` step, since clicking
  navigates.
- **User Roles on Profile:** `RoleTabs` also renders on `/profile/roles`; anchors there are inert, since
  that route has no tour.

## UI/UX

- **Improve:** a guide where legacy has none.
- **Phone:** column steps fall back to the first row's actions and the list; tables become cards.
- **Arabic:** placements mirror through the module.

## Decisions

1. **One editor tour plus page-only steps:** the shared shape suits one tour; Template reorder and
   User Roles import are steps whose anchors exist only on that page.
2. **CSV pages get their own tour:** they share no part with the editors.
3. **Runner uses the first shown match:** fixes kept-mounted tab panels; no tour relied on a hidden
   first match.
4. **`aria-busy` on unmarked loading parts** (recommended, as FM-208): `FieldSkeleton` and the
   `LookupBoundary` fallback (shared, covers every editor), Facility and Template editor skeletons,
   Reason pairs skeleton, Supervisory Node add picker skeleton.
5. **No screen restructuring:** remove buttons stay as they are and lose a row-actions step.
