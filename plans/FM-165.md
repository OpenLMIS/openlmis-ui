# FM-165: Offline Approach

[FM-165](https://openlmis.atlassian.net/browse/FM-165)

## Team Summary

Adjustments is the first complete offline workflow. After signing in while connected, a user
can download home stock, reopen Adjustments without a connection, save a draft, sign and queue
an event, then sync it when connected with a valid session. Offline Events provides the recovery
decisions needed when sending fails or the result is unknown. Stock On Hand and Stock Card
remain online-only; their offline views and history caching move to FM-166/the next PR. Queued
events do not change downloaded balances.

Dexie is the durable business store. TanStack Query remains the in-memory server cache;
persisting it would mix partial page results, rights and freshness with deliberate complete
downloads. A service worker saves app files, configuration and translations, never API responses.
The backend has no stock-event idempotency key, so an uncertain upload always needs a human
decision before another attempt. Synced requires a durable acceptance or explicit user receipt.

## API Map

Business calls retain the shared `/api` base, independent of the app's `/v2` asset prefix.
Download readers traverse every page and validate referenced identities before publishing.

| Purpose | Method and path | Contract |
| --- | --- | --- |
| Sign in or renew | `POST /api/oauth/token` | Existing same-user authentication flow |
| Probe and deployment time zone | `GET /localeSettings` | Public reachability probe; deployment locale setting |
| Scoped grants | `GET /api/users/{id}/permissionStrings` | Preserve raw permission strings |
| User context | `GET /api/users/{id}` | Whitelisted identity and home facility |
| User programs | `GET /api/users/{id}/programs` | Intersect supported home programs and grants |
| Home facility | `GET /api/facilities/{id}` | Facility type and supported programs |
| Stock summaries | `GET /api/v2/stockCardSummaries` | Facility/program, `nonEmptyOnly=true`, all pages |
| Current products | `GET /api/orderables` | Repeated ids in batches of at most 100; all pages |
| Product versions | `POST /api/orderables/search` | Read-only `{identities: [{id, versionNumber}], page, size}` |
| Referenced lots | `GET /api/lots` | Repeated ids in batches of at most 100; all pages |
| Barcode mappings | `GET /api/tradeItems` | Referenced trade-item ids, paging; only when scanning enabled |
| Adjustment reasons | `GET /api/validReasons` | Program and facility type; adjustment-category filtering |
| Submit event | `POST /api/stockEvents` | Frozen Adjustment body; verified 201 UUID is acceptance |
| Review server events | `GET /api/stockEvents` | Facility/program, adjustment type, paging; viewing right |
| Full Stock Card | `GET /api/stockCards/{id}` | Online-only summary and line items; no device history cache |
| Known server event | `GET /api/stockEvents/{id}` | Online receipt/header read with viewing right |
| Server event lines | `GET /api/stockEvents/{id}/lineItems` | Online paged detail read with viewing right |
| Log out | `POST /api/users/auth/logout` | Existing logout after local flush and warning |

Adjustments sends facilityId, programId, signature, eventOrigin `ADJUSTMENT` and lineItems.
Lines retain orderableId, lotId, quantity in doses, occurredDate, reasonId, reasonFreeText and
applicable VVM extraData. Omit documentNumber so the server assigns its normal sequential number.
Product pack size is required for pack/dose conversion; product identities include version.

The server rejects a whole event if a debit makes stock negative at its occurred date or a
later movement, including backdated debits. That is a Stock Changed refusal, not a draft to
silently rebase. Current stock cannot prove that an uncertain event was recorded.

## Architecture And Ownership

Keep the module map short and role-based so internal event component renames do not become a
second architecture contract:

- `src/lib/`: generic download providers/coordinator, access, schedule, connectivity, locks,
  revisioned draft storage/writer, session scoping and shell capability helpers.
- `src/features/stock-events/`: home-stock dataset, event-kind policy, draft/submission hooks,
  frozen queue, delivery/uploader and Offline Events recovery UI.
- `src/routes/`: signed-in service composition and provider registration.
- `src/integrations/local-db.ts`: database ownership and schema upgrades.
- `src/lib/service-worker.ts`: registration, update readiness and guarded activation.

Features never import each other except reference-data. Routes wire feature policies and raw
readers into shared infrastructure. Shell capabilities describe which routes can work offline;
they do not claim that a download is ready. Provider scope selection owns data eligibility.

### Download Providers And Home Stock

A provider has a unique dataset id, translated label, storage table, scope builder, fetcher,
freshness predicate and acceptance validator. Scopes carry a complete storage key, display
id/name and optional facility/program refresh key. Empty scope sets are valid. Keep route
capabilities separate from provider data contracts; do not add provider `pages` or `eligible`
fields when extending the refactored contract.

The home-stock provider selects supported user programs at the home facility with both
`STOCK_ADJUST` and `STOCK_CARDS_VIEW`. It stores complete owner-scoped generations in
`homeStockDownloads`. Format 4 retains hydrated card products and exact versions, children/program
membership, lot codes/expiry, balances, active state, last-update dates, reasons and referenced
GTIN mappings when scanning is enabled. Redundant summary groups and the separate product list
are removed. Incompatible older bundles require a fresh download; drafts and queued events remain.
It contains no transaction history. Database version 10 deletes the former `stockCardHistory`
table while preserving home stock, drafts, queues and receipts.

The access snapshot stores whitelisted user/home/program data, raw permission strings,
generation, format and download time. It contains no token or password. All referenced product
versions must resolve; unversioned lookup selects the highest available version consistently.
Unknown scans in a complete local bundle mean unavailable in local stock, not unregistered.

### Coordinator, Schedule And Backoff

Only the coordinator publishes complete access or dataset generations under the database's
download Web Lock. Foreground online reads may join in-flight work, but never persist partial
snapshots. Failed refreshes retain older compatible complete generations and local edits.
Background reads fail fast; foreground reads retain normal session renewal behavior.

Access and bundle freshness is 30 minutes. Visible tabs check once per minute. A per-database
schedule shares access and dataset failure deadlines across tabs: 1, 2, 4, 8, 16, then 30 minutes.
Recheck deadlines under the lock. Explicit Retry, reconnect and same-user renewal bypass the
periodic delay. Accepted events request a nonblocking refresh for their facility/program.

Download triggers coalesce in priority order force, retry, boot, refresh. Accepted-event refresh
runs stay silent; they cannot silence an already visible user retry or boot download.
Without Web Locks, background downloads and automatic uploads are disabled with an explanation.
Connected reads and draft saves still work; never replace the lock with a timeout lease.

### Durable Data And localStorage

Each deployment/user owns `openlmis-ui:<deployment>:<userId>`. Identity changes close the active
database and clear transient query state. Log Out retains records but requires online sign-in
to access them again. Check captured session/owner scope after asynchronous work and inside
write transactions. A late upload result may be saved only for its captured original owner.

Dexie holds access, home-stock downloads, inventory/event drafts, queue, sync errors and receipts.
Schema version 8 replaces the unreleased adjustment download table with homeStockDownloads;
version 7 remains for development upgrades. Inventory drafts and all queue/recovery records
survive. Schema version 9 added `stockCardHistory`; version 10 removes that table without changing
other records.
Obsolete bundle formats require a new download; never pretend they are complete.

localStorage is also used: deployment time-zone preferences/fallback state and the per-database
download schedule are persisted there, alongside existing authentication/preferences. The rule
is no business datasets, draft payloads or event queue in localStorage, not no offline-related
metadata. If locale settings fail, retain the saved zone; otherwise persist UTC and show one
fallback notice. Render snapshot times with the deployment zone through formatTimestamp.

Accepted receipts and accepted drafts are pruned after 30 days. Queue rows, refusals, retained
sync errors and archived copies are not automatically pruned. Browser eviction, private mode,
clearing site data and device loss can still remove work. Persistent storage is not requested.

### Device Data Sizes

Measured on 2026-10-15 with Chromium against a local backend (administrator, Comfort Health
Clinic, two programs). The stock sample is tiny, so these are floors, not capacity guarantees.

| Stored item | Serialized size |
| --- | ---: |
| Saved access (administrator, 13,347 permission strings) | 1,160,039 bytes |
| Home stock download, Essential Meds (6 cards, 4 lots, 13 reasons) | 8,066 bytes |
| Home stock download, Family Planning (4 cards, 1 lot, 13 reasons) | 6,742 bytes |
| Draft line | about 634 bytes per line |
| Queued ten-line event with its frozen draft | about 17,388 bytes |
| Refused event with its error | 10,844 bytes |
| Synced receipt | 10,780 bytes |

- Access data dominates: permission strings were 97.2% of the downloaded payload. Re-measure with
  a typical store-room user before sizing.
- Chromium compresses IndexedDB: 100 queued events added about 4,997 bytes each on disk.
- App files, configuration and five catalogs use about 4.2 MB of cache before sign-in.
- Rough sizing: access, plus each program download, plus about 17.4 KB per pending ten-line
  event (about 17.4 MB for 1,000 events), plus retained refusals and receipts.

### Draft Store

The shared revisioned store and serial writer stage edits immediately for leave protection and
announce Saved On This Device only after commit. Preserve every typed quantity text part and
display snapshot. Flush before submission, navigation and Log Out. Failed saves remain visible.

Enforce one editing draft per kind/facility/program. Durable transitions compare id and revision;
a stale tab stops saving until explicit Load or Copy. Subscriptions cannot replace active edits.
Copy/Restore archives current edits atomically. Refresh resumed product/lot snapshots by identity
without changing typed input; removed products/lots show an accessible warning before submission.
After inventory server actions, clear the observed conflicting draft without deleting later edits.

### Queue, Uploader, Delivery And Foreground Locks

Both connected and offline submission use the same queue. Flush, validate and collect signature,
then atomically freeze the exact POST body with a unique localEventId and draft revision.
Repeated confirmation reuses that event; queued drafts cannot autosave or be discarded.

The uploader serializes owner-scoped POSTs under a separate upload Web Lock. Before dispatch it
checks fresh identity/session/connection-scoped grants and commits sending/attempt metadata.
Reuse current-epoch access; read independent sources in parallel. Upload reads bypass the download
lock without publishing to Dexie.
Oldest eligible work goes first. Sending or uncertain work blocks later events only for its
facility/program; unrelated scopes continue. Draft/access mismatches pause rather than invent
service refusals. Recover orphaned sending rows only while holding the upload lock.

Queue transport disables mutation retries, never waits for renewal and never interceptor-replays
a 401. Proven not-sent failures return to the original queue without attempt metadata. A
recognized service/OAuth 401 pauses until same-user renewal and fresh grants authorize sending.
A verified 201 UUID atomically writes a receipt/accepted state and removes the queue row.
Receipt-write failures retry local persistence while retaining the lock, never another POST.

Definitive service JSON 400/403/404 retains the signed original and full refusal reason.
Timeout, abort after dispatch, gateway HTML, unrecognized responses, crashes before receipt
commit and post-dispatch scope failures are uncertain. Never auto-resend an unknown result.
Refused handling follows legacy Retry: an explicit action restores the same frozen body,
localEventId, revision and sequence to the existing queue without confirmation. Keep the previous
attempt and record the Retry choice in draft history. Resolve and hide the old refusal atomically;
a new refusal replaces it with the new reason and retains the previous error in history. Verified
acceptance creates the normal Synced receipt. The uploader still owns Web Locks, fresh session
and grants, and the per-facility/program uncertainty barrier. Never automatically retry refusals.

Recovery checks exact owner/revision/status/attempt transactionally. It Was Recorded saves a
user receipt without POST; Send Again requires the duplicate warning and retains body/history.

Foreground delivery holds an event Web Lock and in-memory id while waiting, releasing both on
all enqueue failures and completion. Poll remote ownership only for queued/sending work. If
sending has not started after 1.5 seconds excluding active access preparation, return Event Queued
and let background sync continue.
A started send retains the 65-second foreground uncertainty deadline. This is a feedback limit,
not permission to retry a request whose result is unknown.

### Stock Views And Submission Landings

Stock On Hand and Stock Card are online-only, with the standard disconnected navigation icon,
Connect To Open This Page dialog and direct-route/preload gates. They do not read or save device
stock/history. Their offline readers, timestamps, snapshot and pending-event notes are deferred.
The home-stock download remains available to the Adjustments picker/editor.

A queued Adjustment returns to the Adjustments program list, including connected submissions
that cannot start promptly. Verified online acceptance still opens scoped Stock On Hand.

### Connectivity, Worker And Recovery

Shared connectivity state represents server reachability, not only browser online hints.
No-response failures establish disconnection; cancellations, local absence and timeouts do not.
Public probes back off without overlapping. Probe success does not reset retry backoff until a
real API request succeeds. Browser online hints cancel a waiting backoff timer and probe
immediately, without overlapping an active probe. Query networkMode is always; error views retry
through the shared reconnect hook. Fallback reads permit unreachable/timeouts/non-JSON gateways, never definitive
service errors or cancellations. Device access markers expire locally and become stale on reconnect.

Production registers one worker at BASE_URL scope. Precache app assets; runtime-cache only
configuration and all supported language catalogs, network-first. Keep openlmis-ui-prefixed
caches separate from legacy. Check updates hourly and notify all tabs; applying an update
activates/reloads only the requesting tab through the leave guard. Development has no worker.
Removed lazy chunks reload once while connected through that guard. Offline route/chunk errors
show Not Available Offline and retry on reconnect instead of repeatedly reloading.

## UI/UX Decisions

- Offline Events at `/offline-events` sits below Home and is also in the avatar menu/palette.
  The old stock-management URL redirects with search preserved. Its localized badge counts
  queued, sending, uncertain and unresolved refused work, including held work; hide zero.
  Refused or uncertain events give the badge a destructive tone and a needs-review accessible label.
- The list shows Event Type, facility, program, occurred dates, status and View Details.
  Default order is descending occurred date, queued time and sequence; explicit URL sort wins.
  Filters contains status, enabled offline event types with All, and From/To dates. Dates filter
  occurred dates inclusively, matching an event when any line falls within both bounds. URL
  search validates dates/types; live changes reset paging and Clear Filters clears every filter.
  Phones use cards over the same filtered events; identifying/actions remain visible.
- Details uses a 48rem dialog with fixed compact metadata/footer and scrolling lines. At measured
  672px it uses a bordered table, otherwise product cards. Optional comments/VVM appear only when
  populated. Status sits beside Event Type, with an accessible type/status description. Badge
  tones use success/info/warning/destructive; sending spinners respect reduced motion.
- Transaction History and outline recovery actions precede the final primary Close button;
  initially focus Close. Remove Event uses the shared destructive confirmation. Lot codes stay
  nowrap in tables; cards use break-all without changing copied hyphens. Empty table values stay blank.
- Retry is the first action for unresolved refusals in row menus and phone card actions, and
  precedes Copy For Correction in the details footer. It needs the event-kind scoped grant;
  the uploader rechecks authorization before sending. No Retry is offered for uncertain or
  accepted events. Copy For Correction stays secondary and disables Retry for that original.
- Remove is available for never-attempted queued events, accepted events and refusals. Accepted
  removal hides payload/draft but keeps minimal duplicate protection; refusal removal dismisses
  review without deleting correction copies. Sending/uncertain work retains recovery only.
- Recovery remains available for owned work without an offline-kind right. Send Again needs the
  exact grant. History needs viewing rights and connection; no history preloads. Never show raw
  transport JSON or internal revisions. Correction creates an editable copy and retains the original.
- Program pickers omit download-readiness columns. Unavailable offline actions remain focusable
  with Not Available Offline below. Pending-work copy is one translated ICU message with an
  Offline Events link. Device draft status/archive actions reserve a line-toolbar slot before
  quantity units/View, including pending views. Saved On This Device is a secondary badge in a note.
- Pending-work Alerts use fixed light/dark lavender/purple offline tokens, independent of brand
  presets, with a translated strong lead-in. Sidebar disconnection stays warning-colored.
- SignatureDialog places Submitted By below Signature as its field description, using one ICU
  message with the raw username in strong text. Keep the title; omit a separate header description.
- Sidebar notices show persistent You're Offline and actionable download/sync/access failures.
  You're Back Online, Offline Data Ready and Offline Events Synced use four-second success
  notices. A decorative tone-colored 2px edge bar shares the dismiss timer; hover/focus pauses
  remaining time, collapse releases pauses, reduced motion hides animation without changing timing.
- Announce through one persistent shell StatusAnnouncer. Visual notes are not live regions.
  Announce saves and action-needed work once through the persistent announcer; standing queued
  counts stay silent. Refused/uncertain work has one visible destructive Review notice, including
  without kind rights, before other notices, and marks the closed phone menu dot. Each background pass with new
  refusals shows one destructive count toast with a Review link filtered to refused events.
  Sync completion requires a verified run with no pending rows/errors. No-op passes preserve its countdown.
- While disconnected, suppress connection-related download failures, Sign In To Sync and Sync
  Paused notices/announcements. Retain capability, held-work, receipt-write and update information.
  The phone header indicator exposes warnings/update readiness when the sidebar is closed.
- Update is a ghost icon button beside sidebar theme/language pickers, with an info dot and
  shared tooltip/accessibility label. Footer controls stack on the collapsed rail. Run leave
  protection before update/reload; readiness is announced once.
- Online-only navigation remains focusable/clickable with disconnected icons and descriptions.
  Activation opens Connect To Open This Page, a shared Close-only dialog, preserving the
  originating menu/palette and focus. Sidebar, account menu and palette share one provider. Dim
  unavailable items without hover highlights; retain neutral keyboard focus and collapsed title/count/reason tooltips. Direct routes/preloads are gated.
- Already-open online-only pages retain drafts/guards while hidden offline. Reuse only a valid
  protected match for the same session. The page-visibility gate covers overlay primitives:
  persistent dialog drafts stay mounted but hidden; transient overlays close. Discard decisions
  opt out so navigation/Log Out remains answerable. Reconnect restores the page without lost edits.
- Use Log Out app-wide. Flush drafts and count owner-scoped unsynced work once before one combined
  retention/offline warning; bounded failures use neutral unknown-count copy. Stay Logged In
  cancels. Confirmation is identity-scoped. Password-change logout uses the same path.

Lazy device services publish memoized work/status from a sibling Suspense boundary, keeping
routed content mounted through sign-in. Only the Offline Events nav item subscribes to its count.
Offline Events opens for every signed-in user offline, including before access is downloaded.

## Deliberate Drops And Legacy Differences

Legacy downloads all user programs; this implementation deliberately downloads only supported
home-facility programs with both STOCK_ADJUST and STOCK_CARDS_VIEW. Other facilities and Receive's
full approved catalog require separate dataset work. Offline Stock On Hand, Stock Card and saved
histories are planned for FM-166/the next PR; both stock views currently require a connection.

Legacy Retry was checked in `openlmis-offline-ui` at commit
`664605898b7937874c47bffa186819b34ac7a112`:
[synchronization-errors.html](https://github.com/OpenLMIS/openlmis-offline-ui/blob/664605898b7937874c47bffa186819b34ac7a112/src/events-synchronization-errors/synchronization-errors.html),
[controller](https://github.com/OpenLMIS/openlmis-offline-ui/blob/664605898b7937874c47bffa186819b34ac7a112/src/events-synchronization-errors/synchronization-errors.controller.js),
[events service](https://github.com/OpenLMIS/openlmis-offline-ui/blob/664605898b7937874c47bffa186819b34ac7a112/src/offline-events/events.service.js).
Every listed synchronization error offers primary Retry and destructive Dismiss, without a
confirmation. Retry calls `StockEventResource.create(event)` without changing the event, removes
the old cached error, caches the new error on failure and reloads the list on either outcome.
The wording is Retry, Dismiss and We couldn't perform this event. The stockmanagement UI's
`stock-event-cache.service.js` retains event/error data per user. Our Remove wording and
confirmation remain; durable queue/receipt protection replaces legacy's pre-send error removal.

Do not reproduce legacy's removal of queued work before acceptance or clearing on logout/token
refusal. Keep immutable originals, accepted receipts and explicit uncertainty recovery. Do not
infer acceptance from balances, add unsupported idempotency headers, or replace document numbers.
No per-page Query-cache persistence, API service-worker cache or second queue is introduced.

## Testing Strategy And Rollout Limits

Use focused Vitest tests with fake-indexeddb for transaction/revision conflicts, complete-download
publication, scope/freshness/backoff, session changes, locks, delivery classification, receipt
persistence and recovery. Interaction tests protect notices, leave/logout decisions and navigation.
The no-Web-Locks fallback is covered at the unit boundary, not certified by the browser suite.

The offline Playwright suite in `tests/offline/` exercises a production `/v2` build with a guarded
preview and fixture APIs. Always stub/block stock POSTs, abort failed handlers and keep preview
API denial as an independent barrier. Use relative page URLs and the shared persistent-context
fixture; create/remove profiles under the temporary directory. No live stock mutation is needed.

Run `pnpm test:offline` for Chromium and `pnpm test:offline:browsers` for installed engines/channels.
`.github/workflows/offline.yml` runs Chromium nightly at 02:00 UTC and on PRs labeled `offline`.
Cover restart/offline edits, reconnect ordering, two tabs, two users, expiry, interrupted upload,
refusal/correction, navigation/focus and unavailable downloads. Check English/Arabic on phone and
desktop. Browser availability is separate from pass/fail; Linux WebKit does not certify Safari.

WebKit 27.2 with Playwright 1.64.1 has worker-controlled API interception gaps affecting fixture
sign-in, access and submission. Reproduce on a loopback server: intercept `/api`, compare fetch
before/after a controlling service worker, then compare worker navigation with the context set
offline. Keep the server isolated from real APIs. Firefox temporarily removes routes while
natively offline to preserve worker caching, so synthetic reconnect events are a coverage limit.

Before rollout, test actual supported devices/profiles over HTTPS and measure representative
access data, large home-stock bundles, drafts, queue and retained errors/receipts separately.
Include origin-wide cache/storage overhead. Tiny fixtures are not capacity guarantees; browser
quotas, eviction, private mode and loss remain support constraints. No universal retention promise.

### Home notifications

Home keeps system notifications in a Notifications header action beside Refresh, hidden
when no active notices are available. Its count uses the page language. A scrollable popover
fits the available screen width and height. Legacy Home shows the author and creation time,
without start/expiry dates; creation times use the deployment time zone. Read every page of
`GET /systemNotifications?isDisplayed=true&expand=author`, newest first. Refresh resets the
Home query group, including notifications. Loading and errors stay within the action's boundary; uncached
notifications stay hidden offline. Messages allow only sanitized basic formatting and
HTTP, HTTPS or mailto links through DOMPurify; new-window links receive safe rel attributes.
