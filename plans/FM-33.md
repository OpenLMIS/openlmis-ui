# FM-33: Reset Password (From Email Link)

https://openlmis.atlassian.net/browse/FM-33 · Parent: FM-30 General: auth, home, profile

## Scope

The page the reset email opens, in the same PR as [FM-32](FM-32.md), which holds the shared
card, the requests sent with no token and the session dialog's exemptions.

The link itself is built by the auth service and points at the legacy page
(`<PUBLIC_URL>/#!/resetPassword/<token>`). Everything after `#!` stays in the browser, so no
proxy rule can send it to `/v2`.
[openlmis-auth#31](https://github.com/OpenLMIS/openlmis-auth/pull/31) adds
`PASSWORD_RESET_URL`, defaulting to today's link. A deployment that wants the new page sets
it to `<BASE_URL>/v2/reset-password/`. Until then the email keeps opening the legacy page,
which keeps working.

## Summary

The reset email links to a page where the user chooses a new password. Legacy shows a small
form with the rule written above it and a "Show password" checkbox. The new page shows the
same two fields with a checklist that ticks off each rule as the user types, one eye button
that shows both fields, and a clear message when the link has expired or was already used,
with a way to ask for a new one. After a successful change it goes to Sign In.

## Legacy Today

`/#!/resetPassword/:token` (state `auth.resetPassword`). Screenshots, kept locally, in
`.screenshots/FM-33/`.

- "Reset password", "A password must contain at least 8 characters and 1 number.", New
  password, Re-enter new password, a "Show password" checkbox for both, Change password. No
  Cancel and no way back to Sign In.
- One error at a time, in a box above the fields: "Passwords do not match", "Password is too
  short. It must have at least 8 characters.", "Password must contain at least 1 number".
- The token is not checked on open, only on submit.
- Any failure, an invalid or expired token included, shows "Failed to change password." plus
  a global "There was an error with this request" alert. A malformed token shows the raw
  JSON parse error.
- Success: "Password has been reset successfully", then Sign In.
- A signed-in user is sent home, and the link is lost.

## Agent Brief

### API Map

| Step | Method and path | Params | Fields used | Right | Legacy ref |
| --- | --- | --- | --- | --- | --- |
| Change the password | `POST /api/users/auth/changePassword` | body `{ token, newPassword }`, no `Authorization` | none, `200` empty | none (`permitAll`) | `openlmis-auth-ui change-password.factory.js:51-65` |

Errors: `400` `auth.error.token.invalid` (unknown, used, or replaced by a newer request),
`400` `auth.error.token.expired` (12 hours), `400` without a `messageKey` for a token that is
not a UUID.

The endpoint checks nothing about the new password (`UserController.changePassword`), so
the client is the only check.

### Data Flow

No loader: there is no endpoint that checks a token without using it. The token comes from
the path param. One mutation, sent `anonymous` (see [FM-32](FM-32.md)).

### Risks and Edge Cases

- The same user may hold an old link: only the newest works, which the invalid message says.
- A signed-in user following a link: the page opens (Decisions); the call goes without
  their token.

## UI/UX

- **Port:** two fields, the rule shown up front, Show Password for both, success then Sign
  In.
- **Improve:**
  - a checklist that ticks each rule as the user types, as in Profile and Users;
  - the eye on either field shows both, the way legacy's one checkbox did, with the eye
    buttons the app's password fields use;
  - the heading of a link-problem card takes focus when it replaces the form;
  - every message sits under its own field and they all show at once;
  - an invalid or expired link gets its own message with Request A New Link and Back To Sign
    In, instead of "Failed to change password."; a malformed link says so before anything is
    typed;
  - a Back To Sign In link, which legacy lacks.
- **Drop:** the global "There was an error with this request" alert and the raw parse error.

## Decisions

- **The app's password rules, not legacy's looser ones.** Legacy checks only 8 characters
  and a number on this page, and the server checks nothing here. Every other password change
  in the app follows the auth service's rules, and the service stores passwords with bcrypt,
  which ignores anything past 72 bytes. The names rule is left out because the page does not
  know whose password it is.
- **Open for a signed-in user.** Legacy sends them home and the link is lost. The token is
  what authorizes the change, so the page opens for anyone.
- **The link stays on legacy by default.** `PASSWORD_RESET_URL` keeps today's link unless a
  deployment sets it, so merging changes nothing until an environment opts in.
