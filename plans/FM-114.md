# FM-114: Report Parameters Form

https://openlmis.atlassian.net/browse/FM-114 · Parent: FM-111 Reports

## Scope

Native report parameters and output for template reports: the
`/reports/$module/$reportId/generate` route, a form built from the report's metadata,
complete option lookups, Timeliness's dependent Period, the Format choice and authenticated
delivery in all five legacy formats. The View Reports catalog switches template links from
the legacy handoff to this route. Dashboard links keep the FM-113 legacy handoff until FM-115.

Not included: dashboards (FM-115), template administration, report calculations or Jasper
templates, backend fixes, Home embedding, offline reporting and new country reports. Backend
defects found in research are listed under Risks for separate, later approved scope. No Jira
ticket or backend PR is created by this plan.

Approved branch: `feat/fm-114-report-parameters` stacked on PR #145
(`feat/fm-113-reports-list`, head `e971486e`), retargeted to master after #145 merges. FM-115
stacks separately on the same base. Both PRs touch `report-catalog.tsx`, the key factory and
the catalogs; whichever merges second rebases.

Shared changes are opt-in and limited to what this feature needs (see Shared Helper Changes).
The global 60 s Axios timeout and every existing print caller keep their behaviour.

## Summary

Today, choosing a report in legacy opens a generic "Choose Report Options" page. It shows
the report's fields, a format choice (PDF selected) and Generate. The file opens in a new
tab or downloads. Legacy puts the user's access token in the report address, sends unset
choices as the word "undefined", lets a single failing list break the whole form, and keeps
a stale Period after Program is cleared.

The new screen shows the report's own name as its title, then the same fields, in the same
order, with the same labels and the same choices. Long lists (2,734 facilities, 10,232
products) become searchable and stay fast. A list that fails to load shows its own Try Again
without losing anything already entered. Period clears when Program changes. Generate cannot
be pressed twice; a long report shows progress with a Cancel button and is never cut off by
a timer. PDFs open in a new tab. CSV, XLS, XLSX and HTML download as files; HTML is no longer
opened inside the app because a report page could then run code as the signed-in user.

Report calculations, report files and which data each user may see stay exactly as they are
on the server. The screen works on phones and in Arabic; report and field names stay as the
server provides them, as in legacy.

### Routes, Data Flow And Cache

- New route file `src/routes/(protected)/_protected.reports_.$module.$reportId.generate.tsx`
  (URL `/reports/$module/$reportId/generate`, not nested in the catalog page).
  `staticData.crumbKey: 'reports.generate.crumb'` gives Home / Reports / View Reports /
  Generate Report, parity with legacy. Never edit `route-tree.gen.ts`.
- Loader: capture `getSessionScope()`, await `requireRight(queryClient, RIGHTS.reportsView)`,
  assert scope, read `getSessionUserId()`. If `module` is not in `getReportingModules()`,
  throw `notFound()`. Then `await ensureQueryData(reportTemplateOptions(userId, module, id))`
  (blocking: 404 page and title need it). After it resolves, fire-and-forget `prefetchQuery`
  for each independent lookup, so lists load in parallel as in legacy. Return
  `{ userId, module }`.
- `pendingComponent`: real icon and description, inline title skeleton, field skeletons.
  `notFoundComponent` and a 404 from detail: "Report Not Found" with a link back to View Reports.
  Other failures: `ErrorFallback` with retry, `isForbidden` first.
- Query keys (add `reportParameterOptions` root to `src/lib/key-factory.ts`):
  - Detail: `[...queryKeys.reportTemplates.all, 'detail', { userId, module, id }]`.
  - Lookup: `queryKeys.reportParameterOptions.list({ userId, method, path, body, params })`
    where `path` is normalized without `/api`, `body` is the exact JSON sent and `params`
    holds the dependency values. Identical lookups across reports share one entry.
- Cache: detail uses the app default. Lookups use `staleTime: 10 minutes` so returning to a
  report in a session does not repeat a 12 s product read; nothing is persisted, and all
  queries clear on identity change (existing `tanstack-query.ts`). Lookup query functions
  consume `signal`, so a dependency change or unmount cancels in-flight reads.
- Form values live in component state only, never in the URL or storage. No discard guard:
  parameters are not a draft, matching legacy. Output is never cached in Query, Dexie or the
  service worker.
- Catalog: `ReportLink` for template reports renders a router `Link` to the new route.
  Remove the template branch of `reportLegacyHash`; keep the dashboard branch for FM-115.
- Offline: not an offline route. The shared shell shows Not Available Offline; Generate also
  disables offline through `usePrintReport`.

### Template Data Minimization

`JasperTemplateDto` includes `data`, the compiled template (including its SQL), in both the
list and detail responses. `fetchTemplateReports` and the new `fetchTemplateReport` drop
`data` before returning, so it never enters the Query cache, devtools or error reports. This
is client minimization only: the browser still downloads it and every REPORTS_VIEW user can
read it from the network. That backend disclosure is a separate backend gap; this plan does
not fix it or open a ticket.

### Metadata Classification (pure, `lib/report-parameters.ts`)

Exact legacy order (`report-generate.html`), first match wins:

1. `description === 'datepickers'`: date.
2. `description === 'booleanSelect'` and no static `options`: boolean choice, values
   `'true'`/`'false'`, labels translated True / False (legacy wording).
3. Has `dependencies`, a `selectExpression`, or non-empty static `options`: choice.
   Source precedence inside choice: dependencies (fetched per parent value), then
   `selectExpression`, then static options (value = label = option text).
4. `dataType === 'java.lang.Integer'`: whole number.
5. Otherwise: text.

- Never show `description` as help text: in this metadata it is a control marker. Help text
  is keyed by exact parameter name, as legacy: `GeographicZone` gets
  "If no option is selected, report will include all geographic zones." and `DueDays` gets
  "Insert number of days past the period end date the requisitions are due by. Default is 10
  days." Stock On Hand's lowercase `geographicZone` gets none.
- `defaultValue` and `displayOrder` are null in every observed template and legacy ignores
  both. Keep ignoring them; a non-null default is unsupported until a real fixture exists.
- Unsupported remote metadata (an object-list lookup without `selectProperty`, a select
  path that fails D2 checks, unparsable `selectBody`, method other than GET/POST) renders the field with an in-place
  "These choices cannot be loaded" error. It never falls back to free text. If the field is
  required, Generate stays blocked by validation.
- Static string choices use each option as both value and label; they do not require
  `selectProperty`, a URL, a method or a body. Remote lookup validation never rejects them.
- Multiselect is not supported: no template or legacy markup uses it.

### Lookups (pure adapter plus `api.ts`)

- D2 origin and method check: accept only `selectMethod` null, `GET` or `POST`, and a
  `selectExpression` that is a root-relative path starting `/api/`, with no scheme, no `//`
  prefix, no `..` segment, no query string and no fragment. Strip `/api` and pass the rest to
  the shared client, which carries the bearer only to its own base URL. Nothing in metadata
  is evaluated as code. Validate again after stripping `/api`: the effective path must have
  exactly one leading slash, no backslash, and no decoded or normalized traversal. Resolve
  the final request against the configured API base and require its intended origin and
  base path. Reject `/api//host/path` and encoded/normalization variants before any request;
  never allow stripping a prefix to create an absolute or protocol-relative URL.
- Dependency params go through Axios `params` (`{ programId: '<id>' }`), so values are
  encoded and an existing `?` cannot break the URL. `property` is ignored, as legacy.
- Projection: accept an array or a page. A page must be complete
  (`totalElements === content.length`, `totalPages <= 1`) or the field shows a retryable
  "incomplete list" error. An empty page is an empty list (legacy throws here). Value is
  `String(item[selectProperty])`, label `item[displayProperty]` or the value. Drop items whose
  value is `null`, `undefined` or `''` (legacy drops falsy); keep `0` and `false`. Keep
  returned order. Deduplicate by value, keeping the first, since the submitted value is
  identical (facility or product names can repeat).
- Lists over 50 items use `ComboboxField virtualized`; all choices are searchable and
  optional ones are clearable.

### Dependencies

- A child is disabled, with a translated "Choose Program first" style hint naming the parent
  label, until every parent has a value.
- On parent change or clear the child value is cleared (`form.setFieldValue`) in the parent's
  change listener, before the new list loads. The child's query key includes the parent
  value, so a late response for an old parent can never fill the new list; its consumed
  signal is aborted.
- Timeliness Period depends on Program. Reporting Rate Period has no dependency and lists all
  434 periods, as legacy.

### Validation And Serialization (pure)

- Schema from metadata with `revalidateLogic({ mode: 'submit', modeAfterSubmission: 'change' })`.
  Required choice, date, text and boolean must be non-empty. Format is always required.
- Whole number (`DueDays`): `wholeNumberText` with `min: 0` and the default Java int max
  2147483647 (`MAX_WHOLE_NUMBER`), `optional` unless metadata marks it required. Arabic and
  Persian digits are converted with `toLatinDigits` before sending. Legacy accepted `-5`,
  `abc` and `1.5` client-side; the server rejects negatives and overflow with 400, so this
  is a recorded correction.
- Dates: `DateField` draft `yyyy-MM-dd` is the wire format, sent unchanged (no time zone
  shift). No start/end order or range rule: neither legacy nor the server has one.
- Output params: `{ [exactMetadataName]: value }` for set values only. Unset means
  `undefined`, `null` or `''`; `'false'` and `'0'` are sent. Exact name case matters: the
  requisition service throws 500 on a case mismatch. Append `lang` = app language. If a
  template parameter is itself named `lang`, the template value wins and the app language is
  not sent (edge case, none observed).
- Format path segment is lowercase (`pdf`, `csv`, `xls`, `xlsx`, `html`).

### Output And Delivery

Decision D1 supports all five formats. The request is
`fetchReportFile(path, params, { timeout: 0, signal })`: no client timeout, matching legacy's
tab navigation (Facility Assignment took about 30 s for every format, Timeliness more than
120 s with no answer), with explicit cancellation instead.

Classify the response from its first bytes before delivering (pure, `lib/report-output.ts`):

| Bytes | Delivered As | Filename Extension |
| --- | --- | --- |
| `%PDF-` | PDF; opens in the waiting tab only when PDF was requested, otherwise downloads | `.pdf` |
| OLE2 `D0 CF 11 E0` | `application/vnd.ms-excel` download | `.xls` (common sends the XLSX media type; ignore it) |
| ZIP `50 4B 03 04` with XLSX requested | XLSX download | `.xlsx` |
| Text with CSV requested | `text/csv` download | `.csv` |
| Text with HTML requested | `application/octet-stream` download, never rendered | `.html` |
| Anything else, or a mismatch not listed | Error "The server returned an unexpected file", tab closed, nothing delivered | |

- PDF bytes for a non-PDF request (test requisition service before OLMIS-8379 turns `xlsx`
  into PDF bytes named `.xlsx`): download as `.pdf` and show a warning toast "Report Saved As
  PDF: The server returned a PDF instead of XLSX." Never name it `.xlsx` or claim XLSX.
- Filename: the server's `filename` stem when present (`Facility_Assignment_Configuration_Errors`),
  otherwise the report name with unsafe characters replaced, plus the extension above.
- Only a PDF request opens a tab, synchronously in the click handler (`openReport`), so popup
  blockers allow it; a blocked or closed tab falls back to download (existing behaviour).
  `openReport.deliver` receives only a Blob re-created as `application/pdf` after the `%PDF-`
  check. HTML and every other format never reach a `blob:` tab: a `blob:` page inherits the
  app origin, and report HTML is admin-authored content that could run script there.
- Errors: `usePrintReport` toasts the server message for non-5xx (400 validation, 403
  PermissionMessageException, 404) and the translated generic description otherwise. The
  form keeps every entered value. A user Cancel or unmount shows no error toast.

### Generation Lifecycle

- Compose `usePrintReport({ serverAuthorized: true, userId, request, onReport, ... })`.
  REPORTS_VIEW is unscoped and the server checks `requiredRights`, so no facility/program
  grant is invented. The hook already prevents a second print while pending, closes the tab
  and suppresses delivery after an identity change, and handles offline.
- The form's `onSubmit` creates an opening with validated values, format, a fresh
  `AbortController` and a current-opening guard, then calls `print()`. `onReport` returns
  the PDF waiting tab or download-only delivery, retained by that opening. `request` races
  the whole request/inspection operation against abort, rejecting with Axios cancellation
  promptly even while the shared client awaits non-abortable session renewal. The race
  handles both outcomes of the underlying promise so a late rejection is never unhandled.
- Cancel is an operation-level terminal state: invalidate the opening, close its waiting
  tab immediately, abort the transport and settle pending through the cancellation race.
  The underlying aborted GET must not send another HTTP request after renewal. Check the opening/signal after
  every asynchronous byte read and immediately before delivery; stale or cancelled delivery
  throws cancellation, never downloads or shows a success toast. A new opening cannot be
  changed by an older operation's result.
- While pending: Generate disabled with spinner and "Generating Report", a Cancel button
  beside it, and a visible status note ("This can take several minutes for large reports").
  Use the existing persistent shell StatusAnnouncer for announcements, never another
  live region.
  Cancel terminates as above. Unmount, account change and `usePageHidden()` (the app
  hiding an online-only route offline) terminate that opening and release its delivery too.
  Ordinary browser-tab backgrounding is separate from app page visibility.
- A 401 waits for renewal and replays the GET once through the shared client (a safe read).
  `SessionEndedError` never delivers to the next user.

- Header: `FileChartColumnIcon`, `WorkspaceTitle` = report name (improvement over the generic
  heading; breadcrumb keeps "Generate Report"), `WorkspaceDescription` = translated
  "Choose the report options, then generate it in the format you need."
- One `form` with `FieldGroup`: parameter fields in metadata order, then a `Separator`, then
  Format as the existing `RadioGroupField variant="tile"` with five named choices; formats
  are not translated, as legacy. Its current option API does not render per-item descriptions,
  so put the PDF-versus-download explanation in a shared field description instead of
  inventing an option prop or changing the form library.
- Footer row at the form's bottom end: Cancel (only while pending, outline, `lg`) and
  Generate (default, `lg`, `type="submit"`). Below `@xl/main` both stretch full width.
- Field controls: date `DateField` (clear on optional), boolean `SelectField` with a
  Not Selected item for optional fields, choices `ComboboxField` (virtualized above 50,
  clearable), whole number `NumberField`, text `TextField`. Labels are `displayName`.
- Per-field states: loading shows the disabled control with a spinner placeholder "Loading
  Choices"; error shows an inline destructive `Alert` under the field with Try Again (other
  fields stay usable); empty list shows "No Choices Available"; dependent child disabled with
  its hint.
- Report without parameters (Facility Assignment): Format and Generate only, plus one line
  "This report has no options."
- Invalid submit: retain inline field errors and open the shared `InvalidSubmitDialog`.
  Closing it explicitly focuses the first invalid control in rendered metadata order,
  following AGENTS.md and legacy. `useAppForm` does not provide this focus automatically.
  Output failures retain the existing report-action toast behavior.

## Decisions

- D1 Formats (AC asks to decide): support all five, PDF default. PDF opens in a tab; CSV, XLS,
  XLSX and HTML download. HTML downloading instead of opening is a deliberate security
  departure from legacy. Approved by the user on 16 November 2026.
- D2 Lookup origin: same-origin `/api/` GET or POST only; anything else is a field error.
- D3 Timeliness zone body (open product call, user wants parity):
  - Option A, parity (recommended default): reproduce legacy's rule exactly: POST
    `{"levelNumber":"2"}` whenever `selectBody` is set, `{}` otherwise. Timeliness District
    and Reporting Rate offer the same 14 level-2 zones legacy offers. Isolated in one named
    function so it can change later.
  - Option B, honour metadata: send the stored `{"levelNumber": "3"}`. This changes the
    District list (not the same options as legacy) and returns 400 on servers without a
    level 3. Only with product-owner approval and a server check.
  Option A is recommended because the user asked for parity and the AC requires the same
  options; correcting the stored metadata is administration, outside this story.
- D4 No client timeout on output, with Cancel; other requests keep 60 s.
- D5 Truthful file types from bytes, not from the server's media type or requested format.
- D6 Strip compiled template data client-side; backend disclosure remains open.
- D7 Ignore `defaultValue`/`displayOrder` as legacy does.

### Implementation Adjustments

Small departures forced by the actual APIs, recorded during implementation:

- `usePrintReport` takes a third opt-in, `describeError(error)`, consulted before the server
  message. The hook fixes its error description when Generate starts, so without it the
  "unexpected file" and "incomplete list" wording could not reach the existing error toast.
  Existing callers do not pass it and are unchanged.
- The hook's success toast is fixed at start too, so a PDF returned for another format shows
  the neutral "Report Generated" success toast followed by the "Report Saved As PDF" warning.
  Neither claims the requested format.
- `reportLegacyHash` became `dashboardLegacyHash(id)`, since only dashboards still hand off.
- Catalog template links set `role="link"` explicitly, as the dashboard links already did,
  because Base UI gives non-native buttons the button role.
- The long-running note under Generate is plain text, not a live region; announcements stay
  with the shell StatusAnnouncer, the button label and the toasts.
