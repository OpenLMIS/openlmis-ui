# FM-162: Admin Reports

https://openlmis.atlassian.net/browse/FM-162 · Parent: FM-154 Admin: system & integrations

## Scope

Adds Administration > Reports: a list of dashboard reports with Add, Edit and Delete. Also adds the
Home page report panel, because the new Home shows no dashboard report today and the acceptance
criteria need one (user decision). It also moves the shared report category lookup into
`reference-data`, as FM-163 planned.

Out of scope: Jasper report templates (a separate admin screen), and any backend change.

## Summary

Dashboard reports are links to Superset or Power BI dashboards. Users see them on the Reports page,
and one of them can also show on the Home page. An administrator with the Manage Reports right
manages them on this page.

Legacy lists every report with its category, type and two yes/no settings: Enabled and Show on
Home Page. Its Name and Category headers look sortable but do nothing. Add and Edit open a dialog
with Name, Category, Type, Embedded UUID, URL, Enabled and Show on Home Page. A Superset report
needs a URL or an Embedded UUID; a Power BI report needs a URL and has no UUID. Only one report can
be on the Home page: saving one clears the flag on the others, and legacy asks first. The Edit
breadcrumb shows a raw message key, and every save says "edited", even an Add.

The new page lists reports sorted by name, and also by category. Add and Edit use the same dialog
with clear errors on the field at fault, including a duplicate name. Turning on Show on Home Page
asks first, but only when another report already holds it, naming that report. Delete asks first. After a
save, the list, the Reports page and the Home page all refresh. The Home page shows its report in a
panel below the dashboard cards, as legacy does.

## Legacy Today

Screenshots: `.screenshots/FM-162/legacy-*.png`. Source: `openlmis-referencedata-ui@777e31d`,
folders `admin-report-list`, `admin-report-edit`, `report-dashboard`, `openlmis-home-page-report`.

- **List** `#!/administration/reports`, gated by `REPORTS_MANAGE` (menu and route).
  - Columns: Name, Category, Type (raw enum), Enabled and Show On Home Page (a checkmark or blank),
    Actions (Edit, Delete). Add Dashboard Report above the table.
  - Name and Category headers change `sort` in the URL, but the list is refetched with no params
    and keeps server order. No pager. At 390 px the table scrolls sideways.
  - Empty: "No Dashboard Reports found.". A failed read blocks the page with "Internal application
    error".
- **Add** `.../edit/` and **Edit** `.../edit/{id}` share one modal; the breadcrumb shows the raw key
  `adminReportEdit.title`.
  - Name (required); Category (searchable select, required); Type (select, unset, `SUPERSET` or
    `POWERBI`, required); Embedded UUID (Superset only, must match 8-4-4-4-12 hex); URL (Power BI
    requires it; Superset needs URL or UUID, "Provide either a URL or an Embedded UUID."); Enabled and
    Show On Home Page checkboxes, both off on Add.
  - Any URL text is accepted, including `not-a-url`.
  - Setting Show On Home Page asks "Are you sure you want ${newReport} report to replace the
    ${actualReport} report on the home page?" (Save, Cancel). On Add it asks every time, even when
    no report holds the flag ("replace the undefined report"). On Edit it asks when the flag
    changes from off and another report, enabled or not, holds it.
  - Superset shows the hint "Provide either a URL or an Embedded UUID - at least one is required.".
  - Both Add and Edit toast "Dashboard report edited successfully.". A duplicate name keeps the
    modal open with an error dialog and a "Failed to edit dashboard report." toast.
  - Clicking Save on Add before touching any field throws a `TypeError`.
- **Delete** asks "Are you sure you want to remove {name} report?", then toasts "Dashboard report
  deleted successfully.".
- **Home** reads `availableReports?showOnHomePage=true` (no request at all when offline), takes
  `content[0]` and renders it below notifications and alerts. No record means no panel.
- **Timings**: Add 0.2 to 0.3 s, Edit 0.4 to 0.6 s, Delete about 0.8 s with the reload. Home's
  report lookup 0.6 to 2.6 s.

## Agent Brief

### API map

`D` = `/api/reports/dashboardReports` (openlmis-report@6b33ad6 `DashboardReportController`).

| Step | Method and path | Params / body | Fields used | Right | Legacy ref |
|---|---|---|---|---|---|
| List | `GET D` | none (all rows) | `content[]`: `id`, `name`, `category.{id,name}`, `type`, `url`, `embeddedUuid`, `enabled`, `showOnHomePage`, `rightName` | `REPORTS_MANAGE` | `report-dashboard.service.js` `getAll` |
| Categories | `GET /api/reports/reportCategories` | `size=0` (same as no params) | `content[].{id,name}` | Signed in | `report-category.service.js` `getAll` |
| Edit read | `GET D/{id}` | none | full DTO, including `rightName` | `REPORTS_MANAGE` | `get` |
| Add | `POST D` | `{ name, category: {id}, type, url, embeddedUuid, enabled, showOnHomePage }` | saved DTO | `REPORTS_MANAGE` | `create` |
| Edit save | `PUT D/{id}` | the fresh DTO with the form's fields applied (`id` and `rightName` are harmless; the server ignores `rightName`) | saved DTO | `REPORTS_MANAGE` | `update` |
| Delete | `DELETE D/{id}` | none | `204` | `REPORTS_MANAGE` | `delete` |
| Home | `GET D/availableReports` | `showOnHomePage=true`, `size=0`; never a small size, since the server works out the user's rights from the same page | `content[0]` | Signed in; enabled reports only, each needing its per-report right; no `REPORTS_VIEW` | `home-page-report.controller.js` |

Server paging is broken: with `page` and `size` it pages twice and reports the page length as the
total, so later pages come back empty. `GET D` without params returns every row; the list never
sends paging. `sort=unknown` answers 500.

The `type` enum is `SUPERSET | POWERBI`. Labels shown: "Superset" and "Power BI".

Errors (`{ messageKey, message }`):

| Condition | Status | `messageKey` | UI |
|---|---|---|---|
| Neither URL nor UUID | 400 | `report.error.dashboardReport.urlOrEmbeddedUuid.required` | URL field error (the form prevents it first) |
| Duplicate name on POST | 400 | `report.error.dashboardReport.name.duplicated` | Name field error "A report with this name already exists." |
| Duplicate name on PUT | 500, no key (database constraint) | none | Prevented by the form's own duplicate check against the loaded list; otherwise generic error |
| Right cannot be built or saved (POST) | 400 | `report.error.dashboardReport.save.right.failed` | Translated `api-error.report.error.dashboardReport.save.right.failed`: the report's access right could not be created; try again or contact support |
| Right cannot be deleted (DELETE) | 400 | `report.error.dashboardReport.delete.right.failed` | Error toast with translated `api-error.report.error.dashboardReport.delete.right.failed`: the report's access right could not be removed; remove it from roles first, then try again |
| Name with no Latin letter or digit, or whose right key collides with another report's | 500 (empty or duplicate right key) | none | Prevented by the form (see Rules) |
| Category missing or deleted meanwhile | 404 | `report.error.reportCategory.notFound` | Category field error "This category no longer exists. Choose another." and the category lookup refreshes |
| Report not found | 404 | `report.error.dashboardReport.notFound` | Edit read: `DialogNotFound`. PUT or DELETE: toast "This report no longer exists." and the list refreshes |
| Other (500 on a DB constraint, invalid type) | 4xx/5xx | varies | Generic `apiErrorText` in the dialog |

### Data flow

- **Route** `src/routes/(protected)/_protected.administration.reports.tsx`:
  `staticData.rights: [RIGHTS.reportsManage]`; the loader awaits `requireRouteRights`, then
  prefetches the list without awaiting it. `pendingComponent` shows the real header, a disabled
  toolbar and the skeleton, as FM-163.
- **URL**: `tableSearchSchema(['name', 'category'])` with default `name` ascending kept out of the
  URL; `report` (`'new'` or a lowercased guid) and `delete` (a lowercased guid), invalid values
  falling back to `undefined`; `report` wins over `delete`.
- **List** reads `GET D` once under `queryKeys.dashboardReports.list({ scope: 'admin' })` and sorts
  (locale collator, name then category; ties by the other) and pages locally with `pageLocally`.
  A past-end page clamps with FM-163's clamp (after the dialog closes, replacing history), with a
  minimum last page of 1, so the clamp never competes with the dialog's Back.
- **Category lookup** moves to `src/features/reference-data` as `fetchAllReportCategories`,
  `reportCategoriesOptions(userId)` and the `ReportCategory` type, keeping the key
  `queryKeys.reportCategories.list({ userId })` and the complete-page check `fetchCatalog` does
  today. The distinct name avoids clashing with Report Categories' paged `fetchReportCategories`;
  that feature keeps its own reader. The Reports route and `ReportCatalog` import the moved lookup;
  `report-catalog.test.tsx` switches to a partial mock of the reference-data module. The dialog's
  Category picker reads it inside its own `QueryBoundary` with a field-level retry, as Rejection
  Reasons does.
- **Edit detail** `[...queryKeys.dashboardReports.detail(id), opening, reread]`, read fresh on each
  opening, never prefetched. Copy FM-163's pending-save guard: one fixed `useMutationState` filter
  over all pending report saves, Save and Cancel locked while a save for that id is pending, and a
  reread when it settles.
- **The form reads the admin list** with `useSuspenseQuery` inside its own `QueryBoundary` (the
  dialog mounts outside the table's boundary), for the duplicate-name and right-key checks.
- **Show On Home Page confirmation**: when the flag goes from off to on (or is on for Add),
  `onSubmit` first refreshes the admin list (`fetchQuery` with `staleTime: 0`), since the cache
  can be 30 seconds old. If that read fails, the draft stays and the dialog shows the error. If
  another report holds the flag, ask in an `AlertDialog` nested under the form dialog, as Roles
  does (`roles/components/role-form-dialog.tsx`), with a `type="button"` confirm action that sends
  exactly one write with the submitted values:
  "{other} is set to show on the Home page. Show {name} there instead?" with Cancel and Show On
  Home Page. When the saved report is disabled, add: "The Home page will show no report until
  {name} is enabled." No holder means no question. AGENTS.md allows a confirmation when a save
  changes other records. A holder that changes between the check and the PUT is still cleared by
  the server; that race is accepted.
- **After save or delete**: cancel then invalidate the list keys only,
  `[...queryKeys.dashboardReports.all, 'list']`, with `isCurrent()` checks after each await. That
  refreshes the admin list, the Reports catalog and Home's report, without refetching an open
  detail read, which after a delete would answer 404 mid-close (FM-163's pattern).
- **Home panel**: `HomeReport` in `src/features/reports` reads
  `availableReports?showOnHomePage=true&size=0` under
  `queryKeys.dashboardReports.list({ userId, showOnHomePage: true })` with a non-suspending
  `useQuery`. One online policy covers it: no loader prefetch, the query is enabled only when
  online, and its retry runs only when online (legacy makes no request offline). It fetches once
  the connection returns.
  - It renders nothing while pending, offline, or with no report, so users without a Home report
    never see a flash.
  - With a report, it renders `content[0]` in a card titled with the report's name, below
    `HomeDashboard`, using `DashboardViewer`. The Home route passes `userId` and `username` (from
    the login store, as the dashboard route does); `HomeReport` calls `getSupersetUrl` itself.
  - `DashboardViewer` gains a `placement="home"` mode (default keeps the catalog viewer as is).
    In it, every path that leads to `/reports` stays in the panel instead: the unsupported,
    refused and not-registered states and the Superset sign-in dismissal show an in-panel message
    with Retry, or hide the panel when dismissed. Home users may lack Reports View.
  - The Home card gives the viewer a bounded height (a plain size such as `h-128` on a wrapper,
    never arbitrary values or `className` on shadcn parts) that its loading state also uses, and keeps the
    frame's own controls visible at 390 px, since Home does not use `layout="viewport"`.
  - On error it shows a small alert with Retry and the shared `home.load-error` text, through
    `useOfflineFailure`, never breaking Home.
  - The route mounts it with `key={revision}`, so Refresh remounts it. Home's Refresh
    `useIsFetching`/`resetQueries`, `onLeave` and `src/lib/home-navigation.ts` cancel the partial key
    `queryKeys.dashboardReports.list({ showOnHomePage: true })` as well as `home.all`.
- **Delete**: extract FM-163's `delete-category-dialog.tsx` into a shared component under
  `src/components/display/`. It takes the target, the row hint, the opener and Add focus refs,
  opening-keyed query options for the direct-link read, the delete call, the refresh and the
  translated copy, and keeps the hint capture at mount, Delete disabled until a direct-link read
  succeeds, the focus rules, 404 refresh, no toast offline and the refusal toast. URL state, hint
  clearing when the URL leaves `?delete=`, and the Forward-during-close regression test stay in
  each route, where they are exercised today.

### Rules

- Name, Category and Type are required after trimming; values are sent trimmed.
- Name must not match another report's name (case-insensitive) on Add or Edit, since an Edit
  duplicate only fails as a 500.
- On Add only (the server derives a right only on POST; PUT keeps the stored one): the name must
  contain at least one Latin letter or digit, and its generated right key must not equal any
  report's stored `rightName`. The key is built exactly as the server does (`PropertyKeyUtil`):
  uppercase, spaces to `_`, characters outside `[A-Za-z0-9_]` removed, a `_` prefix before a
  leading digit, and `_RIGHT` appended. Otherwise the POST fails with a 500. Edit keeps only the
  duplicate-name check, so renaming a report stays allowed. Stricter than legacy, which lets those
  saves fail.
- Superset needs a URL or an Embedded UUID. Power BI needs a URL, and its UUID is cleared on save.
- A UUID must be 8-4-4-4-12 hex. A URL is checked only when it is used (Power BI, or Superset
  without a UUID): it must pass the viewer's own check (absolute http(s), no user name or password,
  not the app's own address), shared through `src/lib/frameable-url.ts`. A Superset URL whose
  origin differs from the configured Superset address is not blocked; the viewer's own set-up
  message covers it. A Superset report with a UUID keeps whatever URL it has, so an old unused URL
  never blocks an edit. Stricter than legacy, but the viewer cannot open anything else.
- Superset shows legacy's hint that at least one of URL or Embedded UUID is required.
- Enabled and Show On Home Page are off on Add, as legacy.
- Saves happen at once, except the Show On Home Page takeover, which asks only when another report
  holds the flag.
- Toasts say Added, Saved or Deleted, fixing legacy's "edited" on Add.

- Home discovery skips `REPORTS_VIEW`, but the Superset guest token requires it (FM-111). A user

## Decisions

1. **Local sort and paging.** The server's paging returns wrong totals, and legacy reads all rows
   with the same call.
2. **New `dashboard-reports` feature.** The category lookup moves to `reference-data`, so this
   feature, Reports and Report Categories share it without crossing feature boundaries.
3. **Home panel in this PR** (user decision), using the existing dashboard viewer.
4. **Keep the Home takeover confirmation**, since the save changes another report.
5. **Stricter checks than legacy**: URLs must pass the viewer's check, and names must avoid the
   server's right-name failures (a Latin letter or digit, no colliding key), so saves fail in the
   form instead of with a 500.
6. **Shared delete dialog**: FM-163's delete dialog becomes a shared component rather than a copy.
