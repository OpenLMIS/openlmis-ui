# FM-131: Requisition Group View

https://openlmis.atlassian.net/browse/FM-131 · Parent: FM-124 Admin: facilities & supply chain

Ships with [FM-129](FM-129.md) and [FM-130](FM-130.md), which carries the shared API map,
files, rules and tests.

## Scope

A read-only page for one group: the [FM-130](FM-130.md) editor with `readOnly`.

## Summary

Admins can open a group just to look at it: code, name, supervisory node, its programs and
schedules, and its member facilities with the same filter and pages as Edit. Nothing can be
changed and nothing can be saved. Cancel returns to the list as it was.

Legacy's view page marks fields as required although they cannot be edited. It shows an empty
Actions column and leaves Direct Delivery out. Its breadcrumb has no link
back to the list. The new page fixes those.

## Legacy Today

Route `/#!/administration/requisitionGroups/{id}?tab&facilityName&memberFacilitiesPage&memberFacilitiesSize`
(`administration.requisitionGroupView`), right `REQUISITION_GROUPS_MANAGE`. The heading is the
group name; the breadcrumb says "View Requisition Group", without a link to the list. It shows:

- disabled Requisition Group Code, Requisition Group Name and Supervisory Node, still marked
  required;
- a Programs table with Program and Schedule, plus an empty Actions column;
- Facilities with the filter, pages and an empty Actions column;
- Cancel.

It loads only `GET /requisitionGroups/{id}`. Screenshot `.screenshots/FM-39/legacy/extra-group-view-*`.

## Agent Brief

- Route `/administration/requisition-groups/$id`
  (`_protected.administration.requisition-groups_.$id.tsx`).
  - It awaits `requireRight`, then awaits the detail.
  - Entry reads fresh with `fetchQuery({...requisitionGroupOptions(id), staleTime: 0})` and
    `preload: false`; tab changes use `ensureQueryData` to preserve the cached detail.
  - The loader returns its completed record and read timestamp. The editor remounts for
    each group id or fresh entry; tab changes keep the same record.
  - A 404 shows the not-found panel.
- `staticData.crumbKey: 'requisition-groups.view-title'`. The title is the group name and the
  description is one sentence. Pending keeps a title-height placeholder until the name loads.
- **Editor with `readOnly`:**
  - fields disabled without required marks, in legacy View's order and labels: Requisition
    Group Code, Requisition Group Name, Supervisory Node;
  - the Programs table shows Program, Schedule and Direct Delivery, with no Actions column;
  - Members has no Add and keeps an empty, unlabelled actions column, as legacy; filter, sort
    and pages are unchanged;
  - no discard guard;
  - the footer has only Cancel (`size="lg"`, at the start).

## UI/UX

| Element | Call | Why |
|---|---|---|
| Disabled fields | Port | Ticket: same screen, every field disabled; View keeps its own labels and Code-first order |
| Cancel to the bare list | Improve | Cancel returns to the list with the filters it was opened from |
| Required marks, empty Programs Actions column | Drop | Nothing can be edited; Facilities keeps its empty actions column, unlabelled |
| Direct Delivery hidden | Improve | Shown, as on Edit |
| Breadcrumb without a list link | Fix | Home / Administration / Requisition Groups / View |
| Header actions | Port | None: Cancel only, as legacy (agreed 2026-10-14) |

## Decisions

- **Same component with `readOnly`**, not a separate view. It follows the `readOnly`
  presentation of `program-link-dialog.tsx`: no Save is rendered, submission returns early in
  `readOnly`, and the discard guard is off.

- **No header actions on View** (agreed 2026-10-14): Cancel only, as legacy.
