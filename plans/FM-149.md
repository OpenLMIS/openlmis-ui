# FM-149: Requisition Template Configure

https://openlmis.atlassian.net/browse/FM-149 · Parent: FM-139 Admin: Products & Programs ·
Epic plan: [FM-39](FM-39.md) (Tier 1, row 4) · Builds on [FM-148](FM-148.md), same PR

## Scope

The page Configure opens: Template Columns and Template Settings as two tabs over one draft,
saved together. It uses the feature, types, API and right FM-148 adds.

Shared pieces this plan changes, all additive:

- `src/components/form/form-fields.tsx`: `TextField` and `NumberField` accept opt-in `controlSize="sm"`
  for the columns grid; existing inline callers retain their default size.
- `src/components/ui/table.tsx`: a `TableRow` drag variant that reads the row's movement from CSS
  custom properties, since inline `transform` styles fail `shadcn/no-inline-styles`. Added to
  AGENTS.md's table of required customizations.
- New dependencies `@dnd-kit/core`, `@dnd-kit/sortable`, `@dnd-kit/modifiers` and
  `@dnd-kit/utilities` for moving rows (see Decisions). They load with this page's route chunk
  (`autoCodeSplitting`); the offline service worker still precaches that chunk.

Out of scope: adding or removing columns (legacy edits only the columns a template has), the
`enableAvgConsumptionForCurrentPeriod` flag (legacy has no control; the page keeps its saved
value, which legacy's save resets), and changing the template's program (fixed, as legacy).

## Summary

Configuring a template means choosing, column by column, what a requisition shows: whether the
column is displayed, its label and definition, where its value comes from (typed in,
calculated, reference data, or stock cards) and a few extra options, such as how skipped
products appear, how many periods average consumption covers, and when packs to ship show. Its
settings say what the template is called, which facility types use it, and whether it asks for
a rejection reason, is report only, or adds the Patients tab. A template can also read stock on
hand from stock cards instead of asking for it.

In the old UI the page has the same two tabs, each with its own Save button, although both save
everything. Rows move by dragging, except the three fixed at the top (Skip, Product Code,
Product). A broken rule shows its message in the row as you edit, and Save refuses with
"Requisition Template is invalid". The fixed bottom bar can sit over the last rows.

The new page works as legacy does (the user's decision, 2026-10-14): every column, control,
rule, message and confirmation stays. What changes: one Save for both tabs in a footer that
never covers a row, which checks both tabs and opens the one with the first error; rows can also
move by touch and keyboard; and saving no longer drops deactivated facility types or one setting
legacy does not show.

## Legacy Today

Routes `/#!/administration/templates/{id}/columns` and `/settings`
(`openlmis.administration.requisitionTemplates.configure.columns` / `.settings`), right
`REQUISITION_TEMPLATES_MANAGE`. Title "Configure {template} For {program}", from the saved name.
Evidence: `.screenshots/FM-148/research-a-legacy-browser.md` (full row inventories for CHAZ,
EPI and TB Monthly), `research-b-source-api.md` sections 2 and 5 to 8, `verify-legacy.md`,
`verify-api.md`.

- **Columns**: heading "Configure Template Columns", an "Enable Stock on Hand to populate from
  stock cards" checkbox ("Stock on Hand will be populated from stock cards instead of being
  entered manually."), then a grid: drag handle or lock, Display checkbox, indicator, Label
  input, Definition input (140 characters, with a characters-left counter), Source, Additional
  Options. CHAZ and TB Monthly have 31 rows, EPI 33. S, O and R are locked; only R's Display is
  disabled.
- **Stock toggle**: on, it sets seven columns (A, B, C, D, E, P, X) to Stock Cards and shows a tag
  select on B, C and D, with tags from `GET stockCardLineItemReasonTags`, each tag used once. Off,
  it sets them back to User Input where offered, else the first other source, without restoring
  earlier choices.
- **Drag**: C dropped before B moves; any drop across or onto a locked row is refused with
  "Cannot drop column here". No keyboard way to move a row.
- **Errors**: checked live; the first failing rule of a row shows as text in its Additional
  Options cell, for example "Column label cannot be empty!", "Should be displayed if source is
  USER INPUT", "Number of periods to average must be greater than or equal to 2", "This column
  should be displayed/not displayed together with: Requested quantity explanation". Save then
  toasts "Requisition Template is invalid" and sends nothing.
- **Settings**: heading "Configure Template Settings"; required Template Name; Active Rejection
  Reason, Requisition Report Only and Enable Patient(s) Tab checkboxes with help text; a Facility
  Type select with Add and a Facility Type / Action table with Remove ("No facility type found."),
  sorted by name. The select leaves out types any template of the program uses, whatever its
  report only flag.
- **Save**: from either tab, confirms ("Save changes to the requisition template", "All changes
  to the requisition template columns and settings will only affect future initiated
  requisitions."), PUTs the whole template, toasts and returns to the list. Settings' Save skips
  the column checks. Edits survive tab switches. Cancel returns to the list and discards.
- **Defects**: Settings' Save skips column checks; inactive facility types dropped by Settings;
  `enableAvgConsumptionForCurrentPeriod` reset to false by every save; the Supplying Facility
  Stock source shows a blank label; failures say only "Failed to save the requisition template";
  the confirmation's "only future requisitions" is not true for report only templates (below).

## Agent Brief

### API Map

| Step | Method And Path | Params | Fields Used | Right | Legacy Ref |
|---|---|---|---|---|---|
| Template | `GET requisitionTemplates/{id}` | none | whole template | `REQUISITION_TEMPLATES_MANAGE` | `admin-template-configure.routes.js:41` |
| Program name | `GET programs` | none | `name` | none | `:44` reads one program; the list is cached already |
| Tags | `GET stockCardLineItemReasonTags` | none | string array | none | `template.routes.js:35` |
| Facility types offered | `GET facilityTypes?active=true` | `active=true` | `id`, `code`, `name` | none | `admin-template-configure-settings.routes.js:35` |
| Facility type names | `GET facilityTypes` | none | `id`, `code`, `name` | none | not in legacy (FM-148 Decisions) |
| Other templates | `GET requisitionTemplates` | none | `id`, `name`, `program.id`, `facilityTypes` | `REQUISITION_TEMPLATES_MANAGE` | `:43` |
| Reread before save | `GET requisitionTemplates/{id}` | none | whole template | same | new: the house rule for whole-record saves |
| Save | `PUT requisitionTemplates/{id}` | whole template | status | same | `requisition-template.service.js:127` |

**Save**: reread the template, then apply only what this page edits onto that copy: `name`,
`rejectionReasonWindowVisible`, `requisitionReportOnly`, `patientsTabEnabled`,
`populateStockOnHandFromStockCards`, `numberOfPeriodsToAverage` (a number, or `null` when
blank), `facilityTypes` as `{ id }`, and per column `label`, `definition`, `isDisplayed`,
`source`, `option` (the whole option object from the reread column's `columnDefinition.options`
matching the chosen id, since the server compares `id`, `optionName` and `optionLabel`; `null`
when none is chosen), `tag` and, when the order changed, `displayOrder`.
Everything else, `enableAvgConsumptionForCurrentPeriod` and each `columnDefinition` included,
goes back as read. The last save wins, as legacy and as Products. If the reread copy has no
`program.id`, the template was archived by another save: stop, show "This template has been
replaced. Open it again from the list." and send nothing (a PUT there answers 500).

**Server answers** (`RequisitionTemplateController.java:136`): 200 in every case. Requisitions
point at their template record. When requisitions use the template and the saved copy is not
report only, the server archives the old record (their requisitions keep it) and saves the edit
under a new id. Otherwise it updates in place, so a used report only template changes for its
existing requisitions too. Either way the page returns to the list, which shows the current
template, as legacy.

Failures answer 400 as `{ messageKey, message }`, as a map of fields (`columnsMap`,
`numberOfPeriodsToAverage`, `programId`, `facilityTypeId`, `additionalQuantityRequired`) to
`{ messageKey, message }` keeping only the last error per field, or as Spring's default body with
`message`. `templateServerMessages(error)` reads a top-level `message`, else every map value's
`message`; the failure toast lists them. The client validator stays the main check.

### Data Flow

- Route `src/routes/(protected)/_protected.administration.requisition-templates_.$id.tsx`,
  URL `/administration/requisition-templates/$id`, search `{ tab?: 'settings' }` (Columns is the
  default and stays out of the URL). `preload: false`. An `$id` that is not a UUID shows Not
  Found without a request (the server answers 400 for it).
- Loader: `requireRight`, then the template with `fetchQuery({ staleTime: 0 })` on `enter` and
  `ensureQueryData` on `stay` (tab switches), and `ensureQueryData(programsOptions())` for the
  title, in parallel. 404, or a template with no `program.id` (an archived id), shows Not Found.
  Then prefetch, without awaiting, tags, both facility type lookups and the template list.
- One form (`useAppForm`) above the tabs, `TabsContent keepMounted`, as the facility editor.
  The draft:

  ```ts
  {
    name, rejectionReasonWindowVisible, requisitionReportOnly, patientsTabEnabled,
    populateStockOnHandFromStockCards, numberOfPeriodsToAverage: string,
    facilityTypeIds: string[],
    order: string[],                        // column keys, top to bottom
    columns: Record<string, ColumnDraft>,   // label, definition, isDisplayed, source,
  }                                         // optionId, tag
  ```

  Column keys are `columnDefinition.id`, not `name`: names such as `orderable.productCode` hold
  dots, which TanStack Form reads as nested paths. Applying the draft maps keys back to names.
  Keyed columns keep field paths stable while rows move, as Physical Inventory's keyed lines, and
  each row subscribes only to its own column. Each column draft also keeps `displayOrder`.
  The draft carries a copied `columnDefinitions` map as read-only editor metadata so the pure
  stock-flag, Display and validation helpers can read names, sources and options directly.
  It also records original display orders, so saves apply draft ordering only after a move.
  This map is never applied on save; `applyDraft` keeps the reread definitions.
- Validation: `onDynamic` runs the pure validator through the schema's `superRefine`, with
  `revalidateLogic({ mode: 'change' })` so it checks as you edit from the start, as legacy,
  rather than the house default of the first Save. After the fields mount, the editor calls
  `form.validate('change')` once, so a saved template that breaks a rule shows it on opening.
- Errors show as legacy: each row's first failing rule, as text in its Additional Options cell
  (plain text, not a live region; the field it concerns gets `aria-invalid` and
  `aria-describedby` pointing at it). Inline fields reference that text through `errorDescriptionId`, so no duplicate error text
  or tooltip appears. Settings fields show their errors under them, as stacked fields do.
- Messages that name a column need values, which the shared `formatError` does not take; the
  validator returns a key and values, and the row cell translates them itself.
- Save: legacy's confirmation first ("Save Changes To The Requisition Template" with "All changes
  to the requisition template columns and settings will only affect future initiated
  requisitions.", Save and Cancel); then `useSessionMutation` and `assertSessionScope` after the reread;
  invalidate `queryKeys.requisitionTemplates.all`; toast "Template Saved" with legacy's "Template
  saved successfully."; return to the list.
- Invalid Save: no confirmation and no request; an error toast "Requisition Template Is Invalid"
  with "Fix the errors shown in the rows.", as legacy; the page switches to the tab holding the
  first error (Columns before Settings), since one Save now covers both tabs, then focuses the
  first invalid field in draft order once the panel is visible.
- Server failure: an error toast "Template Save Failed" with the server's
  message (`templateServerMessages`), as legacy's notification plus the reason.
- `useDiscardGuard(changed, { pending })` with a `leaving` ref passed as `allowLeave`, as the
  facility editor, so the return after a save is not blocked. Cancel returns to the list through
  the guard.

### Order Rules

- Rows sort by `displayOrder`; equal values keep the response's key order, as legacy (CHAZ has
  six ties).
- A row moves only if `canChangeOrder`, and only within the run of movable rows between the
  locked rows around it (legacy's `moveColumn` interval), so no row crosses or lands on a locked
  row.
- Moving keeps legacy's `moveColumn` (`template.js:214`) limits, but always lands the row where
  the drop gap shows. Within the run, each position keeps its saved `displayOrder`, bumped only
  where needed to stay strictly increasing. Without ties this matches legacy; with saved ties
  (CHAZ has D and TC both at 7) legacy's move is a silent no-op, so the bump renumbers only as far
  as the tie reaches. A run that would reach the next locked row's order is refused.
- dnd-kit: pointer, touch and keyboard sensors; vertical axis only; each movable run has its
  own `SortableContext` inside one `TableBody`. Pointer hits on locked rows or other runs are
  refused; when the pointer drifts off the table, closest-center detection stays within the
  dragged row's run. `moveColumn` retains the legacy interval checks. Refused drops show
  "Cannot Drop Column Here" with a short description, as legacy's error toast.
  Rows move through the `TableRow` drag variant's custom properties. Keyboard: focus the grip,
  Space to pick up, arrow keys to move, Space to drop, Escape to cancel, with translated
  instructions and announcements ("Picked up {label}.", "{label} moved to position {position} of
  {count}.", "{label} dropped.", "Moving {label} cancelled."). dnd-kit announces through its own
  live region while the grid is mounted.

### Validation Rules

`lib/template-validation.ts` ports legacy `template-validator.factory.js` rule for rule, nothing
added or relaxed. As legacy, a row's rules run in this order and the first failure is the row's
error: label, definition, source, option, calculated cycle, user input display, the column's own
rule, tag, stock cards source. `patients` is `patientsTabEnabled`, `reportOnly` is
`requisitionReportOnly`, `stock` is the stock flag. Messages keep legacy's English wording.

| Rule | Row | When | Message |
|---|---|---|---|
| Label not empty | every | always | Column label cannot be empty! |
| Label at least 2 characters | every | always | Column label must have at least 2 characters |
| Label matches legacy's `UTF8_REGEX` (`admin-template/utf8-regex.constant.js:31`, copied as is) | every | always | Columns label cannot have unsupported characters! |
| Definition at most 140 characters | every | always | Column description is too long! |
| Source chosen | every | always | Source cannot be empty! |
| Option chosen | shown rows whose column has options | always | Option cannot be empty! |
| No cycle of Calculated columns through legacy's dependency map (`requisition-column.js:63`) | Calculated rows | always | Cannot be CALCULATED together with: {columns} |
| Shown when its source is User Input and the column offers more than one source | every | not patients, not report only | Should be displayed if source is USER INPUT |
| Periods required, a whole number, at least 2 | `averageConsumption` | always | Number of periods cannot be empty! / the shared whole number message / Number of periods to average must be greater than or equal to 2 |
| Shown together with W | `requestedQuantity` | always | This column should be displayed/not displayed together with: {W} |
| Shown together with J | `requestedQuantityExplanation` | always | This column should be displayed/not displayed together with: {J} |
| Shown only with N shown | `additionalQuantityRequired` | always | This column should be displayed/not displayed together with: {N} |
| Shown when a shown N or P is Calculated | `totalStockoutDays` | not patients | Should be displayed when {column} is calculated. |
| When hidden, J and W shown | `calculatedOrderQuantity` | not patients, not report only | If {I} is not displayed, then {J} and {W} should be displayed |
| Tag chosen | `supportsTag` rows | stock on | Column tag cannot be empty |
| Not Stock Cards | every | stock off | Cannot select Stock Cards if the 'Enable Stock on Hand to populate from Stock Cards' checkbox is not selected. |

Settings, as legacy: Template Name required (legacy marks it required; the new Save enforces it,
since one Save covers both tabs). No duplicate name check and no facility type minimum on
Settings, as legacy. Column names in messages are the template's current labels. Everything the

## Decisions

The user chose legacy's behaviour for everything (2026-10-14).

- **In-page tabs (`?tab=settings`)** with one draft, as the facility editor; legacy's
  `/columns` and `/settings` become one route.
- **One Save for both tabs**, validating both, as the AC asks; legacy's two Save buttons both
  saved everything.
- **Legacy's validator, rule for rule**, nothing added or relaxed; the server's other checks show
  in the failure toast.
- **Legacy's error display**: each row's first error as text in its Additional Options cell,
  checked as you edit, and the "Requisition Template is invalid" toast on Save.
- **Legacy's Save confirmation** before every save, with its text.
- **Legacy's move rule** (`moveColumn`), so ties and gaps stay as saved.
- **Display is a checkbox**, as legacy and the ticket.
- **Legacy's option rule**: Number Of New Patients Added's option stays text.
- **No facility type minimum and no duplicate name check on Settings**, as legacy.
- **dnd-kit for moving rows**: touch and keyboard support with screen reader announcements built
  in, used by shadcn's own draggable data table, and loaded only with this page. No Move Up or
  Move Down controls, as legacy has none. The bundle cost is measured in the build step and
  reported in the PR.
- **Return to the list after Save**, as legacy, whatever id the server answers with.
- **Reason tags fetched in this feature under the reasons' key**: the reasons feature has the
  same small GET, but features cannot import each other and this build was asked not to add
  shared lookups. The copy uses the same key, `[...queryKeys.reasons.all, 'tags']`, so a reason
