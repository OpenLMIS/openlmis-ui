# FM-175: Offline Foundation: App Shell Caching and Local Store

https://openlmis.atlassian.net/browse/FM-175 · Parent: FM-164 Offline support

## Scope

The groundwork every offline screen will build on, with no offline screen of its own:

- **Caching the app itself:** a service worker keeps the app's own files so the app opens and
  reloads offline.
- **Requests fail fast offline:** a request made offline ends straight away in one shared
  "Connect to download this data" state.
- **Status alerts above the sidebar's footer icons:** "You're Offline", "You're Back Online"
  and "Update Available".
- **A per-user local database:** Dexie, opened per deployment and user, with no tables yet.
- **The offline plan as markdown,** plus developer guidance.

It reaches every page, since that is what it is for. It does not keep any API data offline, cache
rights, queue changes or sync: those are FM-166, built with the first stock screen.

## Summary

OpenLMIS is used at facilities where the connection comes and goes. The old UI keeps a few
screens working offline, such as Stock on Hand and Physical Inventory. The new UI has to do
at least as well, so this ticket lays the foundation.

**The old UI today:**

- **Opening offline:** the old UI opens offline only after two online visits. After just one, it
  opens to a blank page.
- **The offline indicator:** it says "You are offline" in the top bar, but on a phone the words
  are cut off.
- **Pages that need the network:** it blocks those with a pop-up and greys out most of the menu.
- **New versions:** its "update available" message stopped working long ago, so users never
  hear that a new version exists. Every start logs an error about it.
- **Offline data:** it keeps offline data in the browser under fixed names that do not depend
  on the user. A second person signing in on the same computer finds the first person's
  stock data.

**The new UI after this ticket:**

- **It opens and reloads offline after one online visit,** in English, Portuguese and Arabic. The
  first visit downloads the whole app in the background.
- **A yellow "You're Offline" alert** appears at the bottom of the sidebar while there is no
  connection. A green "You're Back Online" shows for a few seconds when it returns.
- **Pages never spin forever.** A page that needs data it cannot fetch says "Connect to download
  this data" with Try Again, and tries again by itself when the connection comes back.
- **A new version waits for the user.** A blue "Update Available" alert in the same spot offers
  to reload into it, and asks first if there are unsaved changes.
- **A local database is ready for later work,** kept apart for each deployment and each user.
  Nothing is stored in it yet.

## Legacy Today

Screenshots are in `.screenshots/FM-175/`, taken from `test.openlmis.org`.

- **Service worker.** A Workbox worker at scope `/` (`dev-ui/src/src-sw.js`) precaches 23 files
  (2.5 MB). It keeps `openlmis.js` (6.3 MB, too big for the precache) in a
  stale-while-revalidate `assets` cache. That cache fills only once a page is controlled, so a
  cold open offline after one visit is a blank page (`legacy-cold-open-offline-after-one-visit-desktop.png`).
  After two visits, a reload offline takes about 0.2 s (`legacy-reload-offline-*`). `/api` is
  network-only. The scope `/` also covers `/v2/*` until our own worker installs.
- **Offline detection.** Offline.js reacts to the browser events, then polls
  `HEAD /favicon.ico` about every 3 to 12 s, which logs `ERR_INTERNET_DISCONNECTED` each time.
  The indicator shows within about 20 ms and clears within about 300 ms.
- **Header.** A lightning icon, "You are offline" and "Check connection"
  (`legacy-users-offline-indicator-*`). At phone width the words are cut off.
- **Menu.** 84 of 114 links are greyed out offline (`legacy-admin-menu-offline-desktop.png`).
  Opening one gives the modal "This page can't be loaded while offline." Any `$http` call while
  offline is cancelled with "This action can't be completed while offline.", and Home shows it
  on every load.
- **Offline pages.** Stock on Hand shows the banner "You are offline. Information on this page
  may not be accurate at this moment..."
- **Updates.** The AppCache "Update Available" flow depends on `window.applicationCache`, which
  browsers removed, so it never shows. Every start logs a `TypeError` from
  `OpenlmisAppCacheController`.
- **Local data.**
  - **PouchDB:** databases with fixed names (`_pouch_orderables`, `_pouch_stockCardSummary` and
    others), about 9 to 17 MB.
  - **localStorage:** about 2.7 MB under `openlmis.*`.
  - **Nothing is scoped to a user.** Sign-out clears localStorage and some of the databases, but
    `orderables` and `stockCardSummary` stay, for whoever signs in next.
- **Offline sign-out** warns first. FM-14 already ported that warning.
- **Offline routes** (`isOffline: true`), for FM-167:
  - home and login;
  - requisitions: search, approval list, batch approval, view and order create;
  - stock management: stock on hand, physical inventory draft, issue, receive, adjustment and
    the mobile flows;
  - the CCE item details page;
  - pending offline events.

## Agent Brief

### API Map

There are no new API calls.

The service worker must leave `/api/**` alone: sign-in, sign-out and every data call go to the
network untouched. It is scoped to `/v2/` and has no runtime route matching `/api`. `/api` is
outside the base path, so a `/v2/` worker still sees those requests from `/v2` pages, but it
passes them through.

### Data Flow

**Service worker** (`vite-plugin-pwa` 1.3.0, peer `vite ^8`) in `vite.config.ts`:

- **Registration:** `registerType: 'prompt'`, `injectRegister: false` (the React hook
  registers), `manifest: false` (no install prompt), `filename: 'sw.js'`. `base` and `scope`
  come from Vite's `base`, which gives `/v2/sw.js` at scope `/v2/`.
- **Precache:** `workbox.globPatterns: ['**/*.{js,css,html,png,svg,woff2}']`, which covers every
  font subset, so Arabic renders offline. Locales are left out on purpose, see below.
  `cleanupOutdatedCaches: true`. The `maximumFileSizeToCacheInBytes` default of 2 MiB stays;
  step 1 checks no chunk is bigger.
- **Navigations:** `navigateFallback: 'index.html'`, with `navigateFallbackDenylist:
  [/^\/api\//]`.
- **Runtime caching:**
  - `**/config.json`: `NetworkFirst`, `networkTimeoutSeconds: 3`, cache `openlmis-ui-config`.
  - `**/locales/*.json`: `NetworkFirst`, `networkTimeoutSeconds: 3`, cache
    `openlmis-ui-locales`, so a deployment can still correct a string without a rebuild. A
    precache would freeze them at the build.
  - Cache names are prefixed `openlmis-ui-`, since legacy uses `pages`, `assets` and `images`
    on the same origin.
- **Dependencies:** add `workbox-window` as a direct dependency (vite-plugin-pwa issue #936
  under pnpm).
- **`preview.proxy`:** a copy of `server.proxy`, so `pnpm preview` under `/v2` can sign in, for
  the browser checks.
- **Warming the locales:** after the first render, `warmTranslations()` fetches every
  `SUPPORTED_LANGUAGES` catalog once, not awaited, so all three are in the cache after one
  visit. It is done by the app, not the worker, because the worker cannot read i18next's
  language list.

**Online state:** `src/lib/online.ts`:

- `onlineManager.setOnline(navigator.onLine)` at boot, since Query v5 otherwise starts online
  even when opened offline.
- A `useOnline()` hook built on `onlineManager.subscribe` with `useSyncExternalStore`.
- `isOnline()` for code outside React.
- `offline-sign-out.tsx` swaps `navigator.onLine` for `isOnline()`, so there is one source of
  truth.

**Query client** (`src/integrations/tanstack-query.ts`):

- `networkMode: 'always'` for queries and mutations, so an offline request goes out, fails at
  once with a network error, and ends in an error state instead of `fetchStatus: 'paused'`.
- `shouldRetry` also skips `isOfflineError` while `!isOnline()`, since a retry would fail the
  same way.
- The Session Expired dialog's own `networkMode: 'always'` becomes redundant; remove it.

**Recognising an offline failure:** `src/lib/http.ts` gains
`isOfflineError(error) = isAxiosError(error) && !error.response && error.code !== 'ECONNABORTED'`.
That is a network failure, not a timeout or an HTTP status. The offline branch shows when
`isOfflineError(error) || !isOnline()`.

**Shared offline state:**

- `src/components/offline-notice.tsx` shows a `WifiOffIcon`, "Connect To Download This Data"
  and "You're offline, and this hasn't been downloaded to this device. It loads once you're
  back online.", with Try Again.
- When `useOnline()` flips back to true, it calls its `onRetry` by itself.
- Wired into:
  - `ErrorFallback`, the route default, which also covers blocking loaders such as
    `requireRight`;
  - `WidgetError` on Home;
  - `DialogLoadError`;
  - the error branch of the Users, Roles and Service Accounts list boundaries.
- `DataTableError` is registry code, so the list pages pass the offline title and description
  in rather than it importing i18next.
- Other one-off error views keep their "check your connection" copy, which is already a clear
  error.

**Sidebar notices:** `src/components/sidebar-notices.tsx`, in `AppSidebar`'s `SidebarFooter`,
above the theme and language buttons. Compact one-line alerts, like a toast: an icon, a title,
an optional action and an optional close.

- **Offline:** `Alert variant="warning"`, `WifiOffIcon`, "You're Offline", with the line "Pages
  you've already opened still work; anything new needs a connection." It shows while
  `!useOnline()` and has no close, since it stays true until the connection is back.
- **Back online:** `Alert variant="success"`, `WifiIcon`, "You're Back Online". It shows for
  4 s after going from offline to online, with a close.
- **Update available:** `Alert variant="info"`, `RefreshCwIcon`, "Update Available".
  - It comes from `needRefresh` in `useRegisterSW` (`virtual:pwa-register/react`).
  - Its Reload action runs `whenLeaveAllowed(() => updateServiceWorker())`, so a draft is asked
    about first.
  - Its close hides it until the next start.
  - `onRegisteredSW` sets up `registration.update()` every hour, so a tab left open still learns
    of a new version. `offlineReady` shows nothing.
- **Collapsed sidebar:** each notice becomes its icon alone, in its colour, as a
  `SidebarMenuButton` with the title as its tooltip. The update one reloads on click.
- **Phone:** the notices are in the sidebar sheet. While offline, the header's sidebar trigger
  also gets a small warning dot, so it is seen without opening the menu.
- **Variants:** `Alert` gains `success` and `info` in `src/components/ui/alert.tsx`, matching
  `Badge`'s, and AGENTS.md's variant list gets them.
- **Roles:** offline and back online use `role="status"`, which is polite, since they are not
  errors.

**Local database:** `src/lib/local-db.ts` (Dexie 4.4):

- `localDatabaseName({ deployment, userId })` gives `openlmis-ui:<deployment>:<userId>`.
- The deployment is `location.origin + import.meta.env.BASE_URL`. In dev, when
  `VITE_API_PROXY_TARGET` is set, that target replaces the origin, since one `localhost` can
  point at different servers.
- `getLocalDb()` opens, lazily, the database for the signed-in user. It declares
  `version(1).stores({})`, since screens add their tables later. It throws when no one is
  signed in.
- A store subscription closes it (`db.close()`) and forgets it whenever `referenceDataUserId`
  changes, next to the query-cache clear.
- Nothing is deleted on sign-out yet (see Decisions).
- Tests use `fake-indexeddb/auto` in `src/tests/setup.ts`.

**Config on reconnect:** `runtime-config.ts` reloads `config.json` on the next `online` event
when the first load failed. A tab started offline can then sign in once the connection is back,
without a reload.

### Risks and Edge Cases

- **Legacy's worker at `/`** handles `/v2` pages until ours installs, and may cache a `/v2`
  `index.html` into its `pages` cache. It is harmless: ours takes over at scope `/v2/` on the
  first visit.
- **A missing `sw.js`** is answered by the SPA fallback with `index.html` and a 200, so
  registration fails with a MIME error. It only happens if the build drops it; step 1 checks
  `dist/sw.js`.
- **The gateway's rate limit** (20 r/s, burst 10) could answer `429` during the precache
  install when the Host is not allowlisted (`deployment.md`). The worker retries on the next
  visit, but it is worth watching on test.
- **`navigator.onLine` can say online with no real network.** Requests then fail with network
  errors and the notice still shows, because `isOfflineError` counts. The sidebar alert would not
  show;
  polling to detect that is left out (see Decisions).
- **The discard guard's `beforeunload`** could raise the browser's own prompt again after the
  user already agreed in `whenLeaveAllowed`. The reload has to pass the guard's `allowLeave`.
- **Precache size.** It is measured in step 1. Dropping Roboto saves about 231 KB; the fonts in
  total are about 560 KB.
- **`config.json` holds the OAuth client id and secret,** and the network-first cache keeps a
  copy in Cache Storage. It is already served to every visitor unauthenticated, so this exposes
  nothing new.

## Decisions

- **Locales are runtime cached, network first, not precached,** so a deployment can still fix a
  translation without a rebuild, as AGENTS.md promises. All three are fetched after the first
  start, so every language works after one visit.
- **`networkMode: 'always'` app-wide.** An offline request fails at once and shows the notice.
  The default would pause, which is the endless spinner. Offline reads from Dexie in FM-166
  will run the same way.
- **The online signal comes from browser events, seeded at boot.** No polling. A failed request
  still shows the notice, which covers the "online but no network" case.
- **The local database is closed on a user change or sign-out, not deleted.** Deleting only
  becomes a question once there is data in it; FM-166 decides it, with the offline plan's
  "warn before deliberately discarding unsynced work".
- **The database name** is `openlmis-ui:<deployment>:<userId>`, where the deployment is the
  origin plus the base path, or the dev proxy target in dev.
- **No web app manifest or install prompt.** This ticket is about working offline, not
  installing the app. `manifest: false`.
- **Roboto is dropped:** unused, and 231 KB less to precache.
- **The status lives above the sidebar's footer icons, not in the top bar.** That was the
  user's call: offline, back online and a new version, as compact coloured alerts in one place.
  The ticket's "top bar" criterion is reworded to match.
- **No greying out of menu entries offline** until a page works offline; the sidebar alert says
  it instead.
