# FM-140: Products List + Add

https://openlmis.atlassian.net/browse/FM-140 · Parent: FM-139 Admin: Products & Programs

## Scope

Administration > Products: the server-paged list with its Code, Name and Program filters,
and the Add Product dialog. It is item 5 of the admin round that sets up what Stock
Management reads (see [FM-62](FM-62.md), "Administration first"), and the first screen of
the products group: FM-141 Product Edit (tabs FM-150 to FM-153) and FM-143 Lots come after it.

It also adds two small shared pieces:

- a page that opens with **any one of several rights** (`requireRight` and `NAV_RIGHTS`
  take a list), since legacy opens Products with either of two rights;
- `min` and `max` options on FM-127's `wholeNumberText`, since pack sizes are Java `long`s,
  not `int`s.

Out of scope:

- **The Edit action and the edit page.** They are FM-141. This PR's list has no row actions
  yet (see Decisions).
- Opening the edit page after an add (legacy does). It waits for FM-141.
- Sorting by column: the server ignores `sort` once any filter is set (see Decisions).
- Every product field beyond the ones Add sets (programs, identifiers, kit contents, trade
  item, VVM).

Depends on FM-127 for `NumberField` and `wholeNumberText`: the list is built first, and the
dialog after FM-127 merges and this branch is rebased on it.

## Summary

Products are the items the system supplies, such as a medicine or a vaccine. Every
requisition, order and stock screen picks from them, and their pack size decides how doses
are counted in packs.

In the old UI, Administration > Products lists the products 10 at a time, with Code, Name,
Description and an Edit button per row. A Filter button opens Code, Name and Program
filters with a Search button. The local demo has 10,233 products. Add Product opens a window
with Product Code, Name, Description, and a "Pack Size Information" group: Dispensing Unit,
Net Content, Pack Rounding Threshold and Round to Zero. Saving opens the new product's
edit page. It works, but:

- Filtering from page 4 stays on page 4, so a search with 4 results shows "Showing 0 items".
- Net Content and Pack Rounding Threshold silently drop what they don't accept, so "1.5"
  becomes 15 and "-5" becomes 5.
- Leaving Dispensing Unit empty passes the form, then the server refuses the product. The
  window says only "Failed to create product", never why, and the same goes for a
  product code already in use.
- Anyone can open the Add Product address, even without the right.
- On a phone the table runs off the screen and the Edit buttons are out of reach.

The new screen keeps the same data, filters and rules, and fixes those:

- Code, Name and Program filters sit above the table and apply as you type; each new
  filter starts again from page 1, and the filters stay in the address.
- The page size can be changed, as on every other list.
- Add Product opens a short dialog with the same fields. Dispensing Unit is required, as the
  server already demands; the number fields say what they accept instead of changing it; a
  product code already in use is flagged on the field; any other refusal shows the
  server's reason, and nothing typed is lost.
- Only users who may manage products see Add Product or can open it by its address.
- It works on a phone and in Arabic.

Until Product Edit (FM-141) is built, the new list has no Edit action and a new product
stays on the list after saving; editing a product still happens in the old UI.

## Agent Brief

### API Map

| Step | Method and path | Params and body | Fields used | Right | Legacy ref |
| --- | --- | --- | --- | --- | --- |
| List | `GET /orderables` | `page` (0-based), `size`, `sort=fullProductName`, `code?`, `name?`, `program?` (program code) | `content[].id, productCode, fullProductName, description`, `totalElements` | none on the server; page needs either right | `admin-orderable-list.routes.js:45-49` |
| Program filter | `GET /programs` | none | `code`, `name` | none | `admin-orderable-list.routes.js:42-44` |
| Add | `PUT /orderables` (no id) | `{productCode, fullProductName?, description?, dispensable: {dispensingUnit}, netContent, packRoundingThreshold, roundToZero}` | `200`, the created orderable | `ORDERABLES_MANAGE` (`403` without) | `orderable-add-edit-general.controller.js:86-98` |

`GET /orderables` details (`OrderableController.java:183-226`, `OrderableRepositoryImpl.java:207-258`):

- Only `id`, `exactCode`, `code`, `name`, `program`, `tradeItemId`, `page`, `size`, `sort`.
  **Any other param is a `400`**, `description` included, which the legacy URL declares.
- `code` and `name`: case-insensitive contains. `program`: case-insensitive exact code.
  Blank strings count as no filter. Only the latest version of each product is returned.
- `sort` applies only with no filter; with any filter the order is always name ascending.
- No `page`/`size` returns every product (10 MB): never call it unpaged.
- The response is a Spring page (`content`, `totalElements`, ...).

`PUT /orderables` details (`OrderableController.java:98-128`, `OrderableValidator.java:81-95`):

- There is no `POST`. Never send an `id`: with one, the call edits that product.
- `200`, not `201`.
- `400 {messageKey, message}`, first error only: `productCode`, `packRoundingThreshold`,
  `roundToZero`, `netContent` required; `referenceData.error.orderable.productCode.mustBeUnique`
  ("Product code is not unique", case-insensitive); a missing `dispensable` or one with neither
  `dispensingUnit` nor `sizeCode` ("dispensable is required, with either a dispensingUnit or
  a sizeCode").
- The server strips all whitespace from `productCode` (`Code.java`) after the uniqueness check,
  so "AB C" against "ABC" passes the check and fails on the DB constraint with a raw message.
  Sending the code with whitespace removed makes the check catch it.

### Data Flow

- Loader: `const rights = await requireRight(queryClient, [RIGHTS.orderablesManage,
  RIGHTS.facilityApprovedOrderablesManage])`, then `prefetchQuery` of the page from
  `loaderDeps` and of `programsOptions()`, both deferred; returns
  `{ canAdd: rights.has(RIGHTS.orderablesManage) }`.
- URL: `page`, `size`, `code`, `name`, `program`, and `product=new` for the dialog, through
  `useSearchNavigation`. No `sort`/`dir`. Defaults stay out of the URL.
- `?product=new` without `canAdd` renders no dialog.
- Keys: `queryKeys.orderables.list(query)`. A save invalidates `queryKeys.orderables.all`, so
  later orderable lookups refresh too.
- The toolbar reads programs with `useQuery` (it sits outside the `QueryBoundary`). Until
  they load, or if they fail, the select offers the program code from the URL, so the filter
  still shows and can be cleared; the list works either way.
- The table reads the query through `useDeferredValue(search)`, as Users. A page past the end
  steps back to the last page.

### Rules

- Product Code required, whitespace alone counts as empty; sent with all whitespace removed,
  as the server stores it (`Code.java`).
- Name and Description optional; trimmed, and left out of the body when blank.
- Dispensing Unit required, trimmed (the server refuses a product without one:
  `Dispensable.createNew`).
- Net Content: whole number from 1 to 9007199254740991. Pack Rounding Threshold: whole
  number from 0 to 9007199254740991. Both sent as numbers. (Legacy: `positive-integer`,
  max `Number.MAX_SAFE_INTEGER`, 0 allowed on both; see Decisions for Net Content.)
- Round to Zero always sent, default off.
- Product codes are unique ignoring case; only the server can check, since the list is paged.
- A new filter, or a cleared one, returns to page 1.

### Risks and Edge Cases

- **A `'` in a filter.** The server builds part of the list query by concatenating the
  filters into SQL (`OrderableRepositoryImpl.java:294-339`, marked `FIXME`), so a quote
  answers `500` (checked locally) and is a SQL injection. The list shows its error state;
  the backend fix is FM-179.
- `%` and `_` in a filter match anything. The server has no escape; accepted, as legacy.
- Products with no name show an empty Name cell and sort last, as legacy.
- Live filtering sends a request per pause in typing (300 ms debounce); a name filter costs
  about 1 s on the server. The deferred query keeps the old rows until the new ones arrive.
- A filter written into the address by hand that the router reads as a number comes back
  as that number's text: `?code=1133` works, but `?code=1e3` searches for "1000". Links the
  app writes are quoted (`?code=%221133%22`), so only hand-typed links are affected.
- Back while a save is running closes the dialog, and a refusal then goes unseen. The lock
  in the shared `useDialogTarget` covers Escape, Cancel and outside clicks only; Facility
  Types shares it. A fix belongs in the shared dialog, not here.
- A list error says "Check your connection and try again." also when the server answered,
  as Users does. A server-error wording belongs in the shared copy, not this page.
- Rebasing on FM-127 touches the same lines in `rights.ts`, `key-factory.ts`,
  `nav-access.ts` (+ test), `config.ts` (+ test), the locale files and `route-tree.gen.ts`;
  all additive.

## Decisions

- **Either right opens the page, as legacy.** `FACILITY_APPROVED_ORDERABLES_MANAGE` alone shows
  the list without Add Product, so FM-152's users can reach a product's Facility Types
  tab. The AC's "only users with the right to manage products" is read as those two rights.
- **Dispensing Unit is required.** The server refuses a product without one, and legacy only
  passes when the field was typed in and cleared, which saves an empty unit by accident.
  Marking it required tells the user before saving instead of after.
- **Net Content starts at 1.** With a pack of 0 the server orders 0 packs for any quantity
  (`Orderable.packsToOrder`), and stock's packs and doses maths would divide by it. Legacy
  accepts 0; nothing valid is lost.
- **No sorting by column.** The server orders any filtered list by name whatever `sort`
  says, so a sortable header would silently stop working as soon as a filter is set.
- **The program filter sends the code**, as legacy and the API do; the URL holds the code, so
  legacy links translate one to one.
- **The shared pager replaces "Showing X item(s) out of Y total"**: the same range and total,
  in the format of every other list here.
- **No confirm before saving**, as legacy's Add and FM-127's rule for every CRUD dialog.
- **Edit comes with FM-141.** This PR ships the list and Add with the nav entry live, and no
  row actions; FM-141 adds the Edit action with the page it opens, and that AC moves there.
  Until then products are edited in the old UI.
- **After a save the dialog closes onto the list** while the edit page does not exist. Once
  FM-141 builds it, a save opens the new product's edit page, as legacy, since a product is
  of no use until programs and facility types are added.
- **The feature is `products`, the query scope `orderables`**: the screen is named as users
  see it, the cache as the API names it, so later orderable lookups share the invalidation.
- **The unescaped filters are a backend fix**: [FM-179](https://openlmis.atlassian.net/browse/FM-179)
  (epic FM-177 Potential BE improvements). A `'` in any filter answers `500` on the local
  backend; the list shows its error state until it is fixed.
