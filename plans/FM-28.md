### Translation Rules And Risks

- Translate the final English catalogue with consistent Spanish and French terminology
  for facilities, products, programs, roles and stock. Preserve accents and readable copy.
- Preserve ICU argument names and semantic types, explicit `=0` branches, select values
  such as `destinations`, `SUPERVISION`, `ORDER_FULFILLMENT` and `REPORTS`, and `other`.
  Translate text inside branches, not selectors or variables. Use language-appropriate
  plural grammar; French zero commonly uses `one`, whereas Spanish zero uses `other`.
- Check million-count cases where either locale selects `many`; do not assume English
  plural categories cover all inputs.
- French apostrophes before ICU braces can quote placeholders silently. Parse messages
  and verify argument preservation, not only that parsing succeeds. Use correct ICU
  escaping or typographic apostrophes where appropriate.
- Validate the new catalogues' placeholders against English. Do not impose identical ICU
  AST structure on existing Portuguese/Arabic messages, whose grammar may differ.
- Ordinary `JSON.parse` and sorting can discard duplicate keys silently. Validate raw
  keys before sorting. Keep every catalogue flat with nonempty string values.
- English fallback is for missing messages, not a substitute for complete translation.
  Test it with isolated fixtures/stubs, without deleting a committed translation.
- Backend-localized error text and legacy language preferences still follow the existing
  server/cookie behavior. Do not silently add backend language synchronization to FM-28.
