# FM-19: API error mapping to readable messages

Ticket: https://openlmis.atlassian.net/browse/FM-19 (Subtask of FM-8, Data-layer conventions)

## Scope

One shared function turns a failed write or action into the text the user sees, replacing the
hand-written `serverMessage(error) ?? t(fallback)` pattern (71 calls in 60 files) and the raw
`Error.message` fallbacks. Page and list read failures already go through shared fallbacks
(`ListError`, `LoadError`, `DialogLoadError`, `ErrorFallback`) and stay as they are.
Session expiry stays with the session dialog.

Out of scope: offline queue refusals already stored on the device, per-record batch envelopes
(requisition batch approve, batch order send) beyond their request-level fallback, new backend
endpoints or parameters.

## Summary

All eight OpenLMIS services answer application errors as `{ messageKey, message }`. The
`message` is rendered server-side through a `CookieLocaleResolver` (`lang` cookie written by
legacy, otherwise the deployment default; Report is always English), so it is usually not in
the page language and sometimes technical: Auth's `error.sendRequest` and CCE's upload I/O key
embed upstream response or exception text. Spring default bodies, OAuth errors, gateway pages
and empty bodies carry no key.

Legacy's global interceptor shows `error_description || message` for any 4xx/5xx except 401.

The shared function, `apiErrorText(error, fallbackKey, t)`, resolves in this order:

1. **Not ours to show**: `401` on session-managed requests, `SessionEndedError` and
   cancellations (`ERR_CANCELED`) return `null`, and callers render no alert or toast at all.
   Sign-in, session renewal and anonymous requests keep their existing copy.
2. **Timeout** (`ECONNABORTED`, `ETIMEDOUT`): on reads, "The server took too long to answer.
   Try again."; on writes, "The server did not answer in time. The change may have been saved.
   Reload before trying again." Infer the failed request's method in multi-request actions,
   including BUQ forecast saves and batch requisition actions.
3. **Unreachable** (`isOfflineError`, or `isAccessFallbackError` for gateway pages): the existing
   `error.check-connection` copy.
4. **Known key**: a `messageKey` with an `api-error.<messageKey>` catalog entry shows our
   translation in the page language.
5. **Keyed server message**: shown as sent, as legacy does, and the key is logged so a
   translation can be added. Auth upstream failures, CCE upload I/O and Stock Management permission
   check failures skip this step.
6. **Unknown**: use `error.description` by default. Keep feature copy for retained work or
   concrete recovery steps. Connection guidance comes from the unreachable branch.

Logging is separate from text: `reportApiError(error)` runs where the failure is handled
(mutation `onError`, catch blocks), never during render, and logs method, path without query,
status and `messageKey` only for Axios failures. Malformed URLs omit the path. Unexpected
non-Axios failures log the original error, and diagnostic failures leave user feedback available.

## Acceptance Criteria

- **Known message key shows the translated message.** `api-error.<messageKey>` entries in all five
  locales win over server text
- **Unknown error shows a general translated message, details to the console.** Unkeyed or technical
  bodies use the caller fallback; `reportApiError` logs unknown keys and errors at the failure
  boundary
- **Network errors show their own message.** Shared unreachable and timeout copy, ahead of caller
  fallbacks
- **Field validation errors next to the right field where possible.** Users (username, email),
  Profile (email), Facility, Program, Product, Lot, Facility Type, Processing Schedule and
  requisition template fields from real payloads
- **Expired session left to session handling.** `null` result suppresses the whole alert or toast
- **Tests cover known, unknown and network errors.** One table-driven test plus one form interaction
  test

## Legacy Today

- `openlmis-server-error-handler` shows `error_description || message` in an alert for every
  failure except 401, and its own generic copy when there is none.
- `form-server-validation` puts a keyed top-level error in the alert and treats other bodies as
  a field map, marking fields and clearing the mark on change.
- An exact comparison of service and legacy English catalogs finds 8 shared keys (data import
  only), so legacy relies on server-rendered text for these errors.

1. Ordinary `serverMessage(x) ?? t(...)` and `|| t(...)` calls: replace with `apiErrorText`;

2. Specialized formatters keep their own rules, then fall through to `apiErrorText`:
   `toRequisitionFailure` (403, conflict, idempotency, field map) and its initiate and action
   dialog consumers; `transfer-error.ts` (empty-file code, 413); CCE upload explanations;
   `use-print-report.ts` and `fetch-report.ts` (Blob decoding, cancellation, no raw 5xx);

   translation keys before falling back to `apiErrorText`.
3. Raw supplier lookup and geographic zone list errors use shared read fallbacks. Shipment entry
   and view retain permission explanations through the shared resolver.
4. The builder writes the final inventory (file, pattern, group) into this plan before
   migrating; deliberate exclusions are named there.

### Field mapping

- Users dialog: `username` and `email` keys mark their fields, stored as translation keys and
  cleared when the value changes. A refusal for a value edited while saving goes to the banner.
- Profile uses the same Notification email mappings and stale-value check as Users.
- Facility, Program, Product, Lot, Facility Type, Processing Schedule: existing duplicate-code
  predicates move to `fieldErrorFor` tables; behaviour unchanged.
- Requisition templates: map `numberOfPeriodsToAverage`, `programId` and `facilityTypeId`
  (to `facilityTypeIds`) where controls exist. Configure opens Settings for duplicate names.
  `columnsMap` errors and period refusals without an Average Consumption control show at section
  level. Requisition and template formatters accept legacy field messages with or without keys.

### Rules

- `401` handling, `waitForSession`, queue transport and `useSessionMutation` stay unchanged.
- Workflow-specific copy for uncertain writes and offline recovery stays ahead of the shared
  function.
- Registry folders (`src/components/form`, `form-dialog`, `data-table`) import nothing new.
- Toasts keep a Title Case title; the resolved text is the `description`.
- No backend change; no `lang` cookie or `openlmis.*` writes.

## UI/UX

No new screens. Titles and layout stay; descriptions change:

- Unreachable: the existing "Check your connection and try again." copy.
- Timeout on a save: says the change may have been saved and to reload first.
- Known key: our sentence in the page language, Arabic included.
- Duplicate username or email: shown under the field in Add/Edit User instead of the banner.

## Decisions

- Our catalog wins over server text for known keys; catalogs load at runtime, so deployments
  can add translations without a rebuild.
- Session-owned and cancelled failures show nothing at all, not an empty alert.
- Unknown keys with a server sentence show that sentence (legacy parity, user decision
  2026-11-23); only unkeyed or technical bodies fall back to the general message.
- Seed only the verified reachable, parameter-free keys (user decision 2026-11-23).
- No `Accept-Language` or `lang` cookie changes: services use the cookie resolver and the
  cookie is legacy's preference.

## Implementation Notes

- User edits, template configuration and BUQ final approval use the failing request method for
  timeout copy. An initial GET timeout gets read guidance.
- Expected domain failures retain their workflow copy without diagnostic logging. Batch approval
  shows synchronization guidance when local draft flushing fails.
- Spanish timeout copy uses formal address. The Unpack and Arabic shipment errors use the menu and
  order terminology from their respective catalogs.
- Reverse Stock Event line feedback keeps the two reason mappings and uses shared keyed text for
  other lines. The offline queue and persisted refusal formatters remain outside this migration.

- Template creation uses a fixed default of three periods. A period refusal appears in the
  create dialog’s form alert. The program is fixed on Configure, so its refusal appears with the
  program label in Settings.
- File transfer and printing pass a lazy translated fallback to the shared resolver. Print still
  uses Blob decoding and suppresses raw 5xx text. Setups that previously modeled service refusals
  with unkeyed messages now use keyed responses.
- The browser fixture exercised gateway, unkeyed 500, unknown keyed refusal, write timeout,
  duplicate username in English and Arabic, correction, and the session dialog on 401. The
  test.openlmis.org session had expired, so live duplicate username and facility code checks
  are pending. The focused Facility Editor test covers duplicate code placement.

- The copy audit covers direct calls and fallbacks forwarded by print, CSV, stock actions and
  requisition helpers. The remaining feature copy explains retained work or gives a concrete
  recovery step, such as checking exported values after an unconfirmed upload. Permission
  refusals and known outcomes use their own descriptions. Toast descriptions follow
  the matching alert tone in both appearances. The light error description darkens the
  destructive token for contrast over the tinted toast. Default descriptions stay muted.

- Problem details and Spring error envelopes use the general fallback, including partial
  envelopes. Reverse line diagnostics report each unknown key once with request metadata.
- An unexpected batch draft flush failure is reported before showing synchronization guidance.
  Expected conflicts, moved BUQ reports and ambiguous inventory submissions keep their workflow
  feedback without error logging. BUQ status checks use read-timeout guidance.
- Actions whose edits remain visible use the general fallback. Removing an offline requisition
  copy keeps the stale-copy guidance. Reverse Stock Event directs users to marked rows when a
  refusal matches a row and shows the resolved refusal or shared fallback in the dialog otherwise.

- Physical Inventory Save tracks whether the current counts have been confirmed on the device,
  including successful lot writes after a failed initial flush. While counts are page-only,
  usable translated or keyed server refusals for the draft or its lots include the counts notice.
  Add a full stop before that notice if the refusal lacks terminal punctuation. Generic failures
  and read timeouts keep the page open. While counts are page-only, lot POST timeouts during
  Save ask users to keep the page open and save again so previously created lots can be reused.
  Duplicate lots and missing trade items still have their own messages. Orphaned drafts report
  any earlier counts kept on device.
- Look up each pending new lot before creating it, including on the first Save. A targeted lookup
  is cheap and also covers a retry after a page reload without tracking POST attempts separately.
  Reference Data's LotController on master serves `GET /api/lots` with `tradeItemId` and `lotCode`.
  The repository searches the code case-insensitively by substring. Match the full code
  case-insensitively, like the server's uniqueness check, and require the same trade item and
  expiry when supplied. Reuse the matching ID and persist it like a newly created lot. If the
  search has no match, POST as before, preserving refusals for a conflicting expiry.
- Reverse Stock Event marks every row targeted by an error, with a shared fallback for malformed
  messages. When no row matches, the dialog shows the first usable refusal or the shared fallback.
