# FM-32: Forgot Password

https://openlmis.atlassian.net/browse/FM-32 · Parent: FM-30 General: auth, home, profile

## Scope

One PR for the whole signed-out password flow: this page, the reset page from the email
([FM-33](FM-33.md)) and the login page's "Forgot Password?" link ([FM-31](FM-31.md)). This
plan holds what they share: the card layout, the requests sent with no token, and the session
dialog's exemptions.

The reset email's link is built by the auth service. Pointing it at `/v2` needs
[openlmis-auth#31](https://github.com/OpenLMIS/openlmis-auth/pull/31), which adds
`PASSWORD_RESET_URL`; see [FM-33](FM-33.md).

Out of scope: account lockout and the rate limit's settings, both server configuration.

## Summary

A user who forgot their password types their email address and gets a link to choose a new
one. Legacy shows this as a modal over the login screen. The new page uses the same card as
Sign In, says the same thing whether or not the address is known, as legacy does, and keeps
the user on the page with a clear confirmation instead of a popup. Cancel and the
confirmation's button go back to Sign In.

## Legacy Today

`/#!/forgotPassword` (state `auth.forgotPassword`), opened from Sign In's "Forgot password?"
link. Screenshots in `.screenshots/FM-32/`.

- A modal in the login box: "Logistics Management Information System", the language
  switcher, "Forgot Password", "Please provide your email address and we will send you a
  reset password link on your registered email.", one required Email field, Cancel and
  Reset Password.
- Empty or malformed: "This field is required" / "The given email address is invalid", plus
  a "This form is invalid" alert.
- Submit shows a loading modal, then the alert "Password Reset Requested": "If an account
  with the provided email address is active, you will receive an email with instructions to
  reset your password." Close goes to Sign In. A known and an unknown address get the same
  alert.
- Any failed request shows "Failed to reset password. No user with given email address
  assigned was found.", which is wrong since an unknown address never fails.
- A signed-in user is sent home.
- Problems: the first click after a validation message is often lost, since the message
  disappears on blur and the button moves up; the email is not URL-encoded, so `+` breaks.

## Agent Brief

### API Map

| Step | Method and path | Params | Fields used | Right | Legacy ref |
| --- | --- | --- | --- | --- | --- |
| Request a reset | `POST /api/users/auth/forgotPassword` | `email` (query), no body, no `Authorization` | none, `200` empty | none (`permitAll`) | `openlmis-auth-ui forgot-password.factory.js:50-59` |

Errors: `429` `auth.error.tooManyRequests` (only with `PASSWORD_RESET_MAX_ATTEMPTS` set),
`500` `auth.error.sendNotification.failure`. Body `{ messageKey, message }`.

The lookup is a case-insensitive "contains" match on email (openlmis-notification
`UserContactDetailsRepositoryImpl`), first match wins. Server behaviour; we send exactly what
the user typed, trimmed.

### Data Flow

No loader and no query: one mutation. The result lives in the page, not the URL.

**Requests with no token.** The auth service is `permitAll` for both password endpoints, but
Spring's OAuth filter refuses any bearer token it is given, even there. A signed-in user, or
one whose session expired, would have the call refused and, today, wait for the session
dialog. So the client gets `anonymous: true`: the request interceptor attaches no token and
never waits for a session, and the response interceptor passes its `401` through.

### Risks and Edge Cases

- No SMTP on the local stack: the request still succeeds, the email is stored in
  `notification.notification_messages`.
- A signed-in user opening the page: allowed (Decisions).

## UI/UX

- **Port:** the login card with the switchers; one Email field; Cancel and Reset Password;
  the same wording for every address.
- **Improve:**
  - the confirmation replaces the form inside the card ("Check Your Email") with a Back To
    Sign In button, instead of a modal to dismiss;
  - field messages stay put until fixed, so no click is lost;
  - the button shows progress instead of a full-screen loading modal;
  - an error says what happened: no connection, too many attempts, or could not send;
  - the email is URL-encoded.
- **Drop:** legacy's "No user with given email address assigned was found", which is
  misleading, and the "This form is invalid" alert, since the field says it.

Buttons: Cancel at the start, Reset Password at the end, sharing the row. RTL via logical
classes only; the card is `max-w-sm` and fits a phone.

## Decisions

- **Email only.** `forgotPassword` takes only `email`; a username would just be matched
  against email addresses. The backlog's "email/username" is not possible without a backend
  change, and legacy has only Email too.
- **Open for anyone.** Legacy sends a signed-in user home. Here the page opens for anyone,
  since asking for a reset harms nothing, and it lets the session dialog link to it.
- **No token on these calls**, through a new `anonymous` request option, so a stale token
  never gets them refused.
