## Scope

The online bin card for one product and lot: header, newest-first transactions with running
balances, paging in the URL, Packs or Doses, Print, the exact facility and program right, and
the View action on Stock On Hand that opens it. The breadcrumbs learn to carry a list's search
back to it, which reaches the shared `AppBreadcrumbs`; the card cannot meet its criterion
without it, so it rides along.

Not in scope:

- Event detail ([FM-76](https://openlmis.atlassian.net/browse/FM-76)). Document Number,
  Reversing and Reversed By show plain text, with a `TODO` where each link to FM-76 goes
  (decided by the user on 2026-10-07).
- Offline. All of Stock ships online first; offline follows once every stock screen is online
  (user, 2026-10-07). The offline criterion stays open on this ticket until then.
- Backend changes. Everything below works against the released stockmanagement.

## Summary

The bin card is the history of one product, or one lot of it, at one facility and program:
every receipt, issue, adjustment and count, newest first, with the stock left after each.
Today legacy opens it from View on Stock On Hand, pages it 20 lines at a time and downloads
the whole card again on every page change. It shows a raw script error for a card that is
gone, and a page past the end shows an empty table with a broken pager.

The new card opens from the same View action, loads once and pages instantly, keeps its page
in the link, and takes the user back to Stock On Hand with their facility, program and filters.
It shows the same header and the same eleven columns in the same order. On a phone each
transaction becomes a card instead of a table that scrolls sideways. Print gives the same PDF
legacy does.

## Legacy Today

Route `openlmis.stockmanagement.stockCardSummaries.singleCard`, URL
`/#!/stockmanagement/stockCardSummaries/{stockCardId}?stockCardPage&stockCardSize`, a child
of Stock On Hand, so its URL carries every Stock On Hand param. Opened only from View on a lot
or No Lot Defined row. Needs `STOCK_CARDS_VIEW`. Screenshots in `.screenshots/FM-70/`
(`legacy-card-*-1440.png`, `-768`, `-390`, `legacy-card-rights-*.png`).

- **Breadcrumbs:** Home / Stock Management / Stock On Hand (back with all its params) / the
  product's full name.
- **Header:** "Bin Card for {program}" and Print. A grey box: "{product} - {display unit}",
  then Product Code, Pack Size, Facility, Program, Stock On Hand, and Lot Number and Expiry Date
  on a lot card only.
- **Table:** Date, Receive From, Issue To, Reason, Adjustment, Stock On Hand, Performed By,
  Signature, Document Number, Reversing, Reversed By. 20 a page, "Showing 20 item(s) out of
  117 total", Previous, page numbers, Next.
- **Packs or Doses:** above the table, shared with Stock On Hand. The header's stock on hand
  stays in doses either way.
- **Print:** opens the server PDF in a new tab, the token in its query string.
- **Problems:** every page change downloads the whole card again (0.85 s on a 117-line card);
  an expiry date one day early on screen (2019-01-30 shown as 29/01/2019); a missing card shows
  "Cannot read properties of undefined"; a page past the end breaks the pager; on a phone the
  table scrolls sideways (985 px in 374 px).
- **No access:** the server refuses, legacy lands on Home with "You are not authorized".

The server already resolves source and destination names, usernames, signatures, every balance
and the reversal document numbers, so no lookup request follows. Lines come all at once,
oldest first by occurred date, then processed date (not in the JSON), reason priority and id;
there is no paging or sort param and no `/api/v2/stockCards`.

The backend skips the right for a facility "linked" to the home facility (type `WS` in the
home's zone). The new UI checks the exact grant regardless, which is the ticket's criterion.

### Data flow

- Route `src/routes/(protected)/_protected.stock-management.stock-on-hand_.$stockCardId.tsx`,
  so the path `/stock-management/stock-on-hand/{id}` sits below the Stock On Hand nav entry and
  inherits its crumbs, with `staticData.crumbKey: 'stock-card.crumb'`.
- The loader blocks, since this is a permission check and a must-404 record: await
  `requirePermissions(queryClient, RIGHTS.stockCardsView)`, then fetch the card fresh on route
  entry with `fetchQuery` and `staleTime: 0`, using `ensureQueryData` while staying on the
  route for paging. Disable route preloading. Then `hasProgramGrant(grants, card.facility.id, card.program.id)` or throw
  `ForbiddenError`. Read the user before the await and stop if it changed, as Stock On Hand's
  loader does. `pendingComponent` is the page skeleton; `errorComponent` renders `ErrorFallback`
  with a Not Found for `isNotFound` (404 and 400) and No Access through `isForbidden`.
- Query: `stockCardOptions(id)` in `src/features/stock-card/api/queries.ts`, key
  `queryKeys.stockCards.detail(id)` (new scope in `key-factory.ts`).
- URL: the card's own paging is `cardPage` and `cardSize` (legacy's `stockCardPage` and
  `stockCardSize`), with the app's default size and options, mapped onto `tableSearchState`. The
  lines are paged in the browser like Roles, clamping a page past the end. A page change never
  refetches.
- Return state: as legacy, the card's URL also carries Stock On Hand's whole search (`mode`,
  `facilityId`, `programId`, `productCode`, `productName`, `lotCode`, `includeInactive`, `page`,
  `size`), validated by `stockOnHandSearchSchema`. View links with the current search plus the
  card id, so a reload or a shared link returns with them too. A card opened without them
  returns to a bare Stock On Hand, as legacy's does.

### Rules (legacy refs in `.screenshots/FM-70/research-b/findings.md`)

1. Lines: reverse the server's order; never re-sort.
2. Physical inventory with `stockAdjustments`: one row per adjustment, in reverse order, each a
   copy of its line with that reason and quantity. The first keeps the line's balance; each next
   one takes the previous balance minus the previous row's signed quantity (DEBIT negative, all
   else positive). No summary row remains. Legacy's fixture: ending 35 with DEBIT 10, DEBIT 5,
   CREDIT 20 gives CREDIT 20 / 35, DEBIT 5 / 15, DEBIT 10 / 20, then the older line's 30.
   Done before paging.
3. Reason: with free text "{name}: {freeText}"; a `PHYSICAL_INVENTORY` category shows
   "Physical Inventory"; else the name; none shows blank.
4. Receive From and Issue To: blank without an object; "{name}" or "{name}: {freeText}".
5. Adjustment shows `quantity`, unsigned, as legacy does.
6. Document Number shows only when `eventOrigin` is set. Reversing shows when
   `reversedEventId` is set, Reversed By when `cancellationEventId` is set, each its document
   number, or "No Number" when blank (legacy's "View" link has nothing to open yet). Each cell
   gets a one-line `TODO` naming the FM-76 link.
7. Product line: "{fullProductName} - {displayUnit}", or the name alone without a unit.
8. Lot Number and Expiry Date only on a lot card. Dates through `formatDateValue` on the
   date-only value, which avoids legacy's day-early expiry.
9. Quantities through `cardQuantity` with the stored Packs or Doses choice; the header's stock
   on hand follows it too (see Decisions).
10. Print: `showInDoses` from the choice, `lang` from the page's language; authenticated
    request, then open the PDF, as Stock On Hand's Print does, with its user-change guards.

## Implementation Adjustment

- Exclude `.screenshots/**` from Vitest while keeping its default exclusions. The saved legacy research includes AngularJS Jasmine specs, which the full test command otherwise discovers and runs without the legacy test harness. Research files remain intact; the app suite runs unchanged.

- Fetch the card fresh on route entry. Review reproduced an old balance and transaction history when reopening a cached card after another transaction. Paging continues to use the already loaded card and makes no request.

- Stock Card Print opens the authenticated PDF in a separate tab through `openReport`, matching legacy and the browser criteria. The shared button accepts `reportAction`; Stock On Hand keeps its existing download behavior through `downloadFile`.
