# FM-112: Spike: Rewrite Reports Or Port As-Is

https://openlmis.atlassian.net/browse/FM-112 · Parent: FM-111 Reports

## Scope

Technical investigation and a proposed direction for Reports, before FM-113, FM-114 and
FM-115 implementation. No code, Jira edits, feature branch or commits are included.
See [FM-111](FM-111.md) for the detailed inventory, API map, source references and UX.

The user does not know the missing country requirements and explicitly asked us to
explore without them. Country gaps are therefore unknown, not empty and not invented.
This proposal does not claim all of this spike's acceptance criteria are complete.

## Summary

Recommend bringing the existing reports into the new UI while retaining their current
definitions, calculations and dashboard platform. This gives users the same reports
through the new app's forms, navigation and error handling. It also allows specific
legacy interface defects to be corrected without changing report calculations.

A report rewrite would need evidence of what countries require, agreed replacement
reports and comparison of their results. None of that evidence is available yet.
Technical investigation can proceed, but it cannot justify selecting replacement
calculations or promising that the current reports meet country needs.

## Legacy Today

Live test research on 14 November 2026 found one Default Category with Stock On Hand,
Facility Assignment Configuration Errors, Periodic Stock On Hand Summary, Sample
Requisition Report, Timeliness Report and Reporting Rate Report. Parameters use dates,
lookup selections, a boolean selection and an optional nonnegative integer. Generic
text/static-choice branches exist in source but are absent from current metadata.
Timeliness has a Program to Period dependency. Output choices are PDF, CSV, XLS, XLSX
and HTML; successful output generation was not exercised during read-only research.

Seven enabled URL-only Superset records exist administratively, but no dashboard is
available to the demo user. Opening a configured dashboard fails in legacy's available
report lookup; the configured Superset host also fails DNS resolution. Working
dashboard rendering, cookie/OAuth behavior and guest-token embedding remain unverified.

The source additionally supports an Embedded UUID mode and POWERBI URLs. Its newer
analytics assets contain nine Superset dashboards backed by CDC/ClickHouse/dbt. Those
assets are a separate reporting pipeline, not proof of deployed replacements for the
six live Jasper reports or of equivalent calculations.

| Risk | Metadata drift, large lookups, existing backend defects, dashboard configuration | All existing risks plus calculation discrepancies and incomplete functional coverage |

No defensible time estimate follows from the current evidence. Work depends on the
metadata patterns, lookup contracts, formats and configured dashboard modes, not merely
the number of React pages.

## Agent Brief

For the complete API map, data flow, files, rights, rules, translations and test
boundaries, use [FM-111's Agent Brief](FM-111.md#agent-brief). Existing app forms,
Workspace, query boundaries, unscoped permissions and authenticated binary delivery
make a UI port feasible. There is no existing Reports feature or Superset host to reuse.

The API inventory distinguishes viewer discovery from management. Do not use the
administrative dashboard detail API for viewer routes, and do not equate REPORTS_VIEW
with access to every dashboard. Report calculations and exports remain server-side.

### Known Technical Gaps

These are not country requirements:

- Legacy can lose completeness in large paged option lists and mishandle empty pages.
- Dependency changes can retain invalid old selections or accept late lookup responses.
- Timeliness metadata requests level-3 districts; legacy sends level 2 because it ignores
  the supplied JSON. Recommend honoring metadata, explicitly subject to approval.
- Legacy concatenates unencoded values, Date objects and undefined optional parameters
  into report URLs and puts the access token in the output URL. Use encoded, date-only,
  authenticated requests in the new UI.
- Empty categories, duplicate category names and absent category records are fragile.
- Reviewed master dashboard discovery pages candidate rights before paging the filtered
  results. A client page loop alone is not proven to return the complete set.
- Reviewed master guest-token issuance checks REPORTS_VIEW and UUID registration but
  omits the dashboard-specific right and enabled status. Treat this as separate backend
  authorization work before guest embedding acceptance, not something link hiding fixes.
- Superset reachability, real viewer grants, configured SSO, token renewal and Arabic
  chart behavior need a working environment. The legacy allowlist is en/fr/pt.
- Actual output validity, filenames/MIME and standalone HTML assets remain untested.
  The reviewed XLS exporter advertises the XLSX MIME type; verify actual file bytes.

Country report gaps: **unknown**. Existing source/dashboard assets must not be labelled
country-approved replacements without supporting requirements and result validation.

## UI/UX

Port category grouping and visible report capabilities. Improve the screens using the
app's existing category cards, form fields, accessible validation and in-place errors.
Keep report-specific fields in their metadata order with their exact submitted values.
Do not replace configured report names with invented translations or hardcode forms
for only the six observed reports.

Recommend retaining all five formats. PDF opens; CSV/XLS/XLSX download; HTML downloads
instead of running inside the app. No current reporting capability is proposed for
removal. HTML delivery and the Timeliness correction are named differences for approval.

## Decisions

Recorded user direction: continue exploration with country requirements unknown.

The user approved starting View Reports (FM-113) on 14 November 2026 with the current
report services retained. Its concrete implementation plan is [FM-113](FM-113.md).
This means preserving backend definitions, not copying Angular defects. Keep the
FM-113/114/115 scope; handle any future country report redesign as separate evidenced work.

All five formats, the Timeliness metadata correction and HTML file delivery remain
recommendations for approval when starting FM-114. A working dashboard environment is an FM-115 acceptance
dependency, not a reason to invent behavior or block all Jasper work.

## Open Questions

- A working authorized dashboard environment is required to finish FM-115's plan and
  acceptance. Backend discovery and token authorization defects need separate scope.
