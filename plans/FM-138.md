# FM-138: Valid Sources

https://openlmis.atlassian.net/browse/FM-138 · Parent: FM-124 Admin: Facilities & Supply Chain

Built together with Valid Destinations in one PR, from one shared screen. The research, the
API map, the UI/UX calls and the steps are in [FM-137](FM-137.md); this plan holds only what
differs.

## Scope

Administration > Valid Sources: the same list, filter, bulk delete and add dialog as Valid
Destinations, over `/api/validSources`, guarded by `STOCK_SOURCES_MANAGE`. Receive's
"Received From" offers these.

## Summary

A valid source says "facilities of this type, in this program, may receive stock from this
place", a facility or an organization. Legacy's screen is a copy of Valid Destinations with
the word changed, and so are its problems. The new screen is the Valid Destinations screen
given the sources wording, endpoints and right.

## Acceptance Criteria

| AC | How it is met | How it is checked |
| --- | --- | --- |
| Only users with the right to manage stock sources can open the screen and see the menu item | Loader awaits `requireRight(STOCK_SOURCES_MANAGE)`; `NAV_RIGHTS` and `NAV_GROUPS` entries | `nav-access.test.ts`; browser as `divo1` |
| The screen uses the same component as Valid Destinations | Its own `valid-sources` feature renders the shared screen in `src/components/valid-assignments/` | Code review |
| The table, filter, bulk delete and add modal behave the same as on Valid Destinations | Same component and tests | FM-137's tests and browser checks, run on both routes |
| Labels say "source", not "destination" | `{kind}` select in every message that names the record | Browser in English and Arabic |
| Adding and deleting change the valid sources, not the destinations | The `valid-sources` feature calls `/validSources` in its `api.ts` | `api.test.ts`; browser on the local backend |
| Uses the same API calls as the legacy screen | See FM-137's API map | `api.test.ts` |
| All text goes through i18n, the screen works in RTL (Arabic), and there are no console errors | Shared keys | Browser in Arabic at desktop and phone width |

## Differences From Valid Destinations

| | Destinations | Sources |
| --- | --- | --- |
| Route | `/administration/valid-destinations` | `/administration/valid-sources` |
| Endpoint | `/api/validDestinations` | `/api/validSources` |
| Right | `STOCK_DESTINATIONS_MANAGE` | `STOCK_SOURCES_MANAGE` |
| Stock screen | Issue, "Issue To" | Receive, "Received From" |
| Local data | 50, 2 organization rows (CHW) | 29, 2 organization rows (NGO) |

Legacy's sources list also works out a `geoLevelId` per row that it never shows; nothing to
port.
