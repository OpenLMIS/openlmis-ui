## Scope

Rework the Offline Events page shipped in PR #92 into the two legacy screens, shown as tabs on
that page: Pending Events and Synchronization Errors, plus the existing synced history as a
third tab. Port legacy columns, details, order, filters and actions; keep confirmations and
live updates.

Not in scope:

- No new queue, retry path, uploader or Dexie schema version. Recovery transactions in
  `stock-event-sync.ts` stay as they are.
- No change to downloads or the program picker. Offline Issue and Receive are already on
  master (#106, #109); reuse their editor and Details patterns. Only the refusal Review
  destination changes in the editor.
- No backend change.

## Summary

When a user submits stock events without a connection, the events wait on the device and are
sent when the connection returns. Legacy has two screens for this, both reached only from a
link in the header: **Pending offline events** (shown while offline) lists what is waiting,
with a Remove button; **Offline synchronization errors** (shown while online) lists what the
server refused, with the server's message and Dismiss and Retry buttons. Legacy has real
problems here: Remove and Dismiss delete at once with no question, an event is lost if the
connection drops while it is being sent, the list does not update after a successful sync,
the errors screen does not open offline, and Retry of an event with lots fails again on
today's server.

The new UI already has an Offline Events page (PR #92) that keeps everything safely on the
device and handles recovery. This work reshapes it to match the two legacy screens: one page
with three tabs, **Pending Events**, **Synchronization Errors** and **Synced**. Each tab has the
legacy columns (Pending Event, Facility, Program, Details, Date, plus Error Message on errors), the legacy order
and the legacy filters (event type and From/To dates), kept in the address. Pending events
leave the list the moment they sync, a retried error leaves the errors list at once and goes
back in line to send, and every removal asks first. Everything works offline, in Arabic and
on a phone.

`src/events-synchronization-errors/`), stockmanagement-ui `stock-event/stock-event.run.js`,
referencedata-ui `openlmis-offline-events-indicator/`. Screenshots: `.screenshots/FM-168/`
and `.screenshots/FM-169/` (desktop, phone, Arabic).

- **Entry:** no menu entry. Header shows "Pending offline events (N)" only while offline and
  "Offline synchronization errors (N)" in red only while online, each only when N > 0. No
  access right on either route; both look up programs with `STOCK_ADJUST` only for names.
  Lists are per user.
- **Pending offline events** `#!/offlineEvents?page&size&eventType&startDate&endDate`,
  offline-capable. Filter popover with Pending Event (Issue, Receive, Adjustment; no All, no
  clear), From, To, applied on Search; dates inclusive against the first line's occurred date.
  Columns **Pending event | Details | Date | Actions**. Pending event is the type plus
  "(Stock Management)". Details has one paragraph per line, parts joined by "; ": Facility
  (Adjustment only, always the home facility); Program; **Product** (name only); Lot or
  "No lots"; **Reason:** / **Issue to:** / **Received from:**; **Quantity:** n. Date is the
  first line's occurred date. Queue order, 10 per page, client paging. Action: red Remove, no
  confirmation, no message. Empty and no-match both say "No offline events". The list does not
  change after a successful sync until reload; a failed send reloads the current page.
- **Offline synchronization errors** `#!/synchronizationErrors?page&size`, not offline-capable,
  no filters. Columns **Pending event | Details | Error message | Date | Actions**. Error
  message is red: "We couldn't perform this event. " plus the server message, or "No details
  available, try to resend the event." Actions: red Dismiss then blue Retry, both visible, no
  confirmation. Retry success removes the row with no message. A refused Retry shows a modal
  with the server message and moves the row to the end; a dropped connection re-adds it
  silently with "No details available". Empty: "No synchronization errors".
- **Sync:** oldest first, one at a time, on reconnect and after login. Each 4xx or 5xx goes to
  errors with one alert modal ("Some work you have done offline could not be synchronized with
  the server", plus the message and a pointer to the header link), and later events continue.
  A dropped connection loses the event and stops the run.
- **Defects:** event removed before sending and lost on a dropped connection; 401 and logout
  wipe both lists (FM-167); rows addressed by list index; Retry posts the decorated display
  object, so lot lines are refused (`lot.idAndCodeExclusive`); Issue to / Received from blank
  for all but the first program; program names blank without `STOCK_ADJUST`; dates can show a
  day off from the deployment's date; Arabic pager shows raw placeholders; 5xx HTML bodies show
  as raw text.

## Agent Brief

### API Map

The page reads only the device database. Retry and sync use the existing uploader unchanged.

| Step | Method and path | Params | Fields used | Right | Legacy ref |
| --- | --- | --- | --- | --- | --- |

### Data Flow

- Reader: `useOfflineEvents()` (Dexie `liveQuery`) stays the only source. Dismissed refusals are
  kept in the database with their history but returned by no tab, as today.
- One route: `/offline-events` gains `tab: 'errors' | 'synced'` (absent means Pending), as
  Requisition Templates does with `?tab=`. The header, toolbar and filters never remount.
  Switching tabs keeps `eventType`, `startDate`, `endDate` and drops `page`, `sort`, `dir` and
  `event`, adding a history entry.
- The old `status` param stays readable in the schema only to map links: `refused` and
  `uncertain` open `tab=errors`, `accepted` opens `tab=synced`, others Pending; the mapped URL
  replaces the old one.
- Pure module `src/features/stock-events/lib/offline-event-tabs.ts`:
  - `tabOf(event)`: `pending` for `queued` and `sending` (including Send Again rows that keep
    `attemptId`); `errors` for `uncertain` and for `refused` (unresolved or copied, which keeps
    `resolvedAt`); `synced` for `accepted`.
  - `pendingState(event, blocked)`: `sending`, `held` (own `pauseReason`, access-changed and
    draft-changed kept distinct), `waiting` (its facility/program is in `blocked`), else `queued`.
  - `errorState(event)`: `refused`, `stock-changed`, `uncertain`, `copied`.
  - Default orders: Pending by original `queuedAt` ascending; Errors by `error.failedAt`
    ascending; Synced by `receipt.acceptedAt` descending. A single sort-value map handles these
    and occurred dates, with `sequence` ascending breaking ties. Retried rows keep their original
    queue time and sequence. The default sort configuration also supplies each time label.
    Clearing a table header sort returns to the active tab default, including Pending queue order;
    each default column's first click reverses its default direction.
- `stock-event-sync.ts`: extract the uploader's barrier into an exported pure
  `blockedScopes(rows)` (every scope with any queue row, earlier or later, that is not `queued`
  or has a `pauseReason`) and use it in the uploader loop unchanged in behaviour. Filter queue
  statuses inside the helper so refusal and receipt projections never block a scope. A Pending row
  can be waiting on an uncertain row shown on Errors; say so in its reason. `pauseReason` is
  only rewritten while the uploader runs, so offline it shows the last known reason.
- Sidebar and avatar counts keep `isPendingDeviceEvent` (everything not yet on the server:
  Pending plus unresolved Errors); tabs show their own counts.
- Dialog: `?event=<localEventId>` as today. A row that moves tab while its dialog is open keeps
  its last snapshot, as today.
- Column visibility: one stored key per tab (`device-events.columns.<tab>`), with the
  preference state keyed by tab (`useStoredState` reads storage only on mount), so each tab
  restores its own choices and Reset Columns affects only the active tab.
- Selection: keep finding `?event` in the complete reader output before tab and filter, so an
  open dialog shows the event's current status even after it moves tab.
- Counts: tab counts ignore filters; copied refusals count on Errors but not in the sidebar
  (`isPendingDeviceEvent` excludes resolved). An explicit `tab` wins over a legacy `status`.
- Paging: each tab clamps past-end pages after live removals, as today.
- Rights and offline: unchanged loader, `OFFLINE_EVENT_RIGHTS` and shell capability.
  No `crumbKey`: tabs are not pages.

### Rules

- Only never-attempted queued rows offer Remove; sending, uncertain and Send Again rows never
  do (`canRemoveDeviceEvent`). Remove keeps a changed linked draft.
- Retry only for unresolved refusals, never uncertain or copied; no confirmation (AGENTS.md);
  disabled without the kind grant. It calls `retryRefusedEvent`, nothing else.
- Dismiss confirms, flags `dismissedAt` and keeps history; never offered on uncertain rows.
  Copied refusals keep View Details and Dismiss. Synced Remove confirms and keeps the minimal
  duplicate receipt.
- Uncertain rows keep It Was Recorded and Send Again in the details dialog with the duplicate
  warning.
- Error Message for `refused` and `stock-changed` renders only through `refusalMessage`;
  `uncertain` shows translated copy and never renders `message`, `lastFailure` or `response`.
  No raw JSON, status codes or keys anywhere.
- Details shows only display snapshots stored with the event; no server or lookup reads.
- Date is never hidden by default or by width.

## Decisions

- One plan and one PR for both tickets: they share the page, reader and actions.
- One route with `?tab=` rather than child routes: no remount, filters carry over, existing
  links keep working.
- No schema version: all needed fields exist (`sequence`, `error.failedAt`,
  `receipt.acceptedAt`, `pauseReason`, `category`).
- Legacy labels kept (Pending Event, Remove, Dismiss, Retry), in Title Case.
- Retry keeps the legacy no-confirmation rule and the shared uploader; removals confirm.
