# FM-143: Lots

https://openlmis.atlassian.net/browse/FM-143 · Parent: FM-139 Admin: products & programs
(epic research: [FM-62](FM-62.md), Tier 1 #10)

## Scope

Administration > Lots: a server-paged list of lots with a product filter and an expiry date
range, and an Edit Lot dialog for the lot code and its two dates, behind `LOTS_MANAGE`.

Shared pieces this needs, built in the same PR because the screen cannot ship without them:

- Server search in the data-table's combobox filter, for the Product filter.
- A `DatePicker` taken out of `DateField`, so a toolbar can pick a date outside a form.
- Product lookups in `reference-data` (search, by ids, by trade items), since `lots` may not
  import `products`. Products' kit tab moves onto them, so each exists once.

Not in scope: adding lots (legacy has no Add Lot; lots are created on Receive, physical
inventory and the product import), an "expired" mark, and sorting (the server cannot sort).

## Summary

A lot is a batch of a product with its own code and expiry date, such as "LC2017A, expires
30 January 2019". Stock screens pick lots when stock is received, issued or counted. This
screen lets an administrator find lots and correct a lot's code or dates.

Legacy shows the lots 10 at a time with a filter for product and expiry dates, and an Edit
button that opens a small form. It is slow: every time the list opens, changes page, filters,
or a lot is saved or the form is closed, it downloads every product in the system, about
10,000 of them (10 MB), to fill the product dropdown and name the 10 lots on screen. That
takes 2 to 10 seconds each time, while the lots themselves arrive in a few hundredths of a
second. Its dates also read `2019-01-30` in the table but `30/01/2019` in the form.

The new screen keeps the same columns, filters, paging and form, and asks the server only
for what is on screen: the page of lots, and the products of those lots. The Product filter
searches as you type instead of listing every product. Dates read the same everywhere, in
the user's language. Saving no longer asks "Do you want to edit this lot?" first, shows the
server's reason when a save is refused (for example a lot code already used), and refreshes
just the list rather than the whole page.

## Legacy Today

Measured on the local instance (referencedata-ui master, 17 lots, all expired, 10,233
products of which 22 have a trade item). Screenshots: `.screenshots/FM-143/legacy-*.png`.

**List** (`/#!/administration/lots?orderableId&expirationDateFrom&expirationDateTo&page&size`,
Administration > Lots, `LOTS_MANAGE`):

- Columns: Product Code, Product Name, Lot Code, Expiry date, Manufacture Date, Actions (Edit
  button). No sorting; the server ignores `sort` and applies no order at all.
- 10 per page, "Showing 10 item(s) out of 17 total", no page size control (`size` in the URL
  still works). Empty: "No lots found."
- Filter button with a count ("Filter (3)") opens a popover: Earliest Expiry Date, Latest
  Expiry Date (datepickers, dd/mm/yyyy), Product (a 10,234-option select2 of every product,
  unsorted, most without lots), then Cancel and Search. Each filter works alone; both dates
  include their own day.
- Rows are named in the browser: each lot's `tradeItemId` is matched against
  `identifiers.tradeItem` of every product; no match shows a hardcoded English "No product".

| Step | Lots | Every product | Table ready |
| --- | --- | --- | --- |
| Open | 0.02 s | 2.2 s | 2.2 to 3.4 s |
| Page 2 | 0.02 s | 5.7 to 6.2 s | 7.3 s |
| Filter | 0.4 s | 4.1 to 4.9 s | 5.3 to 6.0 s |
| Close Edit (save or cancel) | | 3.8 to 5.9 s | about 6 s |

Defects: filtering keeps the current page, so page 2 with 6 matches shows an empty table;
From after To silently finds nothing; a page past the end shows broken page links; `page=abc`
gives a server 500.

**Edit** (`/lots/edit/:lotId`, modal, `LOTS_MANAGE`):

- Reads `GET /api/lots/{id}` on every opening. Title `Edit Lot: "LC2017A"` follows the input,
  and reads `Edit Lot: "${lot}"` once the code is cleared.
- Lot Code (required), Expiry Date, Manufacture Date (datepickers with Clear, both optional).
  No other check: expiry before manufacture and a future manufacture date both pass.
- Save asks "Do you want to edit this lot?", sends `PUT /api/lots/{id}` with the whole lot,
  shows "Lot saved successfully" and reloads the list with every product. A refused save
  shows only "Failed to save lot", hiding the server's reason. Cancel also reloads
  everything. Escape and the backdrop do not close it. An unknown id alerts "Lot not found".

## Agent Brief

### API map

| Step | Method and path | Params | Fields used | Right | Legacy ref |
| --- | --- | --- | --- | --- | --- |
| List | `GET /api/lots` | `page` (0-based), `size`, `tradeItemIdIgnored=true`, `orderableId`, `expirationDateFrom`, `expirationDateTo` (ISO, inclusive) | `content[].id, lotCode, tradeItemId, expirationDate, manufactureDate`, `totalElements` | none (signed in) | `admin-lot-list.routes.js:29-43` |
| Name the rows | `GET /api/orderables` | `tradeItemId` (repeated, the page's distinct ids), `page`, `size=100` | `id, productCode, fullProductName, identifiers.tradeItem, meta.versionNumber` | none | replaces the unpaged `orderableService.search()` (`:71-84`) |
| Product filter options | `GET /api/orderables` | `q`, `page=0`, `size=20`, `sort=fullProductName,asc` | `id, productCode, fullProductName` | none | replaces the 10,234-option select (`lot-list.html:14-17`) |
| Name the picked product (from a link) | `GET /api/orderables` | `id` | same | none | |
| Open Edit | `GET /api/lots/{id}` | | the whole lot | none | `admin-lot-edit.routes.js:25-44` |
| Save | `PUT /api/lots/{id}` | body: the fetched lot with `lotCode`, `expirationDate`, `manufactureDate` replaced (`null` when empty) | | `LOTS_MANAGE` | `admin-lot-edit.controller.js:97-112` |

`PUT` replaces the lot from the body alone (`Lot.newLot`): a missing `active` becomes false and
`tradeItemId` is required, so the body is always the full fetched record.

Server refusals on save (`LotValidatorImpl`, `Lot.setLotCode`), each a 400 with a `messageKey`:
`referenceData.error.lot.lotCode.required`, `.lotCode.mustBeUnique` (per trade item, case
insensitive), `.lotCode.tooLong` (over 20), `.lotCode.invalidFormat` (GS1 AI(10) characters
only), `.tradeItem.required`. A missing lot is a 404.

### Data flow

- Route `/(protected)/_protected.administration.lots.tsx`. The loader awaits
  `requireRight(queryClient, RIGHTS.lotsManage)` and prefetches the list, deferred.
- URL: `page`, `size` (from `tableSearchSchema(...).omit({ sort, dir })`), `product` (GUID),
  `expiryFrom`, `expiryTo` (`yyyy-MM-dd`, anything else drops out), `lot` (GUID, the open
  dialog). Filter changes `replace` and go back to page 1; paging pushes.
- `lotsListOptions(query)` under `queryKeys.lots.list(query)`: one query whose `queryFn`
  fetches the page of lots, then names them, and returns rows with their product, so the
  table suspends once and shows one skeleton. A page with no lots skips the second call.
- Naming: keep only orderables whose `identifiers.tradeItem` (case insensitive) is one of
  the requested ids, and the highest `meta.versionNumber` per orderable, since the server
  returns every version. If none matches, stop: an unknown `tradeItemId` makes the server
  return every product (FM-184). Otherwise follow further pages until `totalElements` is
  read, which only happens when products carry many versions. A lot with no product shows
  "No Product".
- Product filter: `orderablesSearchOptions({ q })`, debounced 300 ms, `keepPreviousData`, as
  the kit picker. A product picked from a link is named by `orderablesByIdsOptions([id])`;
  `withPicked` covers the wait.
- Dialog: `lotDetailOptions(id, opening)` with the opening number (the save sends the whole
  record), not prefetched. Its description names the product through
  `orderablesByTradeItemsOptions([tradeItemId])`. Save invalidates the lots list queries, not
  the detail.

### Server-side work

| Legacy in the browser | New UI |
| --- | --- |
| Downloads every product (10 MB) on each load to name 10 rows | Asks for the products of the page's trade items only |
| Fills the Product filter with every product | Searches the server as you type, 20 at a time |
| Paging, filtering | Already on the server; unchanged |
| Sorting | None in legacy and none possible: `LotRepositoryImpl.search` has no `ORDER BY` and ignores `sort` |

The missing order also means pages are not guaranteed stable:
[FM-187](https://openlmis.atlassian.net/browse/FM-187). The UI does not work around it.

### Risks and edge cases

- Products with many versions on one trade item: the naming follows pages rather than
  trusting one.
- A lot whose trade item no product points to (not in the demo data): "No Product", never a
  wrong product.
- Unstable page order on the server (above).
- The demo data has only 17 lots, all expired, over 9 products: enough for paging (2 pages)
  and filters, not for large data.

  - Columns drop by the room the page has: Lot Code and the menu stay; Product Name,
    Expiry Date, Manufacture Date and Product Code go in that order from last to first, and
    come back from the View menu.
- **Drop**: the Filter button and its count (the filters are always visible), legacy's
  title echoing the typed code, and its "Edit Lot" submit label: the button says Save, as every dialog here.
- **RTL and phone**: codes `dir="ltr"`, names `dir="auto"`; toolbar filters wrap on a phone,
  the table keeps Lot Code and the menu; checked in Arabic at both widths.

## Decisions

- **Same calls, narrowed**: the lots calls are legacy's own; the products call is paged and
  narrowed, which the speed AC asks for.
- **Inline filters, not a popover**: matches the rest of the new app (user, 2026-10-05).
- **No sorting**: the server ignores `sort`, as on legacy. The missing order is
  [FM-187](https://openlmis.atlassian.net/browse/FM-187) under FM-177 (user, 2026-10-05);
  once it ships, the list can sort.
- **No date order check** in the dialog, as legacy and the server; the alternative is an
  "Expiry Date can't be before Manufacture Date" message.
- **No expired mark**: legacy has none; every demo lot is expired, so it would be easy to add
  later if asked.
