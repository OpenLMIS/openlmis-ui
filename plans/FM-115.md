## Scope

Native dashboard viewer at `/reports/dashboards/$dashboardId` for the dashboard reports that
View Reports lists: discovery and access, the source-supported modes (Superset embedded,
Superset link, other link such as POWERBI), frame lifecycle, error states and runtime
configuration. A separate Test-only fixture proposal below covers synthetic dashboard setup and
verification; operational changes need approval of the concrete apply sequence. Catalog
dashboard links open the native viewer by default.

Not included: dashboard or category administration (FM-162/163), Home page embedding, Superset
charts or datasets outside the synthetic fixture, data pipelines, row-level security design,
backend authorization fixes, country or production configuration, and any new Jira ticket.
The Test fixture is separate from the UI PR. The approved FM-114 implementation and its
out-of-scope list stay as they are; this story changes the dashboard half of the catalog.

Branch: `feat/fm-115-dashboard-viewer` from master `cc19bd0e`. Nothing is
stacked any more; PR #145 and #146 are merged.

The UI is built and tested locally first, using the regular Vite backend proxy (S4). No
frontend deployment is required for those checks. **The story cannot be signed off** from
fixtures alone: real charts, guest-token renewal and same-user legacy comparison still need
a configured embedded dashboard and OpenLMIS report/right in UAT. The current go-ahead
authorizes those additive fixture changes, with baseline capture and rollback. It does not
authorize altering the seven existing report records or deploying/restarting services.

## Summary

In legacy, choosing a dashboard report opens it inside the page. Embedded Superset dashboards
open without another sign-in. Superset link dashboards first ask the user to type their
OpenLMIS password so legacy can sign them in to Superset, then show the dashboard in a frame.
Any other link (for example Power BI) is shown in a frame. A missing or broken dashboard shows
a generic "Internal application error" box.

The new viewer opens the same dashboards inside the app, with the normal title and breadcrumbs.
Embedded dashboards still need no extra sign-in. Superset link dashboards come from the older
reporting stack: as in legacy, the viewer checks Superset's own session and asks for the
current user's password only when Superset is not signed in yet, then shows the frame. Other
links are shown in a frame with an Open In New Tab link. Each failure (not available to you, not set up on
this server, reporting service down, dashboard did not load) has its own translated message
and a way to recover.

At planning time, Test had no Superset and UAT had no dashboard connected to OpenLMIS. The
approved local-first approach now uses an additive UAT fixture with the local UI; the completed
acceptance is recorded below. A separate Test-only synthetic fixture remains an alternative.

### Route, Data And Cache

- Route `src/routes/(protected)/_protected.reports_.dashboards.$dashboardId.tsx`,
  `staticData.crumbKey: 'reports.dashboard.crumb'` (Dashboard). The name is the title; crumbs
  stay translation keys (D5).
- Loader follows the FM-114 generate route: capture scope, `await requireRight(REPORTS_VIEW)`,
  `assertSessionScope`, then fetch a fresh `availableDashboardsOptions(userId)` before opening.
  Disable intent preloading and block route revalidation so a revisit cannot render a cached
  dashboard while checking current availability. An absent id shows Not Available. Discovery
  failure uses `ErrorFallback` with retry.
- Widen `DashboardReport` in `lib/types.ts` with `type`, `url`, `embeddedUuid`.
- Guest tokens never enter the Query cache, storage, logs or error reports.
- Not an offline route. Identity changes remount routed content; host cleanup runs.

### Mode Resolution (pure, `lib/dashboard-mode.ts`)

Input: record, runtime `supersetUrl`, app origin.

1. `type === 'SUPERSET'` and `embeddedUuid`: `embedded` if the UUID matches a UUID pattern and
   `supersetUrl` is valid; invalid UUID gives `unsupported`; missing or invalid `supersetUrl`
   gives `not-configured`.
2. `type === 'SUPERSET'` without UUID, valid `url`: `superset-sign-in` with `standalone=true`
   merged through `URLSearchParams` and the validated `supersetUrl`; missing or invalid
   `supersetUrl` gives `not-configured`.
3. Other type with valid `url`: `link` unchanged.
4. Otherwise `unsupported`.

Validate Superset bases separately from dashboard links. Both must be absolute HTTP(S),
contain no username/password and have an origin different from the app origin. A Superset
base must have no query or fragment; normalize its trailing slashes while preserving a
deployment path prefix before the SDK concatenates `/embedded/<uuid>`. A dashboard link may
retain its query and fragment, with `standalone=true` merged normally. Never accept a
same-origin frame with script and same-origin access to app storage.

### Embedded Host (`components/superset-embed.tsx`)

SDK contract pinned from the `0.4.0` package:

- `embedDashboard` fetches the token and mounts the frame in parallel and resolves only after
  both the token and the frame's `load` event. An error page also fires `load`. There is no
  frame timeout.
- Each token fetch is wrapped in `guestTokenFetchTimeoutMs` (default 30 s). Refresh runs at the
  token's expiry minus 5 s (at least 10 s after the last); failures retry every 10 s until
  `unmount()`. Initial failure empties the mount point and rejects.
- `unmount()` stops refresh and empties the mount point. `switchboard.get()` calls such as
  `getScrollSize()` have no timeout.
- The frame always gets `allow-same-origin allow-scripts allow-presentation allow-downloads
  allow-forms allow-popups` and `allow="fullscreen; clipboard-write"`. `id` is concatenated
  unencoded into the frame URL, so the UUID check above matters.

Host design:

- Exact pin `@superset-ui/embedded-sdk@0.4.0`, loaded by dynamic `import()` (code-split). No
  runtime script download, no `new Function`.
- Pass `iframeTitle` = dashboard name, legacy `dashboardUiConfig`, no `referrerPolicy` (leave
  the browser default so Superset's referrer check passes), no sandbox or allow extras.
- Each opening owns a fresh keyed mount node with no React children. The SDK only ever touches
  that node, so a late resolve, reject or unmount from an older opening cannot clear a newer
  frame. State updates check that the opening is still current.
- The shared `waitForSession` gets an optional request signal. Abort rejects with Axios
  cancellation and removes both the login-store and online subscriptions, including when
  already aborted. Both Axios interceptor wait sites pass the request signal. Existing
  callers without a signal keep their current behavior. This small shared prerequisite
  avoids abandoned re-login waits; an outer promise race alone does not unsubscribe them.
- Token callback: SDK 0.4.0 serializes token fetches. Each request uses the shared client with
  `sentFor` identity and its own `AbortController`, aborted at 25 s (below the SDK's 30 s), on
  dispose and on `SessionEndedError`. `SessionEndedError` also disposes the opening, so the SDK never retries for the next
  user. Intentional page/identity disposal is silent; a 25-second deadline becomes a visible,
  recoverable timeout. Same-user re-login retries from a fresh opening. Map errors inside the
  token callback during both initialization and renewal: the SDK swallows renewal errors
  before retrying, so its initial promise catch cannot report them.
- Connected, not "ready": after the SDK resolves, call `getScrollSize()` with a 20 s host
  limit. Superset answers it before checking the token, so a reply proves only that the frame
  and channel work, not that the token, charts or data are valid. Show the frame; keep a
  "Dashboard not showing? Try Again" control reachable below it at all times. If
  `embedDashboard` has not settled within 45 s, or the handshake fails or times out, show Did
  Not Load. Both limits are host constants to tune on the fixture.
- Error mapping: 403 refused; 404 not registered; 500 with
  `messageKey === 'report.error.superset.notConfigured'` not set up on this server; other 5xx
  or network error reporting service unavailable; offline shared offline failure.
- Frame sizing: the mount node sits in a plain wrapper that uses `*:size-full *:border-0`.
- Cleanup, either timeout and app hide all dispose the opening: abort, clear timers, unmount any
  current or late handle against its own node. Check disposal after the dynamic import and
  before invoking the SDK. Try Again creates a new opening. Focus recovery runs only while
  the app page is visible.
- App hide (`usePageHidden()`, true behind the protected layout's offline notice): dispose
  immediately; on return start exactly one new opening. An ordinary browser tab switch keeps
  the opening so renewal continues.
- App-driven Superset theme switching is outside this change; no extra preference or flag.

### Older Superset Sign-In (`components/superset-sign-in.tsx`)

- One opening checks the Superset session; signed in goes straight to the link frame.
- Otherwise a native `FormDialog` shows "Signed in as <user>" and a password field. Cancel or
  Escape returns to View Reports, as legacy's Cancel does.
- Submit runs the API map's password check, authorize, session recheck, approval when needed
  and a final recheck; only a confirmed Superset session opens the frame. A wrong password is
  cleared and never reaches authorize; other failures keep the dialog with a translated message.
- The password lives only in the form; no query, mutation, URL, storage or log. Superset calls
  are anonymous to the app, credentialed and excluded from app connectivity. Every request is
  aborted with the opening (hide, unmount, Try Again) and results for another user are ignored.
- Basic headers encode UTF-8; form bodies use `URLSearchParams` with an explicit form content
  type.

### Link Frame (`components/dashboard-frame.tsx`)

Shared by signed-in Superset links and other types:

- `<iframe>` with `title` = dashboard name, `sandbox="allow-scripts allow-same-origin allow-forms
  allow-popups allow-downloads allow-presentation"` (the SDK's set), `allow="fullscreen;
  clipboard-write"`, default referrer policy.
- Connecting state until `load`, then the frame. A 45 s limit without `load` shows Did Not Load.
  `load` never means success: an error or login page also fires it, and a cross-origin frame
  gives no reliable content signal. So the Open In New Tab link (`target="_blank"`,
  `rel="noopener noreferrer"`) and Try Again stay visible below the frame at all times.
- App hide disposes/removes the frame and timer, invalidates its load callback, and suppresses
  focus changes. Returning creates exactly one fresh frame with a new 45-second deadline;
  ordinary browser-tab backgrounding does not restart it. Each Try Again is also a new opening.

### Runtime Configuration

- `supersetUrl` in `src/lib/runtime-config.ts`, read through `getSupersetUrl()`, from
  `SUPERSET_URL` (the name legacy and the report service already use) via
  `docker/config.json.template`, the `entrypoint.sh` export and `envsubst` list, and
  `docker-compose.yml`. Empty by default. Never compiled in.
- `/v2` sends no CSP or referrer header today, so no frame-src change. Superset must list the
  app origin in its frame ancestors and the dashboard's allowed domains; a working legacy
  setup on the same origin already covers that.

### Backend Gaps (Recorded, Separate)

From `openlmis-report@6b33ad63`; not fixed here; no ticket created by this plan.

1. The guest-token endpoint does not check the record's right or `enabled`. Any REPORTS_VIEW
   holder can get a token for any registered embedded UUID. The viewer only asks for UUIDs in
   the user's available list; that narrows casual use but does not close the gap.
2. Tokens carry `rls: []`, and the stack disables Superset's modified-query check for guests.
   Whether that matters depends on each country's data scoping, which is unknown.
3. Home discovery skips REPORTS_VIEW but the token endpoint requires it.

A backend fix (check `enabled` and the record's right, Home exception) is sketched in research B
§6, for the backend team on their own branch and review. The UI does not depend on it. The Test
fixture is limited to synthetic data so the gap exposes nothing real there; the Test check of
"Reports user without the dashboard right cannot get a token" is expected to fail until the
backend is fixed, and is recorded as such, not as a pass. Turning embedded dashboards on for a
country is a separate rollout decision (Open Question 3).

### Tests (Written First, Small)

All SDK, token and frame behaviour in unit tests is stubbed and is never evidence of real
embedding.

1. Mode resolution: each mode; invalid UUID; missing or invalid `supersetUrl`; `javascript:`,
   `data:`, relative, credential-bearing and same-origin URLs rejected; Superset base query
   and fragment rejected, path prefixes/trailing slashes normalized; dashboard link query and
   fragment retained; `standalone=true` merged into a URL that already has a query.
2. Embedded lifecycle with a mocked SDK: a newer opening survives a late resolve or reject of
   an older one; unmount before resolve unmounts the late handle; `SessionEndedError` disposes
   and stops further token calls; one token request in flight; no handshake reply gives Did
   Not Load; app hide disposes and return opens exactly once; `notConfigured` `messageKey`
   maps to Not Set Up.
3. Viewer: available dashboards open without deployment switches; users without REPORTS_VIEW
   are denied before discovery, and ids missing from the available list show Not Available
   without a token request. Catalog links always use the native route.
4. Link frame: no `load` within the limit gives Did Not Load; recovery stays visible after
   `load`; app hide while connecting disposes the old frame and returning starts one new
   deadline, with late old loads ignored.
5. Shared cancellation: abort before transport while the session is expired, and after a 401,
   settles promptly, releases both subscriptions and never replays after re-login. Use the
   existing Axios/session boundary and a stub adapter; a timeout race alone must fail these checks.

Reuse existing guard, runtime-config and feature-flag coverage; no tests of the SDK itself.

## Decisions

- D1 Bundled SDK `0.4.0`, exact pin, host-owned lifecycle as above. Recommended.
- D2 SUPERSET link-only dashboards (product call): superseded. The user later confirmed that
  both the older OAuth stack and the new embedded stack stay supported, so the viewer ports the
  older stack's sign-in (see Older Superset Sign-In). The original options are kept for history.
  - Option C (originally recommended): sandboxed frame plus Open In New Tab, no `oauth-init` check, no
    `lang/change`, no password. Matches the current stack, where those endpoints are 404 and an
    authorization check would wrongly report "unavailable". Limit: on a deployment still running
    the retired OAuth add-on, users who are not already signed in to Superset see Superset's own
    login (in the frame or the new tab) instead of legacy's password prompt.
  - Option A (earlier draft): check `oauth-init`, link to Superset's own sign-in, Check Again.
    Only useful on the retired stack; unverifiable anywhere known.
  - Option B: port the password prompt. Not recommended: the app would collect and forward
    passwords.
- D3 POWERBI and other types as sandboxed frames; unverified.
- D4 Dashboard reports use the native viewer by default, per the later user decision.
  REPORTS_VIEW and the available-dashboard list govern access; Superset configuration
  determines how an embedded report is displayed.
- D5 Fixed Dashboard breadcrumb, name in the title.
- D6 The user selected local-first testing with UAT underneath (S4), without deploying the
  frontend to UAT. Earlier S1-S3 are alternatives, not the default or approved server changes.

### Viewport and Recovery Actions

Dashboard pages use a viewport-height Workspace so the frame fills the remaining space below
the header and breadcrumbs. The frame area keeps a 20rem minimum and short pages scroll to fit it
and the recovery row. The recovery row keeps its own height, including when translated actions
wrap. If retry removes a focused dashboard control, focus returns to the replacement retry button
or the failure heading. Any control the user focuses while waiting keeps focus. Report failure
alerts place a small destructive retry button at the inline end. Narrow alerts place actions
below the text so translated labels leave room for the message.
