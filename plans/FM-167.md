# [FM-167]: Offline audit of views

[FM-167] · Parent: [FM-164] Offline support

Which screens must work offline in the new UI, what each does offline, and what it needs on
the device. Read from the legacy UI code on 2026-10-13 (every route flagged `isOffline: true`);
the network-off check on UAT that the ticket asks for is still to do.

## Summary

Legacy runs Adjustments, Issue and Receive fully offline: events are kept on the device and
sent when the connection returns. Stock on Hand and Stock Card can be viewed offline, and a
Physical Inventory draft already on the device can be counted, but not saved or submitted.
Kit Unpack and Transaction History are online only. Everything a screen needs offline is
downloaded at sign-in.

## Stock screens

- **Adjustments, Issue, Receive (program list and editor)**: Edit and submit; the button reads
  Submit Offline, the event is queued, no print offer. Needs on the device: rights, home facility,
  programs, products and
  lots, stock summaries, valid reasons, sources and destinations.
- **Stock on Hand**: View only, with a banner that the data may be out of date and a link to pending
  events. Needs on the device: stock summaries per program with `STOCK_CARDS_VIEW`, facilities.
- **Stock Card**: View only, and only cards opened online before. Needs on the device: each opened
  card.
- **Physical Inventory list**: Only programs whose draft is on the device; no new draft offline.
  Needs on the device: drafts on the device.
- **Physical Inventory draft**: Count and edit locally; Save, Delete, Submit and Deactivate
  unavailable. Needs on the device: the draft and its products, lots and reasons.
- **Pending offline events**: List, filter by type and dates, Remove. Needs on the device: the event
  queue.
- **Synchronization errors**: Online only in legacy; Dismiss and Retry. Needs on the device: the
  error list.
- **Kit Unpack, Transaction History, Reverse**: Not offline; menu entries disabled. Needs on the
  device: none.

Outside stock, requisition view, search, approval and batch approval, the order create table
and the CCE inventory item dialog are offline in legacy. They join this list when those modules
are migrated.

## Legacy behaviour worth keeping or fixing

- **Sync:** queued events are sent oldest first, one at a time, when the connection returns
  and after sign-in. A refused event moves to the synchronization errors list and the rest
  carry on. The header shows pending events while offline and sync errors while online.
- **Defect:** legacy removes an event from the queue before sending it, so a crash mid-send
  loses it. The new UI keeps it until the server answers, and never retries an unknown outcome
  blindly.
- **New lots on Receive:** a typed new lot fails offline, since legacy creates it before
  submitting; only a scanned new lot is sent inside the event.
- **Print** is not disabled offline in legacy and simply fails; the new UI disables it.
- **Remove** on pending events has no confirmation in legacy; [FM-168] asks for one.

## Decisions (2026-10-13)

- **Physical Inventory follows legacy desktop:** the draft on the device opens and can be
  counted offline; Save, Delete and Submit are unavailable offline. No new draft offline.
- **Download at sign-in, without blocking it.** After sign-in, offline data downloads in the
  background while the user works. The bottom of the sidebar shows a spinner with "Fetching
  the necessary data for offline" until it finishes, then reports failures without blocking.
- **Typed new lots on Receive work offline**, a small improvement on legacy: the new lot is
  queued inside the event, as scanned ones are.
