# [FM-167]: Offline audit of views

[FM-167] · Parent: [FM-164] Offline support

Which screens must work offline in the new UI, what each does offline, and what it needs on
the device. Legacy route/code review started on 2026-10-13 and was completed with a network-off
check on test.openlmis.org on 2026-10-27. An offline route flag permits entry; it does not prove
that its data or actions work offline.

## Summary

Legacy Adjustments, Issue and Receive can edit and queue events offline when the required data
is cached. Stock On Hand reads cached summaries; Stock Card reads histories saved when viewed
online. Physical Inventory drafts are saved when opened online and can be counted locally.
Legacy cannot open Unpack offline, although an already-open editor still queues an event.
Transaction History and Synchronization Errors cannot open offline. Sign-in prepares shared
reference data and summaries in the background, without waiting for every summary download;
it does not download Stock Card histories or Physical Inventory drafts.

## Stock screens

- **Adjustments, Issue, Receive (program list and editor)**: Edit and submit; the button reads
  Submit Offline, the event is queued, no print offer. Needs on the device: rights, home facility,
  programs, products and lots, stock summaries, valid reasons, sources and destinations.
  Legacy editors initially failed with a cache error in the runtime check, then opened after
  revisiting them online. The new UI checks complete downloads before allowing entry.
- **Stock On Hand**: View cached summaries, with a stale-data banner and pending-events link.
  Needs summaries per program with `STOCK_CARDS_VIEW`, products, lots and facilities.
- **Stock Card**: View only cards opened online before; each saved card includes its history.
  Legacy retains old history after newer summaries. The new UI hides history older than the
  stock download and asks for a connection to refresh it.
- **Physical Inventory list**: Desktop shows only programs whose draft is on the device;
  no new draft offline. Needs saved drafts.
- **Physical Inventory draft**: Count, reasons, VVM and Add Products use the saved draft,
  products, lots and reasons. Legacy Save, Delete, Submit and Deactivate remain enabled and
  attempt server work that the offline interceptor refuses. The new UI requires a connection
  for those actions; Submit checks counts first and retains them when connection is required.
- **Pending offline events**: List, filter by type and first-line date, Remove without a
  confirmation. Needs the local event queue. The new UI confirms removal and filters dates
  against every line.
- **Synchronization errors**: Online only in legacy; Dismiss and Retry use the saved error list.
  The new UI keeps recovery available offline and sends only when connected.
- **Kit Unpack, Transaction History, Reverse**: Legacy cannot open these offline. An already-open
  legacy Unpack editor can queue; the new UI deliberately keeps Unpack online-only.

The initial editor error was: "The data required to access this screen is not cached. We will
fetch it once you are online again." Visiting Pending online had removed the reasons' cache
scope. Revisit the editor online without visiting Pending again and it opens offline.

Reload and browser restart offline both failed to load the shell with
`ERR_INTERNET_DISCONNECTED`. This does not establish a product-only failure: request routing
disabled HTTP cache, service workers were blocked, and Chrome lacks legacy ApplicationCache.
No legacy browser with ApplicationCache was tested. Per-screen data survival after offline
reload/restart therefore remains unverified. The local adjustment did survive shutdown, then
was lost during the deliberately interrupted reconnect sync. No successful server sync,
PI Save/Delete/Submit, lot creation, print or destructive queue removal was tested; PI counts
were observed, not edited. Shell/login and the separate mobile routes above have code-review
coverage only, not individual network-off checks.

## Legacy behaviour worth keeping or fixing

- **Sync:** queued events are sent oldest first, one at a time, on reconnect and after sign-in.
  A server-refused event goes to synchronization errors and the rest carry on. The header
  shows pending events offline and errors online.
- **Defect, reproduced:** legacy removes an event before POST; interrupting sync left both the
  queue and error store empty. `stock-event.run.js:79-93` also reads a missing error body.
  The new UI retains durable work until acceptance is recorded, pauses unknown outcomes for
  review and never blindly resends them.
- **Defect, reproduced:** visiting Pending online calls unscoped `getReasons()` and overwrites
  cached program/facility-type fields, breaking offline editors and PI until refreshed online
  (`events.service.js:300`, `stock-reasons.factory.js:157-197`). The new UI's complete scoped
  downloads stay separate from Pending event display and retain a previous complete download.
- **Defect, code-confirmed:** logout and handled 401 clear localStorage except locale, losing
  queued events, errors and PI drafts; PouchDB products/cards/summaries survive. The warning
  mentions only needing a connection to sign in. The new UI warns about device work, retains
  it on logout and pauses on expiry without deleting it. Evidence:
  `local-storage.service.js:225-230`,
  `logout.controller.js:61`, `access-token.interceptor.js:87`.
- **Defect, code-confirmed:** localStorage write failure is ignored on offline event submit,
  so storage-full submission can be reported as success without an event
  (`local-storage.service.js:70`, `stock-event-cache.service.js:94`). The new UI confirms
  Event Queued only after durable storage succeeds; a failed save keeps edits and offers Retry.
- **Defect, code-confirmed:** desktop PI Submit deletes the device draft on an online server
  error with a body (`physical-inventory-draft.controller.js:594-597`). Offline, null error data
  throws before removal, so the draft survives; it is incorrect to claim offline Submit deletes
  it. The new UI retains counts after failure and requires a connection for submission.
- **Flagged but incomplete:** mobile PI has local `offline-` draft creation, but its parent
  unconditionally requests reasons and fails on cold offline entry. Offline completion only
  retains local counts, with no reconnect uploader. The new UI supports already-opened desktop
  drafts, with no new draft or queued PI Submit offline.
- **New lots on Receive:** typed new lots fail offline because legacy creates them first;
  scanned new lots can travel inside the event. The mobile Add Lot Code flag permits the form
  but still calls the lot API. The new UI queues both typed and scanned new lots inside events.
- **Print:** legacy leaves it enabled but printing needs the server; runtime did not invoke it.
  The new UI disables printing offline.
- **Remove:** legacy pending removal has no confirmation; [FM-168] covers the new UI confirmation.

## Decisions (2026-10-13)

- **Physical Inventory:** count an already-downloaded draft offline; no new draft offline.
  Save, Delete, Submit and Deactivate require a connection in the new UI. Disabling these
  controls is deliberate; the deployed legacy desktop leaves them enabled and requests fail.
- **Download at sign-in, without blocking it.** Data downloads in the background while the
  user works. The sidebar shows progress, then failures without blocking sign-in.
- **Typed new lots on Receive work offline**, a small improvement on legacy: queue the lot
  inside the event, as scanned lots are.

## Decisions (2026-10-27)

- **Scope:** legacy parity plus quick wins only; fix confirmed defects without adding features.
- **Unpack stays online-only in the new UI.** Legacy cannot open Unpack offline; its already-open
  queue path is acknowledged but not added to the new UI.
- **No queued Physical Inventory Submit and no reconnect reminder.** Legacy provides neither.
  Counts remain on the device; the user reconnects and explicitly saves/submits.
- **No Ready label.** Offline picker rows that can open are simply enabled, matching legacy's
  lack of per-program state. Not Downloaded keeps its visible reason before entry.

### Offline criteria for stories

Proposed acceptance-criterion wording for the six stock stories under [FM-62]. Jira has not
been edited. [FM-168] and [FM-169] already contain their offline criteria.

- **Adjustments:** Given a complete home-facility/program download and adjustment rights,
  when offline, users can open Adjustments, add downloaded products/lots, enter quantities,
  reasons and dates, retain edits on this device and confirm Submit Offline. The signed event
  is durably queued once and sent on reconnect; unavailable downloads explain why entry is
  disabled. A failed local save retains edits and offers Retry.
- **Issue:** Given a complete home-facility/program download and issue rights, when offline,
  users can open Issue, choose downloaded stock and valid destinations, enter quantities,
  comments and dates, retain edits on this device and confirm Submit Offline. The signed event
  is durably queued once and sent on reconnect; unavailable downloads explain why entry is
  disabled. Offline submission offers no print action.
- **Receive:** Given complete home-stock and Receive catalog downloads and receive rights,
  when offline, users can open Receive, choose approved products, lots and valid sources,
  enter quantities, comments and dates, and add typed or scanned new lots. Submit Offline
  durably queues the signed event once, including new lots, and sends it on reconnect.
  Unavailable downloads explain why entry is disabled; offline submission offers no print action.
- **Stock On Hand:** Given a complete home-facility/program stock download and stock-card
  viewing rights, when offline, users can open Stock On Hand and filter, page and change units
  over downloaded balances. Show the download time and offline notice; never add queued event
  quantities to downloaded balances. Missing data explains that it is not downloaded.
- **Stock Card:** Given a home-facility stock card previously viewed online and viewing rights,
  when offline, users can read its saved history and change units. Show its download time;
  absent history or history older than the current stock download asks for a connection,
  without returning a server 404. Printing requires a connection.
- **Physical Inventory:** Given a draft opened online with its references saved on this device,
  when offline, users can continue that draft, enter counts, VVM and reasons, add downloaded
  products and retain edits across reopening. New drafts, Save, Delete, Submit and Deactivate
  require a connection. Counts survive failed saves; submission is explicit after reconnect,
  with no queued submission or reconnect reminder.

## New UI audit (2026-10-27)

Downloads, editors/queue, Offline Events/session, SOH/Stock Card/PI and shell/service worker were
checked across Chromium, Chrome and Firefox, English/Arabic, 1440/390px; most focused cases used
Chromium fixtures.
Browser counts: 27 + 19 download reruns, 58 + 20 editor reruns, 23 events/session checks, 20 views
plus reruns and 20 shell cases; offline suite 86 passed after one load timeout passed its 9/9 rerun.
This PR fixes stale removal confirmations, leave-dialog wording and the filter value lost on
quick close. External leaves retain the last committed device draft after a failed save.

Quick wins shipped in this PR:

- Read feature identity through shared session accessors and refresh event reasons with the
  offline access query policy while preserving management invalidation.
- Keep the Physical Inventory reasons dialog to one scroll area, with the shared responsive
  table/card layout, and place its toolbar controls consistently.
- Group Physical Inventory lines once when finding the first invalid row, and skip page-error
  scans before validation. Reuse one date formatter per line-filter pass and cache display
  formatters by locale/options.
- Fetch Receive catalog lots and scanning trade items in parallel, retaining session checks.
- Share wrapping cells across Stock Card, Transaction History and Stock On Hand while keeping
  Transaction Details' original single-line table and wrapping card values.
- Reuse device-event item selection for the Offline Events details count and share attempt
  matching for recovery/removal confirmations without redundant snapshot capture.
- Strengthen Physical Inventory reason-save, multi-lot stock total, foreground preparation,
  delivery invalidation and access-identity coverage; remove redundant test cases.

## Open

- Legacy offline reload/restart in a browser supporting its original app-cache mechanism was
  not established by the guarded headless run; do not infer it from route flags.
- Separate legacy mobile and unavailable requisition/order/CCE modules still need runtime
  checks if migrated; no writes were exercised for those modules in this audit.
