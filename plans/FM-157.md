## Scope

Migrate the standalone Administration Data Import page, its four import types, ZIP picker,
instructions, upload, feedback and per-file summary. Add the small shared file field this
page needs. This supplies the upload subset of FM-23, not its CSV/PDF download requirements.
Backend import changes, Data Export and other upload pages remain outside this story.

## Summary

Administrators choose Products, Facilities, Population or Users, then upload a ZIP of CSV
files. Keep legacy's instructions, warning about replacing user roles, and summary of
successful and failed entries. Use the existing page design, accept ZIP files only, prevent
duplicate uploads and show failures on the page. A partly successful import must show its
failed entries rather than only a success message.

## Legacy Today

Route: `/#!/administration/dataImport`, opened from Administration, gated by `DATA_IMPORT`.

| Order | Type | Value | Instructions |
|---|---|---|---|
| 1 | Products | `Product` | `orderable.csv`, `programOrderable.csv`, `tradeItem.csv` |
| 2 | Facilities | `Facility` | `facility.csv`, `supportedProgram.csv` |
| 3 | Population | `GeographicZone` | ZIP containing `geographicZone.csv` |
| 4 | Users | `User` | `user.csv`, `roleAssignment.csv` |

The file control stays disabled until Type is chosen. Picking a file shows its name and a
remove icon. Changing Type clears the file. Users instructions additionally warn that
imported role assignments replace existing roles. There is no pre-import confirmation.

Import shows a loading overlay and uploads the archive. A response with results opens
Import Summary: one tab per CSV, total/successful/failed counts and any failed-entry details.
Error rows can include Username and Role. Legacy displays a success toast even with failed
entries. Closing the summary reloads the app. File and Type reset after every upload attempt,
including errors. Preserve these reset rules; replacing the page reload with cache refresh
keeps the imported data up to date without restarting the app.

Known gaps to fix:

- The picker advertises RAR and 7z, although the backend accepts only ZIP.
- The button does not explicitly disable during upload.
- Failure handling logs an error; the observed global error dialog also displayed a raw key.
- At phone width the type control overflows horizontally.

### API Map

| Step | Method And Path | Params | Fields Used | Right | Legacy Ref |
|---|---|---|---|---|---|
| Existing route permission check | `GET /api/users/{id}/permissionStrings` | Signed-in user ID; existing session query | Right names | Signed-in session; page requires `DATA_IMPORT` | `admin-data-import.routes.js:31` |
| Import the archive | `POST /api/importData` | Multipart body with exactly one `file` part; no Type, query params or configuration request | `results`, per-file counts and errors | General admin `DATA_IMPORT` | `admin-data-import.service.js:34-57` |

Use the shared Axios client, which provides token and session handling. Override its JSON
content type for FormData using the existing branding upload pattern. Let Axios/browser
generate the multipart boundary. Import does not require additional product, facility or
user-management rights.

HTTP 200 body:

```ts
type ImportResult = {
  fileName: string;
  totalEntriesCount: number;
  successfulEntriesCount: number;
  failedEntriesCount: number;
  errors: { errors: string[]; username?: string; role?: string }[];
};
type ImportResponse = { results: ImportResult[] };
```

HTTP 400 validation and HTTP 403 permission errors use `{ messageKey, message }`.
`message` is server-localized; use `serverMessage()` when it is usable, otherwise a translated
fallback. Proxy HTML, timeouts and errors without a response must not render raw bodies.
Known row-error keys get local translations; unfamiliar plain error text remains visible as
text, never interpreted as markup. Unknown key-shaped errors get a readable fallback.

### Data Flow

- The route blocks only for `requireRight(queryClient, RIGHTS.dataImport)`. The type catalog
  and instructions are static; there is no page-data loader or query to prefetch.
- Keep Type, `File | null`, request feedback and summary in memory. No browser storage,
  URL serialization of files, background uploads or offline queue.
- Changing Type clears the file and feedback. Removing the file resets the native input,
  restores focus and lets the same file be selected again.
- Form submission awaits a mutation, with required/valid values and pending guards.
  Disable Type, file selection/removal and Import during upload. One click submits directly.
- Reset Type and file when the request settles, as legacy does; retain the result or error
  independently. Keep the summary available until dismissed. An empty results array must
  not crash the dialog; an unexpected/missing result payload must not claim full success.
- Invalidate cached queries after a settled upload attempt using the Query client. The
  archive can contain any supported CSV regardless of selected Type, and failed requests
  can still leave committed data. Broad invalidation is appropriate for this rare bulk
  operation and replaces legacy's full reload. Do not clear the session or query cache.
- Refresh the current user's rights through that invalidation. The route passes current
  import access to the feature so losing the right blocks another upload; the completed
  summary may still be read. A cache refresh failure must not turn a successful upload into
  an upload error or cause another POST.
- Mutation retries stay off. Never pass upload resubmission into `useOfflineFailure`, which
  retries on reconnect. Network failure or timeout can have an unknown result; show a short
  explanation to check the affected data before repeating the import. A server error can
  also follow partial changes, so do not promise rollback.
- Use the discard guard while an unsent selection would be lost. Resetting the settled
  upload clears that draft. Keep navigation guarded during the pending request as well.

### Server Work And Rules

Type chooses instructions only. The backend selects handlers by CSV filename, in this order:
`facility.csv`, `supportedProgram.csv`, `orderable.csv`, `programOrderable.csv`,
`tradeItem.csv`, `geographicZone.csv`, `user.csv`, `roleAssignment.csv`.

Enforce required Type and file, and the current backend's lowercase `.zip` extension.
Do not reject a legitimate ZIP because the browser gives it an empty or alternative MIME
type. The backend validates archive contents and exact root-level CSV filenames. Do not
unzip, validate rows or guess the chosen Type from archive contents in the browser.

Source config limits the compressed upload to 1,024,000 bytes, but this may differ by
deployment and there is no limit-discovery call. Do not hardcode that value in the field;
show a server rejection. The existing client timeout is 60 seconds; measure the upload
workflow before changing that timeout locally, without changing the shared client.

Import is not atomic: independently committed batches can survive a later error. A 200 can
contain failed user/role rows. Role import clears existing assignments before rebuilding
them, so keep the Users warning visible. No CSV download, scanning, pagination, search or
server-side filtering needs adding to this page.

## UI/UX

- **Port:** the four options/order, required values, type-specific CSV guidance, Users
  warning, file removal, type-change reset, settled-request reset and per-file summary.
- **Improve:** ZIP-only validation and readable in-page errors required by the AC; loading
  and duplicate-submit protection; phone/RTL layout; accurate partial-import feedback.
- **Drop:** the full page reload after summary dismissal; query invalidation provides the
  same refreshed data. Drop the RAR/7z options because the endpoint rejects them.

Use `Workspace width="narrow"` with the standard header and a compact form. Keep each input
in its own constrained column, stack on narrow content, and put instructions after Type.
Use an Alert for the existing role-replacement warning. `WorkspaceFooter width="narrow"`
holds the large Import button at the end through a plain layout wrapper. Do not add a
Cancel/reset action absent from legacy; the file field already provides Remove.

The result dialog is titled Import Summary and has one wrapping tab per file. Show all
three counts with labels, and Username/Role/Error details where present. Long names and
messages wrap within the dialog; no page overflow at phone width. Use Close instead of
Confirm for dismissing a result, since it submits nothing. Restore focus to the Type field
after dismissal. Isolate filenames and imported names, use logical spacing and direction-
aware primitives, and announce upload/result state accessibly.

## Decisions

- Preserve the complete legacy import capability, including its summary and instructions.
- Follow the ticket's ZIP-only rule and the backend's extension contract.
- Keep legacy's field reset behavior, including failures. The new in-page error persists.
- Submit directly with no new confirmation; preserve the existing user-role warning.
- Add only the reusable file-selection subset needed here; FM-23 stays open for downloads.
- Use existing APIs and broad cache invalidation, with no automatic retry or offline queue.
