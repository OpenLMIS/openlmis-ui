# FM-63: Program Pickers For Stock Events

https://openlmis.atlassian.net/browse/FM-63 · Parent: [FM-62](https://openlmis.atlassian.net/browse/FM-62) Stock management

## Scope

The shared program picker page, delivered with its first consumer, Adjustments
([FM-66](https://openlmis.atlassian.net/browse/FM-66), planned in `plans/FM-66.md`), in the same
PR: the shared component, the Adjustments picker page and its menu entry. A picker merged alone
would link to an editor route that does not exist yet, which `tsc` refuses, so the picker's
commits come first in the PR and can be reviewed on their own.

Not in this PR: the Issue, Receive, Kit Unpack and Physical Inventory pages. Each is added with its
own ticket (FM-64, FM-65, FM-67, FM-68), using the same component. Physical Inventory's Status
column and Start or Continue button come with FM-68. FM-63 stays In Progress until all five pages
work.

## Summary

Every stock action (Issue, Receive, Adjustments, Kit Unpack, Physical Inventory) starts on a small
page titled with the action and the user's home facility, such as "Adjustments for Comfort Health
Clinic". It lists, one row each, the programs the user may act on there, with a button that opens
the action for that program.

Legacy has five near-identical copies of this page. The new UI builds it once and reuses it. The
page looks and behaves as legacy, with two fixes: a user with no home facility gets a clear
message instead of a broken page, and the table stays readable on a phone.

## Legacy Today

Screenshots: `.screenshots/FM-63/` (desktop, tablet, phone, and each restricted user).

- Routes `/#!/stockmanagement/adjustment` (and `issue`, `receive`, `unpack`, `physicalInventory`).
  Heading "Adjustments for Comfort Health Clinic"; a two-column table, Program and Action, with a
  "Make Adjustments" button per row ("Make Issue", "Make Receive", "Unpack Kits"). Physical
  Inventory has Program, Status ("Not yet started", "Draft") and Actions (Start, Continue).
- Rights: `STOCK_ADJUST` for the four event pages, `STOCK_INVENTORIES_EDIT` for Physical
  Inventory. Without them the menu hides the entries, and a direct URL returns to Home with
  "You are not authorized to perform this action."
- Program list (desktop): `homeFacility.supportedPrograms ∩ GET /users/{id}/programs ∩` exact
  grant at the home facility (`stock-program-util/program-util.service.js:49-80`). The phone pages
  list every supported program without the rights check, a legacy bug we do not copy.
- No programs: the caption "There are no programs for this facility. Please contact the Admin."
  No home facility: legacy's factory rejects and the page breaks; it is unreachable for the test
  users because the rights guard redirects first.
- Ready in about 1 s, from legacy's cached user, facility and program reads.

## Agent Brief

### API Map

| Step | Method and path | Params | Fields used | Right | Legacy ref |
|---|---|---|---|---|---|
| Rights | `GET /api/users/{id}/permissionStrings` | Signed-in user | `STOCK_ADJUST\|facility\|program` | Self | `openlmis-permissions/permission.service.js:386` |
| User record | `GET /api/users/{id}` | Signed-in user | `homeFacilityId` | Self | `current-user.service.js:53` |
| Home facility | `GET /api/facilities/{id}` | `homeFacilityId` | `name`, `code`, `supportedPrograms[].id` | Authenticated | `current-user-home-facility.service.js:53` |
| User programs | `GET /api/users/{id}/programs` | Signed-in user | `id`, `code`, `name` | Self | `program.service.js:165` |

### Data Flow

- Loader: `requirePermissions(queryClient, RIGHTS.stockAdjust)` blocks (permission check). It
  then prefetches `userRecordOptions`, `userProgramsOptions` and, once the record resolves, the
  home facility's `facilityOptions`, all deferred.
- Body: a `QueryBoundary` around the table, with a table skeleton and `LoadError`.
- Nothing in the URL; the page has no state.

### Files

- `src/components/stock-program-picker/stock-program-picker.tsx`: presentational. Props: the
  rows (`{ id, label }`), the action label and a link builder, plus `children`-free empty states.
  It imports no auth and no feature, so routes compose it.
- `src/lib/stock-programs.ts` + test: `homeStockPrograms({ homeFacility, programs, grants })`,
  the legacy desktop intersection, sorted by label as `facility-program-selection.ts` does.
- `src/features/auth/lib/rights.ts`: add `stockAdjust: 'STOCK_ADJUST'` (and
  `stockInventoriesEdit` once FM-68 needs it).
- `src/routes/(protected)/_protected.stock-management.adjustments.tsx`: the picker route.
- `src/lib/config.ts`: the Adjustments entry points at the route.
- `src/components/nav-access.ts`: `NAV_RIGHTS` entry for Adjustments, `STOCK_ADJUST`.
- Locales: `stock-programs.*` keys.

### Reuse

`Workspace` parts, `QueryBoundary`, `Table` inside `DataTableCard`, `Button` links,
`recordLabel`, `programGrants`, `facility-program.no-home`, `facility-program.no-home-programs`.

### Rules

- Exact grant at the home facility; a grant elsewhere or an unscoped right never counts.
- A program must be supported by the home facility, be among the user's programs and be granted.
- Sort by name, falling back to code.

### Translations

`stock-programs.program`, `stock-programs.action`, `stock-programs.no-programs`
("There are no programs for this facility. Please contact the Admin."),
`stock-adjustment.title` ("Adjustments for {facility}"), `stock-adjustment.make` ("Make
Adjustments"). The no-home message reuses `facility-program.no-home`.

### Tests

- `stock-programs.test.ts`: intersection, a grant at another facility, a program the facility
  does not support, no home facility, sort.
- Component: rows with links, no-programs and no-home states.
- Route: no `STOCK_ADJUST` shows No Access; the nav hides the entry.
- Browser: administrator on test.openlmis.org (two programs), `sohhomefp` (no access), Arabic,
  390 px.

### Risks

- Legacy's phone pages list more programs than desktop. We follow desktop, the rights-checked one.

## UI/UX

- **Port:** heading, two-column table, one button per program, the no-programs message.
- **Improve:** a no-home-facility message instead of a broken page; the table fills the content
  width with the button at the end of the row, so a phone needs no horizontal scrolling; loading
  skeleton and retry on error.
- **Drop:** the separate phone picker (`adjustmentMobile`); this one page replaces it.

## Decisions

- One PR with FM-66, picker commits first, rather than two stacked PRs: the picker's button needs
  the editor's route to exist.
- One shared presentational component; each action is its own route and passes its label and link.
- Desktop legacy's program rule, not the phone's.
- Unauthorized direct links show the app's No Access page, as every other gated page here,
  instead of legacy's redirect to Home with a modal.
