# FM-205: Onboarding Tour: Stock Events (Issue, Receive, Adjustments, Unpack)

https://openlmis.atlassian.net/browse/FM-205 · Parent: [FM-199] Guided onboarding tours for new users
(React Joyride, isolated module)

Stacked on FM-204 (PR #154), which carries the spotlight scroll fix and the 30 s load wait.

## Scope

- **In:**
  - a tour for each kind's program list and editor (eight tours, built from one file);
  - `data-tour` anchors in the shared stock event screens, so all four kinds share them;
  - one runner fix for every tour: a step with `spotlight` plays only when the spotlit element is
    shown too. Today a step hung from an always-visible toolbar plays over an error notice with no
    spotlight; FM-204's lines and reasons steps have the same flaw.
- **Out:**
  - other runner and launcher changes;
  - anchors in shared components (`StockProgramPicker`, `PickerAdd`, `data-table/`, `DraftStatus`,
    the workspace footer) and in the editor's pending view;
  - per-row controls (counterparty, reason, quantity, VVM, date, comments, Remove, Edit lot): the
    lines step explains them;
  - dialogs (new lot on phones, signature, confirm, print, clear), which explain themselves.

## Summary

Issue, Receive, Adjustments and Unpack get a Show Guide button on their program list and editor.

The program list guide explains, in one step, that each program at the home facility opens the
editor, and what Not Downloaded means offline.

The editor guide walks through:
- choosing a product (and lot) and pressing Add; Receive can add a new lot, Unpack picks kits;
- finding lines with Keywords;
- the saved-on-this-device status, when shown;
- Packs/Doses and View;
- the lines, in the kind's own words;
- Clear;
- Submit: what it checks, the signature or confirmation, printing, the kit contents Unpack records,
  and Stock On Hand after it.

Legacy has the same screens and explains nothing.

### Rules

- **Runner fix:** `presentSteps` keeps a step only when its anchor and, if set, its spotlight are
  shown.
- **No anchors in loading views:** `StockEventPending` and `StockProgramPickerSkeleton` stay untouched;
  the loaded editor's toolbar is never a placeholder.
- **Receive picker skeleton:** `ApprovedProductLotPicker` shows `ProductLotPickerSkeleton` inside the
  anchored wrapper while its first product page loads, outside any busy area. The screens stay as they
  are (tours only), so the step can play over that skeleton; the wrapper persists, so the tooltip is not
  stranded when the picker replaces it.
- **Lines step hangs from View** with the lines spotlit, as FM-204 did; the grid fills the screen.
- **Tests that constrain the anchors:** the Keywords anchor goes on the `fieldset`
  (`event-editor.test.tsx:2605-2608` reads its parent); no `flex-wrap` on wrappers (`:579`); the lines
  wrapper stays outside any `aria-busy` element (`:1656-1681`).
- **Steps that may be absent:** saved (Unpack, plain HTTP, or an editor with no lines), unit (units
  fixed), picker and lines (no stock view right, lookup errors, no destinations or sources). With the
  runner fix all are skipped.
- **Conflict dialog:** a device draft conflict opens a modal and ends the tour.
- **Labels:** use the screen's words in each locale. Submit is Enviar/Envoyer/Enviar/إرسال; View is
  Vista/Affichage/Ver/عرض; Issue To is Salida A/Sortie Vers/Saída Para/الصرف إلى; Received From is
  Recibido De/Reçu De/Recebido De/مستلم من.

## Decisions

- **One tour builder for eight tours:** the screens are shared, so the steps are too; only the words
  differ.
- **Shared keys for identical steps:** search, saved, unit, view and clear read the same for every kind.
- **No step per line control:** they repeat on every line; the lines step names them per kind.
- **Kit contents explained in Submit:** the editor never shows them.
- **Runner fix here, not in FM-204:** FM-204 is pushed and green; the fix rides with the next ticket
  that needs it.
