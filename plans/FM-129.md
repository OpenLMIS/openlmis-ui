# FM-129: Requisition Groups List

https://openlmis.atlassian.net/browse/FM-129 · Parent: FM-124 Admin: facilities & supply chain

Ships with [FM-130](FM-130.md) (add/edit, which carries the shared API map, files, rules and

## Scope

Administration > Requisition Groups:

- a server-paged list with name, zone and program filters;
- View and Edit per row, and Add.

The nav entry, right and `NAV_RIGHTS` come with it.

## Summary

The list shows every requisition group: its name, its programs, code, supervisory node, the
zone of that node's facility, and how many facilities belong to it. Admins filter by name,
zone and program, and open a group to view or edit it, or add a new one.

Legacy asks the server for one page at a time, but it waits for the whole page and its zone
lookups before showing anything. Each row also carries every member facility, so a page of
large groups is over 1 MB. It takes about 10 seconds on UAT.

The new list shows the header, filters and toolbar at once. Rows arrive when the page does,
and zone lookups start as soon as search resolves, without holding the rows back. Earlier pages and
filters come back from cache. Filters live in the address, so a link or reload keeps them.

## Legacy Today

Route `/#!/administration/requisitionGroups?name&zone&program&page&size`, right
`REQUISITION_GROUPS_MANAGE`. Screenshot `.screenshots/FM-39/legacy/gap-requisitionGroupList-desktop.png`
(`admin-requisitionGroupList-desktop.png` is mislabelled).

- **Columns:**
  - Requisition Group Name; Code; Supervisory Node (name); Number of Facilities (member count);
  - Program: the program name for one schedule row, or "{n} Programs" with a popover of names
    for more. It counts schedule rows;
  - Geographic Zone: the zone of the supervisory node's facility, blank without one;
  - View and Edit buttons.
- **Filters:** Filter popover with Name, Program and Geographic Zone, sent as codes. There is no
  sort; the server always orders by name.
- **Paging:** pages of 10, "Showing 10 item(s) out of 510 total".
- **Empty state:** "No requisition groups found."
- **Loads:**
  - `GET /programs`, `GET /geographicZones`;
  - `POST /requisitionGroups/search?page&size` with `{name, zone, program}`;
  - `GET /facilities?id=...` for the node facilities' zones.
  - All of it is awaited before the page paints.

## Agent Brief

### API Map

| Step | Method and path | Params / body | Fields used | Legacy ref |
|---|---|---|---|---|
| Rows | `POST /requisitionGroups/search?page&size` | `{name?, zone?, program?}`; empty values omitted, `{}` when none (any empty string alone gives 400 `search.lacksParameters`) | `id, code, name, supervisoryNode{id,name,facility.id}, requisitionGroupProgramSchedules[].program.name, memberFacilities.length`, `totalElements` | `requisition-group.service.js:115` |
| Zones column | `GET /facilities?id=...` | node facility ids of the page; `facilitiesByIdsOptions` | `id, geographicZone.name` | `admin-requisition-group-list.routes.js:59` |
| Zone filter | `GET /geographicZones` | `geographicZonesOptions()` | `code, name, level.name` | same |
| Program filter | `GET /programs` | `programsOptions()` | `code, name` | same |

**Measured on test (2026-10-14):**

- `{}` took 3.8 s for 85 kB. With no filter the server loads all 510 groups and pages them in
  memory.
- `{program}` took 1.1 s.
- `{name:"Family"}` took 3.0 s for 1.3 MB, because each row carries every member facility.

None of this can change on master.

**Search semantics:**

- name and code match anywhere, ignoring case;
- program and zone are exact codes;
- zone matches only the node facility's own zone, not child zones;
- an unknown code is refused;
- the order is always name ascending, and `sort` is ignored.

### Data Flow

- Route `/administration/requisition-groups`. `validateSearch` with
  `tableSearchSchema(['name']).omit({sort, dir})`, extended with `name`, `zone`, `program`, as
  Lots' `search.ts`. The loader prefetches from `loaderDeps`; a `HistoryState` augmentation
  declares `requisitionGroupsListSearch`, as `reasons.tsx`.
- The loader awaits `requireRight`, then prefetches the page, zones and programs without
  awaiting them.
- **Toolbar outside `QueryBoundary`:**
  - Requisition Group Name text filter (legacy's label);
  - Program `DataTableSelectFilter` over `programsOptions()` by code, as Products'
    `toProgramFilter`, moved to `reference-data` with its content unchanged; `allLabel`
    "All Programs", since legacy's select can be left blank;
  - Zone `DataTableComboboxFilter`, options from `toZoneOption` (moved to `reference-data`)
    with `value` set to the zone **code** at the call site, keeping a linked choice through
    `withPicked` with its own unknown-zone label;
  - View menu;
  - Add at the end.
- **Rows** read `useDeferredValue(search)`. The first load shows `DataTableSkeleton`; later loads
  keep the dimmed rows.
- **Zone lookups** prefetch as soon as search resolves. **Zone cells** read `facilitiesByIdsOptions(nodeFacilityIds)` through a non-suspending
  `useQuery`. A small skeleton shows while it loads; a cell with no facility is blank.
- **Program cell:**
  - one schedule shows the program name;
  - more show a "{n} Programs" button opening a popover of names, named with the group name;
  - none is blank.
- **Row actions:** an end-of-row "..." menu with View and Edit. Links carry
  `requisitionGroupsListSearch` in history state. The menu label includes the name and code.
- **Responsive:** Name, Code and actions always shown. Geographic Zone, then Supervisory Node, then
  Number Of Facilities, then Program, hide by container width (`USER_HIDEABLE_COLUMNS`, View menu).
- **States:** rows, skeleton, no groups, no matches with Clear Filters, `ListError` with retry
  and No Access.

## Decisions

- **An unknown zone or program code in a link** gets a `400` from the server
  (`referenceData.error.geographicZone.notFound` or `referenceData.error.program.notFound`).
  The search query returns an empty page marked as an unknown filter, without retries or
  console errors. The table shows no matches with Clear Filters; other failures show `ListError`.
- **Codes in the URL** for zone and program, as the search body needs them and Products does.
- **No sort control**, since the server ignores `sort`.

- **Backend findings logged** as [FM-190] under [FM-177] Potential BE improvements (2026-10-14):
  the empty filter loads every group and pages in memory, and rows carry every member
  facility. Once FM-190 ships, the list uses its summary search.
- **Browser checks let `POST /requisitionGroups/search` through** (agreed 2026-10-14), so
  paging, filters and the benchmark run on real data. Writes stay stubbed.
