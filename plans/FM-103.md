## Summary

A forecast (BUQ) estimates what a facility will need next year. Preparing one is the first step:
the facility picks a forecasting period and the system fills a draft from the facility's approved
requisitions in that period. Later screens edit, submit and approve it.

Legacy shows the program as fixed text and always uses the user's home facility. The Prepare
button is always enabled, the period list is loaded by fetching every period in the system, and
the downloaded CSV opens twice with the access token in the address.

The new page keeps the same flow on one page: the facility and program as fixed text, the period
picker with Prepare (enabled once a period is chosen), and the list of prepared forecasts below,
with translated statuses, a direct CSV download and a confirmed delete. Periods that already have
a forecast in the list are marked and cannot be prepared again.

## Legacy Today

- `#!/buq/prepare` (state `openlmis.buq.prepareBuq`), menu BUQ > Prepare BUQ, `accessRights:
  [PREPARE_BUQ]`. Resolves refuse entry with an "Application Error" alert when the user's
  programs lack BUQ or the home facility does not support it (`buq.routes.js`,
  `buq.service.js:281-307`).
- Page title "Report List". Left: "Program: BUQ", required "Forecasting period" select ("Select
  period"), Prepare. Right: table Facility Name (home facility), Forecasted Period (`targetYear`),
  Quantification Period (period name), Forecasting Status (raw `DRAFT`), Actions (Download,
  Delete in red); sorted by Forecasted Period; 10 rows per page; empty "No reports available".
- Prepare without a period marks the select invalid; success toast "Report has been prepared
  successfully" and a list refetch; a duplicate period gets 400 "Selected period is already
  prepared" through the global error modal.
- Delete asks "Are you sure you want to delete Report?", then toast "Report has been deleted
  successfully" and the row is removed locally.
- Download calls the endpoint, then opens it again in a new tab with `access_token` in the URL;
  toast "Data has been downloaded successfully".
- Every BUQ page shows a "Not Found" modal from the legacy shell on the local instance (not BUQ).

## Agent Brief

### API Map

| Step | Method And Path | Params | Fields Used | Right | Legacy Ref |
|---|---|---|---|---|---|
| Enter | permissions, `GET /users/{id}`, `GET /users/{id}/programs`, `GET /facilities/{home}` | user id | `homeFacilityId`; program `code === 'BUQ'`; facility `name`, `supportedPrograms` | `PREPARE_BUQ` at home for BUQ | `buq.routes.js`, `buq.service.js:281-307` |
| Periods | `GET /processingSchedules`, `GET /processingPeriods` | `processingScheduleId` of code `BUQ` | `id`, `name`, `endDate` | authenticated | `useBuqCommonFunctions.jsx:33-55` |
| List | `GET /bottomUpQuantifications` | `facility`, `status=DRAFT&status=SUBMITTED&status=REJECTED`, every page | `id`, `processingPeriodId`, `targetYear`, `status` | any BUQ right | `useGetBuqsByStatus.jsx`, `usePrepareBuq.jsx` |
| Prepare | `POST /bottomUpQuantifications/prepare` | `facilityId`, `programId`, `processingPeriodId` | 201 DTO | `PREPARE_BUQ` | `PrepareBuq.jsx:38-60` |
| Download | `GET /bottomUpQuantifications/{id}/download` | none | CSV blob, `buq_quantification_preparation_report.csv` | `PREPARE_BUQ` | `PrepareBuq.jsx:70-87` |
| Delete | `DELETE /bottomUpQuantifications/{id}` | none | 204 | `PREPARE_BUQ`, home facility must match | `PrepareBuqDeleteForm.jsx` |

- Errors `{messageKey, message}`, English only: 400 `buq.error.periodAndFacilityUnique`
  ("Selected period is already prepared"), 400 facility does not support the program, 400 home
  facility mismatch on delete, 403 without the right.
- The list rejects any other param (`programId` gives 400 `buq.error.invalid.searchParams`).

### Data Flow

- Loader blocks on `requirePermissions(queryClient, RIGHTS.prepareBuq)` and the user record, the
  user programs and the home facility (needed to decide access); prefetches periods and the list
  without awaiting.
- Access: no home facility shows `facility-program.no-home`; no BUQ program, home facility not
  supporting it, or no exact `hasProgramGrant(PREPARE_BUQ, home, buq)` shows a no-access message
  with legacy's reason.
- Query keys: new `buq` scope; list `buq.list({ facility })`, periods through
  `processingPeriods.list({ processingScheduleId })`. Prepare and delete invalidate `buq.all`.
- The chosen period is local state, not URL (one-shot action input). List paging is local and in
  the URL (`page`, `size`) as Roles.
- Writes through `useSessionMutation`; download as the CCE export (`fetchReport` plus
  `downloadFile`).

### Server-Side Work

- Periods: legacy fetches all 434 periods and filters by schedule code; we resolve the BUQ
  schedule and send `processingScheduleId` (2 periods, 1.4 KiB instead of 151 KiB).
- Period names: legacy calls `GET /processingPeriods/{id}` per row; we map rows to the periods
  already loaded.
- List stays fetched whole (one facility, three statuses, small) and sorted and paged locally by
  Forecasted Period, as legacy.

### Rules

- Facility is always the home facility; program is the user's program with code `BUQ` (legacy
  matches by name; demo code and name are both `BUQ`).
- Prepare only with a period; one request at a time; the picker clears after success.
- A period whose forecast is in the list is offered disabled with "Already Prepared"; other
  duplicates (forecasts past Submit, not listed) come back as the server message, shown in place.
- Delete always confirms; Download and Delete for every listed row, as legacy.
- Forecasted Period is `targetYear` (the period's end year); Quantification Period is the period
  name; rows sorted by Forecasted Period ascending.

### Risks And Edge Cases

- Prepare duplicates consumption of multi-version products (backend bug, vault); shown as the
  server returns it.
- Deleting a forecast that later screens show is allowed for every listed status, as legacy.
- A user whose PREPARE_BUQ grant is on another facility passes the backend's unscoped check; the
  page refuses it (exact home grant).
- No home facility, BUQ program missing or not supported: clear message instead of legacy's crash.

## UI/UX

**Port**: fixed program, home facility, required period, Prepare, the five columns, Download,
Delete with confirmation, "No reports available".

**Improve**:
- `Workspace` page "Prepare BUQ" with a one-sentence description; facility and program as a
  heading line above a compact `PickerAdd` row (calendar icon, "Select Period", Prepare beside
  it), as other single-picker pages.
- Prepare disabled until a period is chosen, spinner while preparing; already prepared periods
  disabled in the list with a reason.
- Translated status badges (Draft, Submitted, Rejected) instead of raw codes.
- Download CSV saves the file once, no token in the URL; Delete through the row "..." menu
  (cards: `CardActions`).
- Errors in place (server message) instead of the global modal; skeleton instead of a blocking
  loading modal.

**Drop**: the loading modal; the double download; per-row period requests; the always-enabled
Prepare with its invalid state.

States: permissions/home loading (real header, skeleton), no access with reason, list loading,
empty, error with retry, preparing, deleting. Cards below 672px. RTL with logical classes.

## Decisions

- **Program and facility fixed from the home facility** (AC 5): legacy and the backend
  (save, submit, delete) assume the home facility, and the right is granted there.
- **Periods filtered on the server** and names mapped locally, instead of legacy's full fetch and
  per-row calls.
- **Already prepared periods disabled** in the picker, using the listed forecasts; the server
  message covers the rest.
- **Row actions in a "..." menu** (two actions), per AGENTS.md.
