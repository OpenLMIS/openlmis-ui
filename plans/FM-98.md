# FM-98: CCE Inventory List

https://openlmis.atlassian.net/browse/FM-98 · Parent: FM-97 Cold chain equipment

## Scope

- New CCE Inventory page at `/cce/inventory`, the live `nav.cce.inventory` entry under CCE
  Management.
- Facility and program picker, a server-paged list of the equipment found, a functional status
  filter, RTM alert indicators, Export CSV, and the entry points to the add, details and status
  screens.
- The equipment status labels, tones and icons move from Home to a shared module, so Home and
  this page show statuses the same way.
- Not in scope: the add, details, edit, status update and transfer screens, which are the sibling
  tickets FM-99, FM-100 and FM-101. Until they ship, those entry points open the matching legacy
  modal (Decisions). Offline: the route stays online-only, as every admin and CCE page.
- No backend change.

Research baseline, 2026-11-02: UI `origin/master` `5d8dbd7`; `openlmis-cce-ui`,
`openlmis-cce`, `openlmis-referencedata-ui`, `openlmis-ui-components` and `openlmis-auth-ui`
master. Legacy walked on the local ref-distro (`58fea22`: cce 1.5.2, reference-ui 5.2.16, demo

`.screenshots/FM-98/`.

## Summary

The CCE inventory is the list of cold chain equipment (fridges, freezers, cold boxes) installed
at health facilities. Managers use it to see what equipment a facility has for a program, which
items work, which wait for repair, and which have temperature alerts from remote monitors.

Legacy shows a search panel on the left (facility type, facility, program) and a table on the
right with Export CSV, Filter and Add Equipment. It works, but the console fills with thousands
of errors from the export link, Search is clickable before a program is chosen and then shows a
blocking error, the alert bell for active alerts never appears, the status edit icon shows to
people who cannot change anything, the export link carries the sign-in token in its address, and
on a phone the table is squeezed to a thin strip beside the search panel.

The new page uses the same facility and program picker as Stock On Hand and Transaction History,
then a table (cards on phones) with the same columns, a status filter, server paging, a clear
status badge with its reason, an alert bell that works, and Export CSV that downloads the same
file without errors. View, the status edit icon and Add Equipment open the legacy screens until
their own tickets bring them over; the edit actions show only to people who may edit.

## Agent Brief

### API Map

Paths relative to the Axios `/api` base. Sources: `openlmis-cce` `src/main/resources/api-definition.yaml`
and `web/InventoryItemController.java`, `web/AlertController.java`; `openlmis-referencedata`
RAML for the picker.

| Step | Method And Path | Params | Fields Used | Right | Legacy Ref |
|---|---|---|---|---|---|
| Enter page | existing permissions query (`requirePermissions`) | signed-in user | permission strings | `CCE_INVENTORY_VIEW` | `cce-inventory-list.routes.js:39-40` |
| Picker | existing `userRecordOptions`, `userProgramsOptions`, `minimalFacilitiesOptions` (`GET /users/{id}`, `/users/{id}/programs`, `/facilities/minimal`) | none | home facility, programs, facility names | none extra | `facility-program-cache.service.js:163-182` |
| List | `GET /inventoryItems` | `facilityId`, `programId`, `page`, `size`, `sort`, `functionalStatus`, `expand=lastModifier` | `content[].id, equipmentTrackingId, referenceName, catalogItem{manufacturer, model, type}, functionalStatus, reasonNotWorkingOrNotInUse, yearOfInstallation, modifiedDate, lastModifier{firstName, lastName}`, `totalElements` | `CCE_INVENTORY_VIEW` (server keeps only VIEW grants) | `cce-facility-inventory-factory.js:50-84` |
| Alerts | `GET /cceAlerts` | `deviceId` repeated for the page's item ids | `device_id, start_ts, end_ts, dismissed, status{<locale>: text}` | authenticated | `cce-inventory-list.routes.js:83-93`, `cce-alert.factory.js:53-75` |
| Export | `GET /inventoryItems/download` | `format=csv`, `facilityId`, `programId`; blob | file bytes, `inventory_items.csv` | authenticated only | `cce-inventory-list.controller.js:252-257` |

- `GET /inventoryItems` pages on the server (`totalElements`); without `size` it returns
  everything, so the page always sends `size`. Default sort is `referenceName`.
  `functionalStatus` is one of FUNCTIONING, AWAITING_REPAIR, UNSERVICEABLE, NEEDS_ATTENTION.
  `supervised` is ignored by the server and is not sent.
- **Server leak**: the service builds the facility and program sets from the user's VIEW grants
  independently, and drops the facility predicate when the user has no VIEW at the requested
  facility (`InventoryItemService.java:76-94`, `InventoryItemQueryBuilder.java:80-108`). Observed:
  vsrmanager1 asking for Depósito Distrital Cuamba got 230 items from 9 facilities. The page must
  only ever request an exact `CCE_INVENTORY_VIEW` grant (Rules).
- `GET /inventoryItems/download` ignores `functionalStatus` and paging and checks no right; it
  returns `text/csv;charset=ISO-8859-1`, columns Facility Name, Model, Type, Net Volume,
  Reference Name, Program Name, Serial No., Year of Installation, Year of Warranty Expiry,
  Functional Status, Last Modifier Name, Modified Date.
- `GET /cceAlerts` without `active` returns past and current alerts; an alert is active when it
  has no `end_ts` and is not `dismissed`, the same test legacy applies.
- Errors are `{messageKey, message}`; 403 when refused; a bad enum or id is a 400.

### Data Flow

- Route `src/routes/(protected)/_protected.cce.inventory.tsx`, modelled on Transaction History:
  the loader blocks on `requirePermissions(queryClient, RIGHTS.cceInventoryView)`, prefetches the
  picker options, and prefetches the list (not awaited) only for a complete selection with
  `hasProgramGrant(permissions, RIGHTS.cceInventoryView, facilityId, programId)`.
- URL: `facilityProgramSearchSchema` (`mode`, `programId`, `facilityId`), `page`, `size`, `sort`,
  `dir` from `tableSearchSchema`, and `functionalStatus` (enum, invalid values dropped). Defaults
  stay out of the URL. Filter changes replace history and reset to page 1; paging adds entries.
- Query keys: `inventoryItems` scope in `key-factory.ts`; list under `list(query)`, alerts under
  `[...all, 'alerts', ids]`. Alerts load after the list and never block or remount the rows.
- Export runs through `useSessionMutation` and `fetchReport`, then `downloadFile`, from the
  toolbar; disabled until a search is applied; a failure shows a toast.
- View hides Serial No., Make/Model, Type, Last Updated, Year Installed (the last three below
  896, 1024, 768px). Facility, Reference Name and Functional Status always show.
- The picker's draft, Search and refused-link behaviour are the shared component's
  (AGENTS.md, Facility and program picker).

### Server-Side Work

- Paging, counting and the status filter already happen on the server, as in legacy.
- **Facility name**: legacy asks `GET /facilities?id=X&id=X...` with the same id once per row,
  only for the name. The page already has the selected facility's name from the picker's
  `minimalFacilitiesOptions`, and every row belongs to that facility once the request is an
  exact grant, so the call is dropped.
- **Sorting**: legacy never sorts. The table sorts on the server through `sort` for Reference
  Name, Serial No. (`equipmentTrackingId`), Type (`type`), Functional Status, Last Updated
  (`modifiedDate`) and Year Installed (`yearOfInstallation`). Checked on the local instance
  (2026-11-02): all six answer 200 and order both ways where the demo data differs (Reference
  Name and Serial No. as text, so "Fridge #11" comes before "Fridge #2"; Type by catalog value;
  Functional Status by its code; Year Installed numerically); `modifiedDate` is accepted, though
  the demo dates are all equal or empty. An unknown key (`manufacturer`, `facility`) answers 500,
  so only these six are ever sent. Facility and Make/Model stay unsortable: `catalogItem.model`
  sorts but by model alone, which would misorder a Make/Model column. A chosen sort adds
  `referenceName,asc` and `id,asc` as tie-breakers, so equal values never repeat across pages.
- Export stays one server file for the facility and program; the browser never builds or
  filters the CSV.

### Rules

- **Exact grants only.** The picker offers, and the page requests, only facility and program
  pairs with `CCE_INVENTORY_VIEW` (`programGrants(permissions, RIGHTS.cceInventoryView)`). A link
  to another pair is refused by the shared picker and sends nothing (server leak, API Map).
  Legacy also offers `CCE_INVENTORY_EDIT`-only pairs; the server returns nothing useful for them,
  and some return other facilities' items.
- **Edit actions follow the selected pair.** Add Equipment and the status edit icon show when the
  user has `CCE_INVENTORY_EDIT` for the selected facility and program (`hasProgramGrant`), the
  check legacy's status modal makes per item. View shows to everyone with VIEW.
- **Columns**: Serial No. is `equipmentTrackingId`; Make/Model is `manufacturer` and `model`
  joined by a space; Type is the catalog value as stored (not translated, as legacy); Last
  Updated is the modifier's first and last name, then `modifiedDate` with `formatTimestamp` in the
  deployment time zone, either part left out when missing; empty cells stay blank (AGENTS.md,
  List pages).
- **Status**: badge with label, tone and icon from `cce-equipment-status.ts`; the reason under it.
  Both are closed server enums, typed directly.
- **Response**: `@JsonInclude(NON_NULL)`, so empty values are absent keys. Optional:
  `equipmentTrackingId`, `reasonNotWorkingOrNotInUse`, `modifiedDate`, modifier fields.
- **Alerts**: active when no `end_ts` and not `dismissed`. Active alerts show a bell button that
  opens a popover listing each alert's start time and text (the page language's text when the
  `status` map has it, else `en-US`, else the first entry); past alerts only show an outline bell
  with a tooltip; no alerts, no icon. The bell and the edit icon are icon buttons with accessible
  names.
- **Export**: the facility and program of the applied search, never the draft; the whole list for
  that pair (the server ignores the status filter), which the button's tooltip says; filename
  `inventory_items.csv`; bytes saved unchanged.
- **Legacy links** (until FM-99, FM-100, FM-101): View opens
  `#!/cce/inventory/{id}/details?page&size&facility&program&supervised`, the status edit icon
  `#!/cce/inventory/{id}/statusUpdate?...`, Add Equipment `#!/cce/inventory/add?...`, built from
  the applied search (`supervised=true` for the Supervised mode, else `false`, plus
  `functionalStatus` when filtered), through
  `openLegacy`, which keeps the leave guard; they show only when `legacyAvailable()`.
- Page size 10 by default as legacy, sizes from the shared pager; sort default Reference Name
  ascending, as the server.
- No code comments (user, 2026-11-02); clear names instead. No em dashes.

### Risks And Edge Cases

- The server leak above: a stale or hand-made link must never reach the server unless it is an
  exact VIEW grant.
- Export is ISO-8859-1, so accented names come out garbled in some spreadsheets, as in legacy.
  The bytes are saved unchanged; fixing it is a backend matter.
- `/cceAlerts` can return many past alerts per device; only the page's ids are asked for (at most
  the page size).
- Sort keys other than `referenceName` are built into the server query from the parameter; a key
  that fails on the local instance is left unsortable rather than risking a 500.
- Legacy links need the legacy UI on the same host (`legacy.available`); without it the three
  entry points are hidden until FM-99, FM-100 and FM-101.
- Saves in FM-99, FM-100 and FM-101 must invalidate the `inventoryItems` scope and Home's
  equipment counts.

## Decisions

- **No backend change.** Only master endpoints; the server leak is handled by exact grants.
- **Same layout as Transaction History and Stock On Hand** (user, 2026-11-02: match the other
  tables in the new UI): picker row, applied heading, toolbar, table card and pager.
- **Same picker as the other facility and program pages**, in a row above the results, with the
  app's submit-first validation rather than a disabled Search (AGENTS.md: forms validate on
  submit, then on change), as on every facility and program page; the shared picker, which every
  stock page uses, stays unchanged (user, 2026-11-02).
- **Shared pager** ("1-10 / 23" with pages and sizes) instead of a separate "Showing X item(s)
  out of Y total" line; it carries the same counts (user, 2026-11-02).
- **View, status update and Add Equipment open the legacy modals** until FM-100, FM-101 and FM-99
  ship, as Requisitions did before FM-43; each then swaps its link for the new screen
  (user, 2026-11-02).
- **Composed from existing components** (user, 2026-11-02): no new shared component and nothing
  in `src/components/ui/`. The three files in `src/features/cce-inventory/components/` only
  compose existing parts for this page, as Transaction History's results and toolbar do; the
  status labels, tones and icons move from Home to `src/lib/`; Home looks the same.
- **Route access needs `CCE_INVENTORY_VIEW`**, as the AC says, rather than legacy's any of VIEW,
  EDIT or TRANSFER: without VIEW the server returns nothing to list.
- **Status styling shared with Home** through `src/lib/cce-equipment-status.ts`, since a feature
  cannot import Home.
- **Online-only**, as every admin and CCE page.
- **Results stay until Search**: a picker change without Search keeps the searched list and its
  export; no separate pending state.
- **Row state through context** (alerts, legacy actions, pending state), not column definitions,
  so re-renders never remount cells, popovers or focus.
- **Facility always shown** (user, 2026-11-02); Functional Status is not hideable either, as it
  holds the status update.
- **Add Equipment needs EDIT for the selected pair** (user, 2026-11-02), stricter than legacy.
- **Status order as Home; Last Updated in the app's date format** (user, 2026-11-02).
