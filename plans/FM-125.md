# FM-125: Facilities List + Add

https://openlmis.atlassian.net/browse/FM-125 · Parent: FM-124 Admin: Facilities & Supply Chain

## Scope

Administration > Facilities: the list, its filters, and adding a facility with the programs it
supports. Item 3 of the admin round that sets up what Stock Management reads (see
[FM-62](FM-62.md), "Administration first"), after FM-127 Facility Types and FM-142 Programs.

It builds the facility form, both its information and its programs, as one piece that
[FM-126](https://openlmis.atlassian.net/browse/FM-126) Facility Edit then reuses, so the two screens can never drift apart. It also
adds two shared pieces the stock screens need later: a date field and a searchable filter for
long lists.

Out of scope: editing (FM-126), removing a facility (legacy has none), geographic zones as a
screen (FM-128), and the facility's location, comment, go-down date and extra data, which no
legacy screen shows.

Builds on FM-140 Products (#33, merged): its toolbar with a search box and a reference-data
filter, its two empty states, and text filters that survive a value that looks like a number.
No backend change: the search, the zone filter and Operational Date behave as in legacy, as the
user decided.

## Summary

A facility is any place that stores or hands out products: a clinic, a hospital, a warehouse.
Stock, requisitions and user rights are all tied to facilities, and the programs a facility
supports decide what it can order and stock.

In the old UI, Administration > Facilities lists facilities ten at a time with their code, zone,
type and whether they are active and enabled, and a Filter button searches by name and zone.
Add Facility opens a window with the facility's details. Saving it creates the facility at once;
only then does a question ask whether to add programs, and a second window saves those. It
works, but:

- The facility exists before its programs are chosen, so closing the second window leaves a
  facility that supports nothing.
- Opening the programs window again from its address, or reloading it, fails with an error,
  which is the failure seen on UAT.
- The zone list is every zone in the system, unsorted, in one long list.
- Filtering from page 3 stays on page 3, so it often shows nothing.
- Errors appear as a blocking "This form is invalid" alert before the fields are marked.
- A new facility does not show up in the other screens' facility pickers until the admin signs
  out and in again.
- On a phone the table runs off the screen.

The new screen keeps the same data, fields, help texts and rules, and fixes those:

- The list shows the same columns, pages and counts on the server, and can be sorted by name,
  code, active or enabled.
- Search by name, as legacy, and a zone filter you can type into, sorted by name, with the
  zone's level beside each name.
- Add Facility opens a page with the details and the programs together, and one Create saves
  both, so a facility is never left half set up.
- Errors show on the fields, a code already in use included.
- A new facility is in every picker at once.
- It works on a phone and in Arabic.

## Legacy Today

Screenshots: `.screenshots/FM-125/legacy-*` (desktop and phone), `research-zz-*` (the real
save flow on the local backend).

- **Routes:** list `/#!/administration/facilities?name&zoneId&page&size`, Add modal
  `/new/details`, programs modal `/new/programs`. UI in `openlmis-referencedata-ui`
  (`admin-facility-list`, `admin-facility-add`, `admin-facility-programs`, `admin-facility-view`).
- **Rights:** list and edit check `FACILITIES_MANAGE`; the server checks it on create and save,
  nothing on reads. `divo1` lacks it: no menu entry, a deep link goes Home.
- **List:** `POST /facilities/search?page&size=10&sort=name,asc` with `{name, zoneId}`. Columns
  Facility name, Code, Geographic zone, Type, Active (tick), Enabled (tick), Edit. No sorting, no
  page size choice, "Showing 10 item(s) out of 2736 total". Filter popover: Facility name and a
  searchable Geographic zone select of all 205 zones (`GET /geographicZones`, unpaged,
  unsorted, refetched on every list change). The zone filter never sends `recurse`, so a region
  finds only facilities placed directly on it (Gaza: 2, with its districts: 152). Empty and no
  match both read "No facilities found."
- **Add, step one:** Facility Name*, Facility Code*, Facility Type* (active types), Operational
  Date (optional on add), Active Facility (on), Enabled (on), Geographic Zone*, Description,
  Facility Operator. Help texts:
  - Operational Date: "This is used in reporting to record the date the facility becomes
    operational"
  - Active Facility: "This determines whether or not the facility can submit requisitions or
    receive deliveries"
  - Enabled: "Checked = The facility can operate" / "Unchecked = The facility is permanently
    decommissioned"
- **Save, step one:** `POST /facilities` without programs, toast "Facility has been saved!", the
  list, then a confirm "Do you want to add programs to {name}?". A failed create shows "Failed
  to save facility!" and then throws in the console (`facility-add.controller.js:73-101`).
- **Step two:** "Assign Programs to {name}". Program* (programs not yet added) and Start Date*,
  Add; table Program, Active (on for a new row), Start Date (editable, with the help "The
  program start date determines the first date available for users to enter requisitions
  related to the program."), Locally Fulfilled (off). No remove. Save sends
  `PUT /facilities/{id}` with the whole facility, toast "Facility saved successfully!". Opened
  from its address or reloaded, the facility is gone from memory and the modal throws
  `facility.isManagedExternally is not a function`, which matches the UAT failure.

## Agent Brief

### API Map

| Step | Method and path | Params and body | Fields used | Right | Legacy ref |
| --- | --- | --- | --- | --- | --- |
| List | `POST /facilities/search` | query `page`, `size`, `sort`; body `{name?, zoneId?}` | `id, code, name, geographicZone.name, type.name, active, enabled`, `totalElements` | none | `admin-facility-list.routes.js:26-61` |
| Zone lookup | `GET /geographicZones` | `sort=name,asc` (legacy sends none) | `id, name, level.name` | none | `geographic-zone.service.js` |
| Type lookup | `GET /facilityTypes` | `active=true` | `id, code, name` | none | `admin-facility-add.routes.js:28-53` |
| Operator lookup | `GET /facilityOperators` | none, a plain array | `id, code, name` | none | same |
| Program lookup | `GET /programs` | none | `id, code, name, active` | none | `admin-facility-programs.routes.js:27-58` |
| Create | `POST /facilities` | `{code, name, description, type, geographicZone, operator, goLiveDate, active, enabled, supportedPrograms: [{id, code, supportActive, supportLocallyFulfilled, supportStartDate}]}` | 201, the facility | `FACILITIES_MANAGE` | `facility-add.controller.js:73-101` |

Errors on create:
- `400 referenceData.error.facility.code.required`.
- `400 referenceData.error.facility.code.mustBeUnique` "The facility with given code already
  exists." Unique ignoring case (`LOWER(code)` index), so `hc01` clashes with `HC01`.
- `400 ...facilityType.notFound`, `...geographicZone.notFound`, `...facilityOperator.notFound`.
- `400 referenceData.error.program.id.code.null` for a program without id and code.
- A missing `active` or `enabled` is a raw SQL message: always send both.
- `403 referenceData.error.unauthorized`.

The server does not require a name; the form does, as legacy does.

### Data Flow

- List route `/administration/facilities`: awaits `requireRight(FACILITIES_MANAGE)`, prefetches
  the page from `loaderDeps`, deferred. URL: `page`, `size`, `sort` (`name`, `code`, `active`,
  `enabled`; default `name` ascending), `name` (`textFilterSchema`), `zoneId` (a guid).
- Add route `/administration/facilities/new` (`facilities_.new`, no nesting): awaits the right
  and prefetches the four lookups, deferred; each field that picks from one loads behind its own
  boundary, so name, code and the rest can be typed at once. The draft lives in `FacilityEditor`,
  above the tabs, and the tab is a search param (`tab=programs`, Information left out), as Edit
  User Roles, so a tab switch never trips the discard guard. The footer's Create submits the
  Information `<form>` through its `form` attribute, so Enter creates; the add-program row is its
  own form, so Enter there adds the row. Opened from the list with the list's search in history
  state; Create and Cancel go back to it.
- Lookups in `reference-data`, `staleTime` 10 minutes like the others:
  `geographicZonesOptions()` (`queryKeys.geographicZones.list()`),
  `facilityOperatorsOptions()`, plus the existing `facilityTypesOptions({active: true})` and
  `programsOptions()`.
- The zone filter reads the zone lookup with `useQuery`, so the toolbar never suspends, as the
  Products program filter does.
- After Create: invalidate `queryKeys.facilities.all`, which refreshes the list and the minimal
  facilities lookup the user screens read.

### Server-Side Work

- Paging, sorting by name, code, active and enabled, and the total count: already on the
  server.
- Sorting by zone or type returns `500`, so those columns stay unsortable.
- The search matches the name only, as legacy; `code` is a separate filter joined with AND, so
  a code-or-name box would need a backend change, which the user chose not to make now. `%` and
  `_` in a search act as wildcards on the server, as in legacy.
- The zone filter sends `zoneId` without `recurse`, as legacy: a region finds only facilities
  placed on it, not in its districts.
- Zones: one unpaged request, sorted by the server, cached for the session; 205 zones locally,
  about 16 KB.

### Rules

- Operational Date optional on Add, as legacy (FM-126 requires it on Edit).
- Name, code, type and zone required; whitespace alone counts as empty; text trimmed.
- Code unique ignoring case, checked by the server only (2700+ facilities, too many to load);
  a refusal lands on the Code field.
- Active and Enabled start on; both always sent. They are `SwitchField` rows with their legacy
  help texts behind the info button, as #36 made every switch.
- Type offers active types only.
- A program row needs a program and a start date (`associated-programs.html:1-14`); a new row
  starts Active on, Locally Fulfilled off; `supportActive` and `supportLocallyFulfilled` always
  sent, since a missing one saves as off.
- A program already in the table leaves the program choice.
- A row added on this page can be removed before Create; legacy has no remove because it saved
  each row at once.
- Dates are `yyyy-MM-dd` both ways, shown in the page's language, never shifted by time zone.

### Risks and Edge Cases

- Code uniqueness ignores case on the server; the form never claims a code is free.
- A facility without a name exists in the data (the server allows it): the table shows "-",
  as Products does.
- 205 zones with repeated names at different levels: each option shows its level.
- A zone id in the URL that no longer exists: kept as its own option, as Products does with an
  unknown program.

## Decisions

- **Add is a page, not a dialog**: it holds a table of programs, which AGENTS.md sends to a page,
  and FM-126's Edit page is the same page with the record loaded. Recommended over a two-step
  dialog with one save at the end, which would be the first wizard in the app and cramped on a
  phone.
- **One save creates the facility with its programs**, as the AC asks; the server accepts
  `supportedPrograms` on create.
- **Tabs, not steps**: Information and Programs as tabs, the same as Edit; Create checks both
  and opens the first tab with an error.
- **shadcn's calendar for dates** (`react-day-picker`), not the browser's date input: it follows
  the page's language and direction, which a native input does not, and the stock screens need
  many dates. Day names are narrow, since full Arabic names do not fit a day column.
- **Search by name only, as legacy**, as the user decided, rather than one code-or-name box,
  which would need a backend change first.
- **The zone filter matches the chosen zone only, as legacy**, as the user decided, though the
  server could include sub-zones.
- **No backend tickets** for the search or for the `500` on sorting by zone or type, as the user
  decided.
- **The zone filter is a searchable combobox**, not Products' select: 205 zones, against 8
  programs.
