# FM-42: Requisition: Patients Tab

https://openlmis.atlassian.net/browse/FM-42 · Parent: [FM-39] Requisitions

## Scope

- Makes the Patients tab editable for creators and authorizers on templates with
  `patientsTabEnabled`, and opens every other edit and action on those templates (Sync, Submit,
  Authorize, Approve, Reject, Delete, Skip, comments) through the policy already used for
  product-only templates.
- Approvers on patients templates edit the columns the server keeps for them: the patients count
  (TC), Quantity Issued (B) and Remarks, as legacy (Approved Quantity is not editable there).
- Removes the interim legacy link (`LegacyActionsNote`) and the closed patients gate, now unused.
- Not in scope: offline opening ([FM-164]/[FM-167]); batch approval ([FM-46]).

## Summary

TB and Leprosy programs report how many patients are on treatment in each month of their
regimen. Those numbers drive how much of each TB medicine the facility asks for. In legacy, a
requisition on such a template opens on a Patient(s) tab: a grid with a TB group and a Leprosy
group, one row per patient type, a Skip box and one input per month of treatment.

The new UI has shown this tab read-only, with a link to legacy for editing. With this change,
facility staff fill it in the new UI: the grid scrolls sideways with the row labels pinned,
product quantities follow the patient numbers as they type (legacy only updates them when the
other tab is opened), Submit and Authorize check the grid is complete, and phones get one card per
row instead of legacy's unusable strip. Approvers keep the grid read-only, as legacy, and adjust
the patient-driven quantities on the product tab.

## Legacy Today

No TB Monthly requisition exists on test; legacy was walked on a real INITIATED record served
with the real TB Monthly program and template (`.screenshots/FM-42/research-a-legacy-browser.md`,
screenshots `legacy-*.png`, PUT bodies `data/*-put-body.json`). Source and API:
`research-b-legacy-source-api.md`.

- Tabs: "Patient(s)" first and default, then "Priority drugs and medical supplies" (Full Supply
  renamed); TB Monthly has no non-full-supply tab.
- Grid: Skip, Month of treatment, 1 to 12; TB rows "Number of adult patients(new)", "Number of
  children(new)", "Number of retreatment patients", "Number of adults on IPT", "Number of children
  on IPT"; Leprosy rows "Number of adults on MB regimen", "Number of adults on PB regimen",
  "Number of children on MB regimen", "Number of children on PB regimen". PB rows enable 12
  months, others 6: 66 of 108 inputs. Skip and label pinned; 2518 px wide.
- Inputs strip non-digits on blur or after 500 ms; a cleared input stores `null`. Skip is disabled
  once the row holds any value, including 0; skipping disables the row and clears its marks.
- Any value in a row marks that row's empty enabled months invalid ("This field is required",
  English only). The pager turns red; the tab gets no marker.
- Submit/Authorize: confirm, then "R&R has errors, please correct them to proceed." when any
  unskipped row has an empty enabled month. Approve does not check the grid. Sync saves
  incomplete grids.
- TC ("No of Patients on Treatment next month") for nine product codes is computed from month
  sums only when the product tab is opened; a save without opening it sends a stale TC.
- Save: `PUT v2/requisitions/{id}` with `patientsData` = `JSON.stringify({TBData:[[rows]],
  leprosyData:[[rows]]})`; a row is `{key, title, data: 12 x {value, disabled, isInvalid,
  isFocused}, isSkipped, isSkipDisabled}`. The server stores the string as sent on every save and
  nulls it when absent (`Requisition.java:437-438`).
- Approver: grid read-only; product tab edits TC, Quantity Issued (B) and Remarks. The server
  keeps B and TC for approvers only on patients templates (`RequisitionLineItem.java:398-412`).
  Legacy validation for these templates skips B and, in Authorized, stock on hand
  (`validateTbMonthly`).
- Phone: no cards; pinned columns leave room for one input.
- Defects not ported: patients kept in global localStorage (another record's data can appear;
  Submit validates storage, not the record); hardcoded English; B editable regardless of rights;
  stale TC on save; unused `PATCH updatePatientsData` without a permission check.

## Agent Brief

### API Map

No new endpoints. `PUT v2/requisitions/{id}` (existing `transform.ts`, `patientsData` always
sent), `POST requisitions/{id}/submit|authorize|approve` and `PUT requisitions/{id}/reject`
(existing). Never use
`PATCH .../updatePatientsData`.

### Data Flow

- `lib/patients.ts`: `parsePatients` normalises once (numbers, `title`, flags; malformed JSON
  becomes an error state, not a throw); `writePatients(rows)` produces legacy's exact shape
  (double-nested arrays, `title` message keys, `disabled` per month, `isInvalid` from our
  validation, `isFocused: false`, `isSkipDisabled`; `""` for untouched and disabled months,
  `null` for cleared ones). Field ids are flat and language-independent, in the existing
  `texts.<id>:<col>` style: `patients:<disease>:<key>:<month>`.
- Draft (`lib/draft.ts`): `RequisitionDraft` gains `patients`, `null` while unchanged, holding only
  changed cells and skip flags (like line changes), so a patients-only edit counts as unsynced
  (`lib/unsynced-device-work.ts`), is never dropped as empty
  (`hooks/use-requisition-draft.ts:88-95`), and undoing every change makes it clean again. Rebase
  keeps local changed cells over newer server data, as lines. Older drafts without the field load
  as unchanged (rebase canonicalises a missing field to `null`, so dirty checks and empty-draft
  cleanup compare equal); the optional field needs no draft format or Dexie schema bump (`formats: [1]`,
  key `draftId`).
- Apply and save: with no patients changes the record's `patientsData` string goes back
  unchanged (approvers and viewers never rewrite it); with changes `writePatients` builds it. For
  creators and authorizers the save also writes the TC computed from the draft's patients into
  each formula line, since the server stores TC as sent and recalculates nothing
  (`RequisitionLineItem.java:449-454`, `617-630`); legacy sends the computed TC too.
- Form (`hooks/use-requisition-form.ts`): `setPatientValue(disease, key, month, text)` and
  `setPatientSkip(disease, key, skipped)`.
- TC follows the draft: `requisition-tabs.tsx` passes the parsed draft `PatientsData` to
  `calculateLine` (no re-parsing per keystroke). Formulas sum month values and ignore Skip, as
  legacy (`calculation.factory.js:687-694, 731-760, 775-861`); skipped rows hold no values anyway.
  Payload safety is separate from completeness: before every PUT (Sync, Print and every action)
  each count and each computed TC must fit 0 to 2147483647 (Java `Integer`); otherwise the save is
  blocked with the invalid dialog. Incomplete grids still save.
- Performance: patient-dependent calculations are keyed by the normalised patient totals per
  formula code, so a keystroke recomputes only the nine formula lines and keeps every other line
  model reference; patient inputs subscribe per row (`useStore` selector), not to the whole
  draft.
- Approver TC: `draft.ts` `editableChanges` keeps TC when the approver may edit it (calculated
  columns are otherwise dropped), and `validateLine` checks it as a whole number like user-input
  columns; a stored TC differing from the formula wins from Authorized on, as today.

### Rules

- Inputs: whole numbers 0 to 2147483647 through `NumberField` (`wholeNumberText`, Arabic and
  Persian digits accepted); empty is allowed while editing.
- Skip: disabled while the row has any value (0 included); skipping disables the row's inputs and
  clears its errors, as legacy.
- Live errors: a row with any value marks its empty enabled months (editor validates live from
  the first change, AGENTS.md). After a failed Submit/Authorize every unskipped row's empty months
  are marked. A row cleared back to empty loses its marks (legacy keeps them): a deliberate
  difference, since Skip is enabled again.
- Submit/Authorize: every enabled month of every unskipped row filled; else the invalid dialog
  focuses the first empty cell on the Patients tab (`revealField` in cards). Approve and Sync do
  not check the grid.
- Patients tab gets the warning badge when it holds errors, as product tabs do.
- Capabilities: grid editable for CREATE on INITIATED/REJECTED and AUTHORIZE on SUBMITTED.
  Approvers on patients templates (template flag, as the server; legacy keyed on the program
  name) edit TC, B and Remarks. The creator check `program.name === 'TB Monthly'`
  (`capabilities.ts:97-101`) moves to the template flag too.
- Validation on patients templates (port `validateTbMonthly`, every status): B and Remarks never
  required; TC not checked in INITIATED and SUBMITTED; stock on hand not checked in AUTHORIZED
  (still checked in IN_APPROVAL); the stock-on-hand calculation check skipped. Stock on hand stays
  required and non-negative at Submit and Authorize, as the server (`StockOnHandValidator`).
- The server never checks the grid or TC; completeness is enforced only here, as legacy.

- Pure: `writePatients` round-trips legacy's captured body; TC from draft rows; completeness

### Risks And Edge Cases

- Malformed stored `patientsData`: `parsePatients` returns a shared result type (rows or an
  unreadable state keeping the original string). Calculations treat unreadable data as
  unavailable TC (no formula value), the tab shows it read-only with an error, saves send the
  original string unchanged, and Submit/Authorize are blocked with an actionable message.
- Legacy stores `isInvalid` flags; we recompute them, so a legacy-saved record shows our marks.
- No real TB record on test (Open Questions).

## UI/UX

**Port**: groups, labels, months, Skip rule, completeness check, pinned columns, approver
columns.

**Improve**: TC updates while typing; Patients tab error badge; translated messages; Arabic digits;
phone cards; no stale TC on save; drafts per record on the device instead of shared browser
storage.

**Drop**: legacy's stored focus flags (always false); the pager on this tab (all nine rows show).

## Decisions

- **`patientsData` is sent on every save**, as legacy's PUT does, since the server nulls it when
  absent; unchanged grids go back as the stored string.
- **Saves carry the TC computed from the grid**, fixing legacy's stale TC.
- **Approver patient columns follow the template flag**, as the server keeps them, not the
  program name.
- **Labels follow legacy** ("(new)", "Patient(s)").

- A real TB Monthly requisition exists on test for review checks: `cc485932-4ed3-4fe4-8dd4-a23990b4956b` (INITIATED, Jan2017, Comfort Health Clinic), created 2026-10-30 with the user's approval.

## Implementation Notes

- Browser, live-server and typing-timing checks are deferred to review, as the build brief prohibits browser and server access during implementation.
- Payload bounds are checked centrally in the existing Sync path, shared by Print and transitions. Completeness is checked before Submit and Authorize only. Unreadable data is preserved unchanged for Sync and blocks those transitions.
- The writer fixture is copied from the captured creator Sync PUT body. An untouched grid sends the record's stored string back unchanged (null only when the server already holds null), so every PUT includes patientsData and none erases it.
- The Patients pending view now follows the grid and card layouts. Patient row subscriptions and product model caching retain references for unaffected rows and formula totals.
- Patient payload and completeness checks run only for users who can edit the grid, so approvers
  and viewers are never blocked by legacy-saved data they cannot change, and see no Patients
  error badge. TC is also exempt in REJECTED, where the creator edits as in INITIATED and the
  saved TC is the computed one.
