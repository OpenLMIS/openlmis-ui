# FM-212: Onboarding Tour: Profile And Settings

https://openlmis.atlassian.net/browse/FM-212 · Parent: [FM-199] Guided onboarding tours for new users
(React Joyride, isolated module)

Stacked on the review fixes (PR #167).

## Scope

- **In:** two tours: Profile (Basic Information, Role Assignments, Notification Settings) and Settings
  (Branding, Theme, Feature Flags), each played by whichever tab page is open.
- **In:** `data-tour` attributes and plain wrappers, new keys in `TOUR_ANCHORS`; reuse of `editorTabs`
  (already on `WorkspaceTabs`), the shared `list-*` anchors and `sortStep` / `viewSortStep`.
- **In (approved exception, as FM-208 and FM-210):** `aria-busy` on placeholders that load after
  mount in parts a step highlights: the Home Facility name, the pending-email check and the role table's
  node and facility names (`Pending`).
- **Out:** the Change Password dialog and reset dialogs (portalled; steps describe them); no pager step;
  no screen changes beyond attributes and wrappers.

## Summary

The account pages get a Show Guide button. On Profile the guide explains changing the password, the
three sections, the user's own details and email verification, their roles by type (with what "Ignored:
No Home Facility" means) and how notifications are delivered. On Settings, shown only to administrators
where the deployment turns it on, it explains the sections, branding with its preview, the colour theme
and default appearance for everyone, the feature flags and Reset To Defaults. Each page plays only the
steps for what it shows; Save and Reset steps play only when those buttons can be used. Legacy has no
guide.

### Rules

- Disabled controls carry no anchor (Save, Cancel and Reset are disabled until something changes).
- Tall parts (details, notifications, branding, theme, flags) are spotlit while the tooltip hangs from
  the control above them (vault: a `top` or `bottom` tooltip on a tall target leaves the screen).
- Order follows the page: header action, tabs, content top to bottom, footer.
- Copy is checked against the code: Change Password signs the user out after saving; Settings apply to
  everyone; each user can still change their own appearance with the theme button in the menu; the
  logo is also the browser tab icon. Arabic quotes UI labels with «», as earlier tours.
- `roleTypes` sits in RoleTabs, so the admin Edit User Roles page gets it too; no admin step uses it.
- Copy says Settings apply to everyone, and that each user can still pick their own appearance.

- `roleTypes` and the `Pending` busy marker sit in shared users components, so the admin Edit User
  Roles page gets them too; no admin step uses `roleTypes`, and busy only makes its guide wait.

### Risks

- Post-mount loads: the pending email alert can push the details down, and Home Facility and role node
  names show placeholders inside spotlit parts; these get `aria-busy` (Scope). Role tab counts and the
  settings background refetch stay unmarked: no step targets them and they do not move the anchors.
- Settings with the endpoint missing shows Settings Not Available with no tabs: the guide says it is
  not available (onboarding review toast).
- Notifications without contact details or configurations show an empty state: the step drops.

## UI/UX

- **Improve:** a guide where legacy has none.
- **Phone:** tabs wrap one per row; roles and notifications become cards.
- **Arabic:** placements mirror through the module.

## Decisions

1. **One tour per page group**, played by each tab route: `WorkspaceTabs` are links, so a step cannot
   switch them.
2. **Own copy for searches and Save:** the shared search and admin Save texts mention codes and lists
   that these pages do not have.
3. **Legends:** email Verified / Not Verified and the Ignored role badge, drawn as the screens draw them.
4. **`aria-busy` on late placeholders** inside spotlit parts (Scope), as FM-208's Create Orders form.
5. **PR description** names the shared changes: `roleTypes` in `RoleTabs`, `Pending` busy in the role
   table.
