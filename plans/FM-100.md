# FM-100: Equipment Details And Edit

https://openlmis.atlassian.net/browse/FM-100 · Parent: FM-97 Cold chain equipment

## Scope

- Details dialog over CCE Inventory, opened by View (`?item=<id>`); replaces the legacy details
  link.
- Edit dialog in place of the details (`?item=<id>&edit=true`), reusing the FM-99 step two.
- Update Status in the details opens the legacy status modal until FM-101; the list's status
  button keeps its legacy link.
- Not in scope: status update, RTM alerts, history, transfer (FM-101).
- No backend change. Builds on `feat/fm-99-add-equipment` (PRs #122, #125). Kept small: reuse
  FM-99 parts, tests for workflows only.

Research baseline, 2026-11-03: legacy walked on the local ref-distro as administrator, divo1,
vsrmanager1, wclerk1, every write stubbed. Evidence in `.screenshots/FM-100/`.

## Summary

Managers open a piece of equipment from the inventory to see what is recorded about it and to
correct its details.

Legacy shows the details in a modal and edits them in a second modal with the add form. Edit
works on the copy the list loaded, so a change made by someone else meanwhile is overwritten
without warning; errors appear only after Save behind a blocking dialog; a direct edit link
without the right shows a blank page.

The new UI does the same in two dialogs over the list, kept in the URL. Edit reads the item
fresh, saves only the fields it edits and returns to the details, with the change visible there
and in the list.

## Legacy Today

- Details `#!/cce/inventory/<id>/details?<list search>`: reference name; status dot and label,
  modifier name (only from the list) and `dd/MM/yyyy HH:mm:ss`; Update Status and Transfer for
  EDIT / TRANSFER on the item's pair; District (facility zone), Facility, Program, Equipment
  Type, Net Volume "38 liters"; Identification (Make/Model, Serial Number); History (Utilization,
  Year of Installation, Source and Warranty only when set); Installation (stabilizer, generator,
  regulator, gauge, RTM); Additional Notes when set; Close, Edit for EDIT. Reason and
  decommission date are not shown.
- Edit `#!/cce/inventory/<id>/edit` ("Edit Equipment Details"): read-only District, Facility,
  Program, Type, Make/Model; editable identification, history, installation and notes; no status
  fields. Power fields disabled for SOLAR and NOT_APPLICABLE. Dirty Cancel asks; Save sends the
  whole list copy and returns to the details.
- vsrmanager1 (VIEW): details with Close only; edit URL blank. wclerk1: 403. Nobody on the demo
  data has CCE_INVENTORY_TRANSFER.
- Arabic and 390px: labels run into values, time reversed.

## Agent Brief

### API Map

| Step | Method and path | Params | Fields used | Right | Legacy ref |
|---|---|---|---|---|---|
| Details, edit | `GET /inventoryItems/{id}` | `expand=lastModifier` | all; `catalogItem` embedded; `facility`, `program` ids | exact VIEW for the pair, else 403; 404 | `cce-inventory-factory.js:52-67` |
| District, Facility | `GET /facilities/{id}` | | `name`, `geographicZone.name` | authenticated | `cce-inventory-factory.js` |
| Program | `GET /programs/{id}` | | `name` | authenticated | `cce-inventory-item.routes.js:33-42` |
| Save | `PUT /inventoryItems/{id}` | body id = path id | whole record | exact EDIT for the stored pair, else 403 | `cce-inventory-item.service.js:105-112` |

- PUT replaces every mutable field; an absent field becomes null. `facility`, `program`,
  `catalogItem` are required but ignored. Same 400 rules as POST. No versioning: last write wins.

### Data Flow

- `inventorySearchSchema`: `item` becomes `'new'` or a GUID (anything else is dropped); `edit: true` optional; both in
  `CLOSED_INVENTORY_DIALOGS`. The loader drops `edit` without any EDIT grant, as `item=new`.
- Details read fresh per opening: `inventoryItemOptions(id, opening)` under
  `inventoryItems.detail(id)`; facility and program from reference-data `facilityOptions`,
  `programLookupOptions`. Not prefetched.
- Edit replaces the details in the same dialog (replace, history state kept); Save rereads the
  item, applies the form's fields, PUTs and waits for `inventoryItems.all` to refetch, then
  invalidates `home.all`, toasts and goes back to the details. Cancel goes back to the details.
  A refused item read shows the no-access message.

### Rules

- Edit and Update Status for EDIT on the item's pair.
- Read-only on edit: District, Facility, Program, Type, Make/Model.
- Status, reason, decommission date and `remoteTemperatureMonitorId` come from the fresh record.
- Power fields disabled for SOLAR and NOT_APPLICABLE; shown and saved as Not Applicable only for
  SOLAR on edit and in the details, as legacy, so NOT_APPLICABLE models keep their stored values;
  Add still prefills Not Applicable for both (FM-99). A failed refetch after the PUT shows the
  save error, so the form never shows a stale copy.
- Source, Warranty and Notes rows only when set; Net Volume as "{value} liters".
- No code comments; types hold only the fields the screens read.

### Translations

### Risks And Edge Cases

- Last write wins; the fresh read narrows the window only.
- Demo items without a serial number need one before saving, as legacy.
- An item whose model is archived keeps its own catalog item.

## UI/UX

**Port**: every legacy field, order and conditional row, status with modifier and time, Update
Status, Edit, read-only edit header, rights per item.

**Improve**: dialogs in the URL (reload and shared links); reason and decommission date with the
status; modifier also on direct links; fresh read on edit, inline validation, saved toast; labels
and values on separate sides at every width and in Arabic.

**Drop**: none. Transfer comes with FM-101.

States: loading skeleton, not found, no access, load error with retry, saving, server error.

## Decisions

- **Review (Oliver, 2026-11-05)**: Equipment Details as the title with the equipment name beside
  the status badge; `table` width; compact read-only rows (`SettingsList density="compact"`);
  legacy section rules for Identification, History and Installation. Edit opens as a stacked
  dialog over the details (the shared nested-dialog shrink, dim and blur) in one column; Cancel
  and a saved edit step back to the details. Skeletons follow the same layout.
- **Details and edit as dialogs, as the ticket** (user, 2026-11-03); edit replaces the details.
- **Update Status opens the legacy modal** until FM-101 (user, 2026-11-03).
- **Reason and decommission date shown in the details** (user, 2026-11-03), though legacy omits
  them.
- **Fresh read and merge on save** instead of legacy's list copy.
- **Small PR**: reuse FM-99 parts; tests cover workflows.
