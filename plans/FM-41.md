Built on the read-only page from [FM-44](FM-44.md) in the same PR (#114), as the user decided on

## Scope

- Editing on `/requisitions/view/$requisitionId` for INITIATED and REJECTED (CREATE) and SUBMITTED
  (AUTHORIZE) records: user-input cells, losses and adjustments, line skip, Add Comment, non-full
  supply Add Product, emergency full supply Add Product, unskip of hidden skipped lines.
- Device autosave, Save/Sync, Submit (or Submit And Authorize), Authorize, Skip, Delete and
  edit-mode Print in a sticky footer; the physical stock count date prompt before Submit and
  Authorize; outdated and conflict handling.
- Not in scope: approve mode ([FM-43]: approved quantity, remarks, Approve, Reject), the Patients
  tab ([FM-42]), offline opening of requisitions ([FM-39] step 12). Records an approver opens, and
  records on templates with the Patients tab, stay read-only with the legacy note until those
  stories ship.

## Summary

Facility staff fill in a requisition: what they had, received, used and lost, and what they need.
Legacy keeps every keystroke in the browser, shows "All changes are saved" when that local copy is
written, and only sends the requisition to the server on Save/Sync, Print, Submit or Authorize.
Submit, Authorize, Skip and Delete each ask for confirmation, then return to the previous page.

The new page works the same way and looks like the Stock editors. Edits are kept on the device as
the user types (the status reads Saved On This Device, as Physical Inventory), so a reload or a
crash never loses work. Save/Sync sends the draft to the server; Submit and Authorize save first.
Mistakes are highlighted in their cells as the user types, as legacy, with the message on hover,
and an invalid Submit opens a dialog that jumps to the first problem, as on the Stock screens.
Leaving keeps the device copy, so nothing is lost. If someone else changed the requisition
meanwhile, the page says so and offers to load their version; the local edits are kept until the
user chooses.

## Legacy Today

Researched 2026-10-28 on test as administrator and srmanager2 (Comfort Health Clinic, Family
Planning), screenshots and captured requests in `.screenshots/FM-41/` (`shots/`, `data/`).

- **Comments**: Add Comment opens an inline textarea "Add a comment about the changes you have
  made" with Remove Comment (no confirmation). It is `draftStatusMessage` on the requisition, sent
  with every save; Submit and Authorize turn it into a status message with author and date.
- **Grid**: inputs per user-input column; calculated cells update about 0.4 s after a change;
  inputs keep digits only ("ab-1.5x" stores 15); errors show at once on change, red cell with an
  icon and a hover popover; the tab label gets an error icon.
- **Skip**: Skip All, This Page, None above the grid and a checkbox per line, enabled only when
  every shown user-input cell is empty (0 counts as data, so demo records cannot skip).
- **Losses and adjustments**: dialog with Reason, Quantity, Add; table Reason, Quantity, Remove;
  live Total; Cancel and Update. Reasons from the record's snapshot minus hidden ones and those
  already on the line; quantity above 0.
- **Packs/Doses**: Packs shows `[packs] ( + [doses] )`; stored in doses; the PUT carries
  `quantityUnit`.
- **Non full supply**: Add Product opens a dialog (search by name or code, Select, Code, Product,
  Unit of Issue, pager, no quantity) over the record's `availableNonFullSupplyProducts`; "There
  are no more products to add..." when empty (test has none). Added rows have Requested Quantity
  and Explanation (255) and a trash button, instant.
- **Indicator**: "Saving changes", then "All changes are saved" after a timer; it reflects the
  local copy only.
- **Footer**: Save/Sync with Server at the start; Skip, Delete, Submit (or Authorize) at the end.
  INITIATED shows Save/Sync, Skip, Delete, Submit; SUBMITTED shows Save/Sync, Delete, Authorize.
  All disabled offline.
- **Actions**: see the API map; each returns to the previous page about 3.6 s later.
- **Reload**: grid edits survive from localStorage; a comment typed under a second before reload
  is lost; a newer server copy shows "This is an outdated offline version" with Update. No leave
  prompt anywhere.

Defects to fix: no leave prompt; the indicator never reflects the server; product filter empty
text says nothing was added; the Add Product breadcrumb reads "Kit Unpack List"; footer buttons
cover rows on phones; failed Sync tells users to clear local storage; 409 drops local edits.

## Agent Brief

### API Map

All under `/api`; legacy refs in `/tmp/fm39-src/openlmis-requisition-ui/src/`.

| Step | Method and path | Params and body | Right | Legacy ref |
|---|---|---|---|---|
| Read | `GET v2/requisitions/{id}` | Keep the `ETag` response header and `modifiedDate` | VIEW | `requisitions.service.js:110` |
| Save/Sync | `PUT v2/requisitions/{id}` | Header `If-Match: <ETag>` when available; body: the record as `transformRequisition` builds it (below) | CREATE (INITIATED, REJECTED), AUTHORIZE (SUBMITTED) | `requisition.js:808-845`, `requisition-view.controller.js:321-331` |
| Submit | `POST requisitions/{id}/submit` | Header `Idempotency-Key`; body `{}`; after a successful PUT | CREATE | `requisition-view.controller.js:382-430` |
| Authorize | `POST requisitions/{id}/authorize` | Same, after PUT | AUTHORIZE | `:432-469` |
| Skip | `PUT requisitions/{id}/skip` | `Idempotency-Key`; no save first | CREATE | `:597-611` |
| Delete | `DELETE requisitions/{id}` | 204; the backend ignores `Idempotency-Key` | DELETE plus CREATE or AUTHORIZE by status | `:481-496` |
| Print (edit) | PUT, then the existing print | | as Save, then VIEW | `:345-364` |
| Add Product | `POST orderables/search` `{identities}` (`orderablesByIdentitiesOptions`) | The record's `availableProducts`, split by the program entry's `fullSupply` (non-full tab: non-full; emergency full supply tab: full supply; hidden skipped lines: the skipped products), minus present lines; new lines take `pricePerPack` from the program entry | none | `requisitions.service.js:490-498`, `:531`, `requisition.js:574-583` |

PUT body (`transformRequisition`): the whole record with hidden and calculated columns set to null
except `numberOfPatientsOnTreatmentNextMonth` (`requisition.js:865-868`), `orderable` cut to
`{id, versionNumber}`, `program` and `facility` to `{id}`, without `template`, `availableProducts`,
`stockAdjustmentReasons` and any client-only field; keeps `draftStatusMessage`, `modifiedDate`,
`datePhysicalStockCountCompleted`, `extraData`, `patientsData` (the backend overwrites it from the
body, `Requisition.java:438`). Emergency requisitions only transform columns in the emergency
subset; values outside it are sent as stored. Packs/Doses is client-only (`useQuantityUnit`), never
sent.

The PUT response returns the full record and the new `ETag` (`RequisitionV2Controller.java:155-158`).
Errors: 400 `{field: {messageKey, message}}` (line errors are not per cell) in a dialog; 403
`requisitionView.updateForbidden`, then reload; 409 on `modifiedDate` or ETag mismatch
(`RequisitionVersionValidator.java:45-52`, `BaseRequisitionController.java:266`) keeps the edits
and offers Update; 409 "key already used" (`GlobalErrorHandling:202`) after a timed-out Submit or
Authorize means it may have gone through, so refetch the record and show its status. A new
idempotency key after a received non-409 error response; retain it after network errors or timeouts
without a response.

### Data Flow

- Route as now (blocks on the record, `preload: false`, fresh fetch on enter). `fetchRequisition`
  also returns the `ETag`.
- One TanStack Form draft above the tabs (`useRequisitionForm`), keyed by line id:
  `{ lines: Record<lineId, LineDraft>, addedLines, removedLineIds, draftStatusMessage,
  datePhysicalStockCountCompleted }`; tab and page switches never remount it. Display values come
  from `calculateLine` over the changed line only.
- **Device draft**: Dexie table `requisitionDrafts` (schema version 14), owner-scoped through
  `local-records.ts`, written by `createDraftWriter` with revision checks (`draft-store.ts`), as
  Physical Inventory. Each row holds the draft, the base `modifiedDate` and `ETag`. On open: a
  draft whose base equals the server's `modifiedDate` loads; an older base shows the outdated
  alert, as legacy, with Update (discard local, load the server copy). The draft stays until the
  user chooses; a 409 from Sync offers the same Update. Plain HTTP
  (`isSecureOrigin` false): no device draft.
- Sync: flush, `requireOnline`, PUT with `If-Match` when available; adopt the PUT response and
  its `ETag` as the new base (no refetch), revision-check the device write so edits made during the request stay,
  toast. Submit and Authorize: validate, all-skipped check, stock count date when required,
  confirm, Sync, POST, toast. After Submit, Authorize, Skip and Delete: stop pending autosaves,
  clear the device draft with a revision check, invalidate `queryKeys.requisitions` and Home,
  navigate back.
- Line drafts store only changed user-input fields, skip state and adjustments. Rebase against the
  PUT response removes saved additions and removals and keeps edits made during the request.
- Outdated drafts pause writes without failing the writer. Update discards the local copy, adopts
  the server base and resumes autosave.
- `useSessionMutation` for every write; `assertSessionScope` after each await (AGENTS.md Identity
  isolation).
- `useDiscardGuard(dirty, { pending, flushBeforeLeave })`, as the Stock editors: a flushed device
  draft leaves silently and is kept; a failed flush, or plain HTTP with no device draft, asks.
- URL adds `addProduct` (dialog key) to the existing search.

### Validation

`lib/validation.ts`, pure, rules from [FM-39] Rules plus `requisition-validator.factory.js:129-285`:
skipped lines never validate; required user-input columns; SOH and consumed not negative (shown on
the calculated cell too); both user input must balance with their calculation (not on stock-based
templates); requested quantity rules; the explanation only on full supply lines
(`validation.factory.js:104`) and never sent while its column is hidden (`RequestedQuantityValidator`);
non-full lines validate only the non-full column subset; stockout days at most 30 times the
period's months; whole numbers up to 2,147,483,647 (`wholeNumberText`); explanation 255;
adjustment quantity above 0. Submit and Authorize also need one non-skipped line and, on regular
requisitions whose program enables it, a stock count date not in the future
(`DatePhysicalStockCountCompletedValidator.java:56`).

Errors show as the user types, as legacy: the form validates on change from the start. This is a
recorded exception to AGENTS.md's submit-first `revalidateLogic` for the requisition editor.

### Rules

- Capability fixes from legacy: Skip needs no template skip column (`requisition-view.factory.js:170-177`);
  Sync for approvers follows the node check, as Approve ([FM-43]). Comments follow `$isEditable`
  (`requisition.js:493-519`); an AUTHORIZE-only user on INITIATED can type a comment but has no Sync
  or Submit, as legacy.
- Line skip only when every shown user-input, non-boolean cell is empty; 0 counts as empty
  (`line-item.js:231-238`).
- Non-full lines can be removed while the record is editable, whether added now or saved
  ([FM-39] Rules, fixing legacy's transient flag); full supply lines, emergency ones included,
  never (`requisition-validations.decorator.js` `deleteLineItem`).
- Every write sends the draft as of the last flush; no write while another is pending.

## Decisions

- **Save/Sync** (AC): local autosave to Dexie on every change; Save/Sync writes the server with
  `If-Match`; Submit, Authorize and edit-mode Print save first; Skip and Delete do not. As legacy
  and [FM-39].
- **Built in PR #114** with [FM-48] and [FM-44] (user, 2026-10-28).
- **Footer order** follows Physical Inventory.
- **Validation timing**: live from the first change, as legacy (user, 2026-10-28); an AGENTS.md
  exception for this editor.
- **Test writes**: fresh requisitions may be initiated on test.openlmis.org (user, 2026-10-28).
- **Patients templates** stay read-only with the legacy note until [FM-42], since Submit must
  validate the Patients grid.
