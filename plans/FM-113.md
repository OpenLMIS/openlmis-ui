# FM-113: Reports List

https://openlmis.atlassian.net/browse/FM-113 · Parent: FM-111 Reports

## Scope

Implement View Reports at /reports: rights-gated navigation, grouped category cards,
complete catalogs, loading/empty/error states and links to the existing report screens.
The user approved starting this story on 14 November 2026. Jira is assigned to Oliver
Lewandowski and In Progress. The branch starts from master 4fc47c01.

FM-114 owns native parameters/output and FM-115 owns native dashboard viewing. Until
those ship, links hand off to the existing legacy parameter/dashboard routes in the
same tab, with the app's leave guard. Show this behavior in a short page notice; legacy
may require its own sign-in, as existing session rules specify. Do not create empty
native destinations or silently include those larger stories here. Home embedding and
administration are outside this story.

## Summary

Users can find their reports in the new UI, grouped under the same category names as
legacy. Only nonempty categories appear. Selecting a report opens its existing parameters
screen, or its dashboard. Those destination screens will migrate in the following stories.

The page keeps its heading visible while catalogs load and gives useful retry and empty
states. Independent source failures are shown explicitly while successful report sources
remain usable. The screen works on phones and in Arabic.

## Legacy Today

See [FM-111](FM-111.md#legacy-today) for the dated live inventory and evidence. The entry
is /#!/reports/list. Its one Default Category contains Stock On Hand, Facility Assignment
Configuration Errors, Periodic Stock On Hand Summary, Sample Requisition Report, Timeliness
Report and Reporting Rate Report. No dashboard is available to that demo user, although
seven enabled dashboard records exist administratively. Never substitute the admin list.

Legacy groups by category name, creates empty boxes and assumes Default Category exists.
The new page groups by ID, preserves returned category/report order and uses a safe fallback
for uncategorized reports. No report is lost because its category metadata is absent.

## Agent Brief

### API Map

| Step | Method And Path | Params | Fields Used | Right / Source |
| --- | --- | --- | --- | --- |
| Guard | GET /api/users/{userId}/permissionStrings | Existing auth options | rights | REPORTS_VIEW |
| Categories | GET /api/reports/reportCategories | Unpaged catalog request | id,name,content,totalElements,totalPages | Authenticated lookup; no admin right |
| Module catalogs | GET /api/reports/templates/{module} | common,requisitions by default | id,name,description,category | REPORTS_VIEW |
| Dashboards | GET /api/reports/dashboardReports/availableReports | showOnHomePage=false; unpaged request | id,name,category,type and page metadata | REPORTS_VIEW plus per-dashboard server filtering |

Pinned contracts and legacy references are in [FM-111](FM-111.md#api-map). Dashboard
backend filtering is paged twice, so a client page loop does not guarantee completeness.
Request its supported unpaged form and reject an incomplete result with a retryable error;
do not silently display a partial dashboard catalog or use management discovery.

Template modules are deployment-configured: add runtime reportingModules with validated,
deduplicated module names and common,requisitions defaults. Pass through the deployment
configuration; no hardcoded environment hostname or database report IDs.

### Data Flow And Files

Authorization blocks first. Prefetch categories, each module and available dashboards in
parallel without awaiting prefetchQuery. The Workspace/header renders immediately. Catalog
readers use shared query options; loading/error handling is independent per source so a
failed dashboard service does not blank successful Jasper reports. A failed category lookup
keeps known report-provided category names and shows its error rather than losing links.
Empty means all sources finished successfully with no reports, not a failed request.

Add features/reports/api/{api,queries}.ts, lib/{types,report-categories}.ts and the catalog
component; add the protected /reports route. Register separate template/category/dashboard
query roots, REPORTS_VIEW and its nav mapping. Scope catalogs to the signed-in user and
abort/ignore obsolete-session multi-request work. No data goes into offline storage.

Use existing Workspace, Card, Button/link, Skeleton, Empty, translated errors and the
legacy navigation/leave-guard helpers. Categories are not an administrative management
screen, so keep these reads feature-owned until an actual shared consumer exists. No
feature-to-feature imports except reference-data. Do not edit generated route-tree code.

### Rules And Tests

- Stable category IDs prevent merging namesakes. Preserve order: template modules, then
  available dashboards; no invented sort/search/page controls.
- A missing category uses the returned Default Category when available, otherwise a
  translated Other Reports group. Orphaned explicit categories retain their names.
- Encode modules/IDs in legacy hashes; no tokens in URLs. Do not publish new-UI credentials
  to legacy storage. Normal clicks pass the leave guard; modified clicks remain links.
- Keep backend filtering authoritative for available reports; template-specific generation
  rights remain enforced at the existing output screen/server.
- Tests first: grouping/fallback/order and empty-category behavior, rejection of incomplete
  dashboard results, link destination selection, route guard and partial-failure recovery.
  Reuse existing framework, permission and leave-guard tests; do not test stock components.
- Sync new reports.* copy across all five catalogs with sync-translations. Server names,
  category names and descriptions remain configured content, not invented translation keys.

## UI/UX

Default-width Workspace, report icon, View Reports title and one-sentence description.
Category cards stack below the existing container threshold and use two columns when
space permits. Long names and descriptions wrap; link icons respect RTL. A short notice
explains that report screens open in legacy for now. Each report is a keyboard-accessible
link. Loading uses category skeletons; each source failure has a labelled retry; an empty
catalog has an explicit message. Successful report links stay available during failures.

## Decisions

Approved: implement View Reports now, preserving the current reporting services.
Implementation sequencing: functional legacy destinations until FM-114/115 replace them.
No dashboard embedding, output generation, report redesign or country-gap claims here.

## Open Questions

No unanswered question blocks the catalog. Actual Superset access and country requirements
remain the integration/product gaps documented in FM-111 and FM-112. If a deployed server
cannot return a complete dashboard catalog, show the source failure and scope its backend
repair separately rather than claiming incomplete data is parity.
