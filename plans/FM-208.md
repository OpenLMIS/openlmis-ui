# FM-208: Onboarding Tour: Requisition Workflows (Initiate, Approve, Convert, Create Orders)

https://openlmis.atlassian.net/browse/FM-208 · Parent: [FM-199] Guided onboarding tours for new users
(React Joyride, isolated module)

Stacked on FM-207 (PR #157).

## Scope

- **In:** six tours, one per route:
  - Create/Authorize (`/requisitions/initiate`);
  - Approve (`/requisitions/approve`);
  - Batch Approval (`/requisitions/approve/batch`);
  - Convert To Order (`/requisitions/convert`);
  - Create Orders (`/requisitions/create-orders`);
  - the order drafts editor that Create Orders opens (`/requisitions/create-orders/$orderIds`).
- **In:** `data-tour` attributes on loaded parts of these screens, plain wrapper divs where a part has
  no single root, and new keys in `TOUR_ANCHORS`. Shared `list-*` anchors from FM-207 are reused.
- **Out:**
  - module changes: the runner already skips missing parts, waits for loading and highlights columns;
  - dialogs (confirmations, summary, invalid submit): the steps describe them;
  - the selection bars on Approve and Convert: they appear only after ticking, so the selection step
    describes them.

## Summary

The Requisitions screens where users create, approve and convert requisitions get a Show Guide button,
like View Requisitions already has:

- **Create/Authorize:** pick the facility and program, choose Regular or Emergency, Search, then use
  Proceed on a period to start or continue its requisition.
- **Approve:** filter by program, sort by authorization date, open a requisition with View; where batch
  approval is on, tick several and view them together.
- **Batch Approval:** the device copy and draft status, one column group per requisition, product
  totals, and Revert, Sync and Approve.
- **Convert To Order:** filter, pick the supplying depot on each row, tick rows, then Convert or Release
  from the bar that appears.
- **Create Orders:** program, requesting facilities, supplying facility and Create.
- **Order drafts:** one tab per facility, the order summary, adding products, quantities, and Delete,
  Save Draft and Create.

A screen shows only the steps for the parts it has. Legacy has no guide.

## Legacy Today

No guide (FM-200).

## User Flows

Steps say where each action leads, so a tour reads as part of the flow, not a single screen:

- **Create/Authorize:** Search, then Proceed opens the requisition (`/requisitions/view/$id`); Show Guide there
  starts its own tour (FM-200), and Back returns to this search.
- **Approve:** View opens the requisition, where Approve and Reject live; with batch approval on, ticking
  rows and View Selected opens Batch Approval.
- **Batch Approval:** Approve sends every approvable requisition and returns to the Approve list with its
  filters; Cancel returns without sending.
- **Convert To Order:** Convert or Release asks for confirmation; converted rows leave the list.
- **Create Orders:** Create opens the order drafts editor for the new orders.
- **Order drafts:** also opened by Edit on a Creating order in View Orders; Create shows a summary to
  confirm, sent orders leave the tabs, and the page goes back once none remain.

No user-flow notes or diagrams exist for Requisitions in the vault or `docs/` (BPMN exists only for CCE);
these flows are traced from the routes.

### Rules

- **No anchors on loading parts** (FM-204, FM-207): wrappers set `data-tour={pending ? undefined : ...}`.
  `BatchPending`, `CreatePending` and the order drafts `Pending` stay unanchored. Anchors sit on the
  control a step names, not a wider row.
- **Loading parts get `aria-busy`** (decision 4): without it the runner sees a loaded page with no
  anchors and gives up after 5 s. So does the Create Orders form while
  its programs or facilities load, or the tour starts without those steps (decision 7).
- **First match:** row anchors (`requisitionProceed`, `requisitionOpen`, `convertDepot`) mark every row;
  the runner takes the first.
- **Copy** (vault, Onboarding gotchas from FM-200..207):
  - true in both layouts: no "last column" or "on the phone"; say "on narrow screens";
  - labels exactly as each screen shows them in every locale (es/pt/fr Save vs Saved differ);
  - generic where one step serves several states (Proceed starts or continues; View may be
    unavailable offline).
- **Tests counting `[data-tour]`:** count only this screen's own anchors, since shared `list-*` anchors
  sit in Filters and View too.
- **Playwright:** `isVisible({ timeout })` does not wait; wait after clicking Show Guide.

## Decisions

1. **One tour file for the six screens:** they share copy patterns; separate ids per route.
2. **Reuse `requisitionsPicker` on Create/Authorize:** same picker as View Requisitions.
3. **No steps inside dialogs or the selection bars:** they open on user action; steps describe them.
4. **`aria-busy` on loading parts** (user, 2026-11-19): `CreatePending`, the Create Orders lookup fields
   and Approve's toolbar fallback, so the tour waits for loading instead of giving up after 5 s. Like
   `CardListSkeleton` in FM-203. Route pending components (`BatchPending`, order drafts `Pending`) need
   none: the launcher mounts the runner only once navigation settles.
5. **Approve with the batch flag off** (the default): the select step drops.
6. **List steps hang from View** (Approve, Convert, Batch cards): a tall list leaves no room for a tooltip
   above it, which cut the tooltip off at 390; as FM-205, the tooltip hangs from the control above.
7. **Create Orders form busy while its lookups load** (review): `aria-busy` on the form while programs or
   facilities are pending, so a guide started then waits for all four steps.
