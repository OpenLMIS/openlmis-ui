# FM-171: Spike: Where the App Configuration Lives

https://openlmis.atlassian.net/browse/FM-171 · Parent: FM-170 Global app configuration
(branding, theme & feature flags)

## Scope

This spike decides and records the storage and API, and specifies the referencedata change
precisely enough to build. The backend code itself is a PR in `openlmis-referencedata`
(see Open Questions for who opens it). Nothing in this repo changes except this plan and,
at the end of FM-172, `docs/deployment/deployment.md`.

## Summary

The new UI needs one place to keep the logo, app name, theme and feature flags, which
everyone can read (the login page shows the logo before anyone signs in) and only an
administrator can change. No OpenLMIS service has anything like it: the few "settings"
tables in requisition, fulfillment and report are unused, the settings services read
environment variables, and there is no file store for a logo.

We add one small configuration record to referencedata, the service that already serves
the other public setting (`/localeSettings`), already records who changed what, and already
knows the System Settings right. The logo is stored next to it in the database, so backups
and restores carry it with everything else.

## Legacy Today

- No UI setting is stored anywhere. Legacy reads `GET /localeSettings` (public,
  `Cache-Control: no-store`, no `ETag`) after sign in and keeps it in localStorage
  `openlmis.localeSettings`.
- Feature flags are container env vars; referencedata separately has four Togglz flags in
  Redis. The Togglz console and `/actuator/togglz` are public: `GET /actuator/togglz`
  answers 200 with no token on test.openlmis.org, and `togglz.console.secured=false` means
  the console can flip them too.
- Evidence (referencedata at `31a49fe`): `web/locale/LocaleController.java`,
  `security/ResourceServerSecurityConfiguration.java:89-100`,
  `db/migration/20170209091631201__create_system_settings_manage_right.sql`,
  `application.properties:96`. The report service still declares a dead
  `GET /api/settings/{key}` in its RAML (`openlmis-report/.../api-definition.yaml:661`),
  which Consul routes to report, so the new resource must not be called `settings`.

## Agent Brief

### API Map (referencedata, new)

| Step | Method and path | Params / body | Response | Right |
|---|---|---|---|---|
| Boot, login page | `GET /api/appConfiguration` | `If-None-Match` optional | 200 body below, `ETag: W/"<version>"`, `Cache-Control: no-cache`; 304 when it matches | none (public) |
| Logo image | `GET /api/appConfiguration/logo?v=<sha256>` | | image bytes, stored `Content-Type`, `X-Content-Type-Options: nosniff` (from Spring Security), `ETag: "<sha256>"`, `Cache-Control: public, max-age=31536000, immutable` when `v` is the current hash, `no-cache` otherwise; 404 when none | none (public) |
| Save settings | `PUT /api/appConfiguration` | `If-Match: W/"<version>"`; body: `appName`, `theme`, `featureFlags`, `version` | 200 full body, new `ETag`; 400 validation, 403, 409 stale version, 428 no version sent | `SYSTEM_SETTINGS_MANAGE` |
| Upload logo | `PUT /api/appConfiguration/logo` | `multipart/form-data`, part `file`; `If-Match` | 200 full body with the new `logo`; 400 type, empty or size, 403, 409 | `SYSTEM_SETTINGS_MANAGE` |
| Remove logo | `DELETE /api/appConfiguration/logo` | `If-Match` | 200 full body, `logo: null`; 403, 409 | `SYSTEM_SETTINGS_MANAGE` |
| History | `GET /api/appConfiguration/auditLog` | standard `author`, `changedPropertyName`, `page`, `size` | Javers changes, newest first | `SYSTEM_SETTINGS_MANAGE` |

Response body. Missing or `null` fields mean "use the built-in default":

```json
{
  "version": 4,
  "appName": "OpenLMIS",
  "logo": { "url": "/api/appConfiguration/logo?v=9f2c...", "contentType": "image/png", "size": 48213 },
  "theme": { "preset": "blue", "defaultAppearance": "system" },
  "featureFlags": { "BATCH_APPROVE_SCREEN": true, "QUANTITY_UNIT_OPTION": "BOTH" },
  "modifiedDate": "2026-09-29T10:00:00Z"
}
```

```sql
CREATE TABLE app_configuration (
  id uuid PRIMARY KEY CHECK (id = '5c3d6b1e-0000-4000-8000-000000000001'),
  appname varchar(64),
  themepreset varchar(32),
  defaultappearance varchar(16) CHECK (defaultappearance IN ('light', 'dark', 'system')),
  featureflags jsonb,
  logosha256 varchar(64),
  logocontenttype varchar(32),
  logosize integer,
  version bigint NOT NULL DEFAULT 0,
  modifieddate timestamptz NOT NULL DEFAULT now()
);
CREATE TABLE app_configuration_logos (
  sha256 varchar(64) PRIMARY KEY,
  contenttype varchar(32) NOT NULL,
  data bytea NOT NULL
);
INSERT INTO app_configuration (id) VALUES ('5c3d6b1e-0000-4000-8000-000000000001');
```

The nullable columns are deliberate: a fresh row means "all defaults", and the UI's
defaults, not the database's, decide what that looks like.

### Rules

- `appName`: trimmed, 1 to 64 characters, no control characters, or `null` for the default.
- `theme.preset`: `^[a-z0-9-]{1,32}$` or `null`. Not an enum: the UI owns the preset list
  and falls back to the default for a name it does not know, so a new preset needs no
  backend release.
- `theme.defaultAppearance`: `light`, `dark`, `system` or `null`.
- `featureFlags`: at most 100 keys, each `^[A-Z][A-Z0-9_]{0,63}$`, each value a boolean or
  a string of at most 64 characters. Shape only: the UI registry owns names, types and
  defaults, so a new flag needs no backend release. A key left out of a `PUT` is removed,
  which is how one flag is reset.
- Logo: PNG, JPEG or WebP, detected from the magic bytes, not the extension or the
  declared type; 1 byte to 512 KB. nginx's default `client_max_body_size` is `1m` and
  answers larger bodies with an HTML 413 before Spring sees them, so the UI checks size
  first. SVG is refused: the file is served from the app's origin to every user.
- Version: `If-Match` or `body.version` must equal the stored version; neither gives 428,
  a mismatch gives 409. The same weak `W/"<n>"` ETag as requisition
  (`web/ETagResource.java` there).
- A request carrying an invalid or expired token on a permitAll path is still refused
  with 401 by Spring OAuth2, so the UI's boot read sends no `Authorization` header.

### Risks and Edge Cases

- Spring Security adds its own `no-cache` headers; the integration test must prove the
  logo's long cache header survives.
- Old logos stay in `app_configuration_logos` after a replace. Delete the previous row in
  the same transaction when no config points at it.
- Two admins saving at once: the second gets 409 and must reload; FM-173 shows that.
- A deployment running an older referencedata answers 404: the UI treats it as "no
  configuration" and uses defaults (FM-172), and the System Settings page shows that the
  server does not support it yet (FM-173).

## Decisions

1. **referencedata, not a new service.** It has the public-read precedent, Javers audit,
   Redis and the right. A new service means a new container, database schema, Consul
   registration and release train in every deployment, for one row.
2. **Not Consul KV.** It holds routing only, the browser cannot reach it, and it has no
   rights model or backup.
3. **Not Togglz** for UI flags. Its flags are a Java enum, so each new one needs a backend
   release, and its console is unsecured. It stays for backend behaviour.
4. **`/api/appConfiguration`**, one record. Avoids the dead `/api/settings` route, and does
   not end in `config.json`, which FM-175's service worker caches by suffix.
5. **Flags stored as a map of overrides**, validated by shape only; defaults, types and
   labels live in the UI registry (FM-176).
6. **Deployment env vars feed flags through the UI's `config.json`**, not the backend, using
   the legacy variable names, so existing `settings.env` files keep working (FM-176).
7. **Backend-enforced flags stay backend-only.** `CATCHMENT_POPULATION_CALC_AUTO` is read by
   referencedata once at startup in three places (`CatchmentPopulationAspect`,
   `GeographicZoneService`, `GeographicZonesImportPersister`). Letting the UI edit it would
   make the two disagree, so it is not in the UI registry. The Togglz flags are not shown.
8. **Logo in the database** as `bytea`, served with a content-hashed URL. No file store
   exists in the platform, and a database blob is backed up with everything else.
9. **Caching by `ETag`/304 and a hashed logo URL**, no Redis cache. A one-row primary-key
   read is cheap; the 304 saves the transfer.
10. **Everything in the response is public.** Flags and theme are not secrets by rule;
    The body carries no user data; the audit log records who changed what.

11. **SVG is refused for now.** Sanitising it server-side needs a library such as OWASP Java
    HTML Sanitizer and its own security review; a follow-up if deployments ask.

12. **The version is checked under a row lock, not with JPA `@Version`.** The save reads the
    row `FOR UPDATE`, compares the version the caller sent, and bumps it, so the check and the
    write cannot interleave and the new version is in the response without a flush.
13. **`PUT` for the logo upload**, multipart with a `file` part, since it replaces the one logo.

### Checked Against a Local Stack

Verified on ref-distro with referencedata `15.8.0-SNAPSHOT` built from master:

- Consul routes `/api/settings/{key}` to report and nothing to `/api/appConfiguration`.
- `administrator` holds `SYSTEM_SETTINGS_MANAGE` in the demo data.
- `GET /localeSettings` answers 200 with no token and 401 with an invalid one.
- Spring Security sends `Cache-Control: no-cache, no-store, max-age=0, must-revalidate` on
  public responses today; the integration tests prove the controller's own headers win.
- nginx runs with `client_max_body_size 1m`.
