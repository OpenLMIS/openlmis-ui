The combined PR delivers the shared picker and online Stock On Hand list: scoped access,
URL state, grouped product/card rows, filters, quantities, page-specific metadata and PDF
printing. Missing foundations are built with this first consumer, using existing app
patterns. There is no Data Import, stock-event editing, transaction history or backend work.

## Summary

Stock On Hand lets a storeroom manager choose a facility and program, find the products
with stock cards, inspect each product's lots and balances, and print a report. The new
view uses one responsive screen at every size. It avoids the legacy phone screen's full
product download, keeps searches and pages in the link, and gives each load a clear
loading, empty or retry state. The shared picker is built alongside it. Stock Card follows
soon in the new app; offline access follows in the later offline pass.

## Legacy Today

Desktop route is `/#!/stockmanagement/stockCardSummaries` with `facility`, `program`,
`supervised`, zero-based `page`, `size`, `includeInactive`, `productCode`, `productName`,
and `lotCode` search parameters. Legacy also has separate phone stock routes. The new
screen replaces both layouts without adopting the phone module's approved-product warmup.

The page has a shared facility/program selector and Search, a product/lot filter form,
Include Inactive Items, a Packs/Doses toggle, Print, and server-page navigation. Product
headers show code, product, pack size and quantity. Child rows show their own code,
product, pack size, lot code or No Lot Defined, expiry, last update, quantity and View.
Children may be substitute products, not simply lots of the header product. Last Update
is `occurredDate`, not processing time. Children sort by lot code with no-lot first.
There is no user-selectable product-group sorting in this contract.

The separate React phone screen shows product code/name/total, expandable lot/quantity
rows, filters and a product/card detail destination. Preserve its group Expand/Collapse
capability in the responsive view, using accessible controls instead of clickable icons.
Its stored expansion choices are presentation state, not server paging or permission data.

Legacy maps screen filters to v2 summary params, hydrates only the returned page, filters
inactive children locally, removes groups with no remaining children and keeps server
pagination totals. Its omitted inactive param includes all children even while its initial
checkbox looks unchecked. Its Doses parent total can include hidden inactive children;
Packs sums visible children. These behaviors must be explicit rather than hidden in a
generic normalization step.

### Data Flow And URL

Route `/stock-management/stock-on-hand` lives under the protected layout. Add its Stock
On Hand navigation entry and `STOCK_CARDS_VIEW` gate only; other Stock placeholders stay
hidden. Entry authorization blocks. Without a complete context, render the heading and
selector, with no stock request. A complete context blocks only for FM-18's scoped option
validation, then prefetches the summary without awaiting it. Only the result subtree
suspends behind QueryBoundary; the selector and filter controls remain mounted.

Validated search holds `mode`, `facilityId`, `programId`, `productCode`, `productName`,
`lotCode`, `includeInactive`, one-based `page`, and `size`. No sort controls/params are
offered without endpoint support. Use existing text and pagination validation; add a
pagination-only schema/helper if necessary rather than inventing a fake sort field.
Subtract one for API page. Defaults stay out of the URL except normalized selector mode.

Search is an explicit form submit for the picker, as legacy. Keep a transient controlled
selector draft initialized from the URL's applied selection. Mode/program changes clear
incompatible draft choices; Search atomically commits the validated mode/facility/program
and resets page in the URL. The URL is the sole persisted applied-query authority; no
extra `searched` flag is needed. A complete authorized shared/reloaded URL loads results.
Reset the draft when applied URL state changes through Back/Forward or an external link.
While draft context differs from applied context, hide the previous rows and disable Print
with a Search hint; never request or act on an unsubmitted context. A reload before Search
returns to the last applied URL selection, matching legacy.

Text filter changes use replace navigation and reset page; with an applied complete
context they update the active query. Paging adds history. Preserve filters when Search
commits another context. Use latest-state updater functions for rapid transitions and
suppress old-context actions while scoped validation is pending. Repeating Search can
refresh the current applied query. Print always reads the validated applied URL context.

Query scope is `queryKeys.stockCardSummaries`. Its raw page key contains authorized user
ID, facility/program, server filters, page and size. Hydration reuses sorted/deduplicated
`orderablesByIdsOptions`; add shared `lotsByIdsOptions` under the lots scope. Unit and
inactive visibility do not change server data, so derive them locally without refetching
the summary or altering raw keys. Defer filter/page result rendering with current search,
but immediately suppress old-context actions during scope/context changes or lost grants.
No startup approved-product fetch, no all-pages summaries warmup, no request on unit toggle.

### Server And Client Work

- v2 supplies product grouping, code/name/lot searching and response paging. Do not page
  individual lot rows or count lots as product groups. Backend builds all summaries before
  slicing its response; measure time/payload rather than promise database-level paging.
- Only hydrate returned-page parent and child IDs. Skip empty ID arrays. Make hydration
  explicit in the shared by-ID APIs: deduplicate IDs, split into batches of at most 100,
  request `page=0&size=100` with repeated `id` for each batch, then read further lookup
  pages until the response's `totalPages` is exhausted. This handles server page-size
  caps without fetching unrelated IDs or creating an oversized query string. Deduplicate
  collected metadata by ID; latest product versions come from the verified ID endpoint.
  Apply this to existing `fetchOrderablesByIds` and the new lot lookup. Test a batch
  larger than the server's default/capped page size and a group with more than 100 IDs.
- `nonEmptyOnly` means at least one card child, not positive stock. Keep zero/negative
  balances and no-lot cards. Substitution means children can have different pack sizes.
- Sort children by lot code with no-lot first. Preserve server product-group order; no
  local sorting of one page masquerades as global product sorting.
- Local inactive filtering and label lookup remain necessary because the API has no
  equivalent inactive-filter parameter. Do not download every server page to hide gaps.

### Inactive Items, Counts And Quantities

Use a boolean Include Inactive Items control with **effective default true**. Legacy's
omitted value also includes everything; render this honestly as on instead of copying
its unchecked-but-unfiltered initial checkbox. Explicit false keeps only `active===true`
children and drops empty groups. This is a named UX correction to the default indicator,
not a change to the effective default result set. A false URL param must survive reload.

Keep server `totalElements` for product-group pagination; label that count as matching
products before inactive filtering when the filter is off, with the visible group count
for this page. Do not claim it is the number of visible lots or active products. A page
emptied locally still shows "No products found." with an explanation and navigation to
other server pages/Include Inactive. Do not clamp based on local row count; clamp only
against server page bounds.

Use existing `useFlag/getFlag`: flags are already implemented, not new plumbing.
`DEFAULT_QUANTITY_UNIT` defaults DOSES; a saved user preference overrides it.
`QUANTITY_UNIT_OPTION` defaults BOTH and controls toggle visibility only; a single option
does not force the displayed unit. Define the new app's preference with its existing
stored-state convention, separate from legacy storage, and do not alter legacy caches.
Keep the chosen unit when switching pages/filters and feed it to Print.

Shared quantity utilities preserve legacy arithmetic and visible text, localized where
appropriate, using canonical backend doses without overwriting DTOs:

- Doses children show their own `stockOnHand`; Doses parent shows original summary total.
- Child Packs: positive division uses floor, nonpositive uses ceil; signed `%` remainder.
  Valid pack size renders a bracket even for zero remainder: 10 doses / pack 10 is
  `1 ( +0 )`; -11 / 10 is `-1 ( -1 )`. Invalid/zero pack size follows legacy's 0 fallback.
- Parent Packs sums visible children, divides by parent pack size using floor even for
  negative totals, and omits a zero remainder bracket. Legacy -11 / 10 is `-2 ( +-1 )`.
  This is deliberately preserved legacy output: it does not reconstruct -11 by ordinary
  packs-plus-remainder arithmetic. The implementation's failing fixture must reproduce
  controller lines 296-309 with a visible child of -11 and parent pack size 10 before
  adding the formatter. Do not simplify the two formatters or change negative rounding.
- Doses parent may include filtered-out inactive cards while Packs parent sums visible
  ones. Explain the total basis when inactive items are hidden. Changing totals/format is
  a separate product decision, not implicit cleanup under exact-parity acceptance.
- Null/missing balance is unavailable, not a fabricated zero; test runtime contract nulls
  and agree any discrepancy found on the target data before changing business values.

Expiry and Last Update use localized date-only formatting, not timestamp/timezone shifts.
Use `occurredDate`, not `processedDate`, for Last Update. Missing lot expiry stays blank
as legacy; no-lot gets the translated label.

### Printing
