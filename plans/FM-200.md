# FM-200: Onboarding Module, Top-Bar Icon and Pilot Tour (Requisitions)

https://openlmis.atlassian.net/browse/FM-200 · Parent: [FM-199] Guided onboarding tours for new users
(React Joyride, isolated module)

## Scope

- The onboarding module, the top-bar Show Guide button, the `ONBOARDING` flag and two pilot tours:
  View Requisitions and requisition detail.
- Screens only gain `data-tour` attributes, plus plain wrapper divs where a component accepts no
  extra props.
- Out of scope:
  - tours for other screens (FM-201..FM-207);
  - automatic start and remembering seen tours;
  - backend changes.

## Summary

New users get no in-app guidance today. Legacy has none either: its only guidance is the
(i) column definitions in the requisition grid, plus a Help link hidden behind a right, whose
page returns 404.

This ticket adds a Show Guide button to the top bar. It appears only on screens that have a guide.

Pressing it dims the page and walks the user through the screen's main parts one at a time, with
Back, Next, Skip and Close. The guide never opens on its own. It works:

- on phones, where tables turn into cards;
- in Arabic;
- with the keyboard.

The first two guides cover View Requisitions and the requisition detail screen. Deployments and
administrators can turn guides off with a feature flag.

## Agent Brief

### API Map

None. No backend calls.

### Library

- `react-joyride@3.2.0` (MIT, peer React 16.8-19, about 20 kB gzipped).
- **Lazy-loaded:** the runner is lazy-loaded with `React.lazy` on first click, so users who never open a guide pay nothing.
- **Hook API:** use `useJoyride` in uncontrolled mode. Uncontrolled mode skips a missing target forward (or backward after Back), which gives graceful skipping. Controlled `stepIndex` does not skip, and had lifecycle bugs (#1205, #1206).
- **Options used:**
  - `continuous: true`, `skipBeacon: true`, `loaderComponent: null`;
  - `blockTargetInteraction: true`, so users cannot open dialogs mid-tour;
  - `targetWaitTimeout: 5000`, to cover suspense on slow links;
  - `closeButtonAction: 'skip'`, `dismissKeyAction: false`;
  - `zIndex` above the `z-50` layers;
  - `scrollToFirstStep: true`.
- **Escape:** handled by our own `document` keydown listener while running, calling
  `controls.skip()`. Joyride's default Escape moves to the next step instead of closing.
- **Focus:** on `tour:end`, focus returns to the Show Guide button. Joyride restores focus per step,
  not to the trigger.
- **Ending the tour:**
  - when the route changes;
  - when the page hides (`usePageHidden`);
  - when a modal opens (`hasOpenDialog`).

No queries. Tour state is local React state in the launcher. Nothing in the URL or storage.

### Rules

- Tour files hold data only.
- One anchor per element.
- Anchors go on containers that exist in both table and card layouts.
- No `className` on shadcn parts and no raw colors.
- The overlay keeps Joyride's default dim in both themes; the arrow takes `var(--card)` so it
  matches the tooltip card.

### Risks and Edge Cases

- **Zero-size skeletons:** Joyride treats a zero-size skeleton as visible. Anchors sit on real
  content wrappers, not inside skeleton fallbacks.
- **Modals:** a Base UI modal sets `aria-hidden`/`inert` on body siblings, and Joyride's portal is
  one of them. Tours end when a modal opens, and `blockTargetInteraction` keeps one from being opened
  mid-tour.
- **Only the active tab:** only the active tab panel is mounted, so the grid anchors resolve to the
  visible tab.
- **Registry-clean components:** `src/components/data-table/` must stay registry-clean. Later admin
  tours (FM-207) anchor on wrappers, not inside it.

## UI/UX

- **Button:** a ghost icon button with a `CircleHelpIcon`, in the top bar before the account avatar.
  - Tooltip and accessible name "Show Guide".
  - Visible at every width.
  - Hidden on screens without a guide, so it never offers nothing.
- **Tooltip:**
  - a card in the app's own style, at most 380px wide (less on phones);
  - title, one or two sentences, and progress text;
  - Back and Skip at the start, Next or Finish at the end, with a close X.
  - It follows the light and dark themes.
- **Overlay:** dims the page with a rounded spotlight around the current part. Clicks inside the
  spotlight are blocked, so the guide shows rather than acts.
- **Arabic:** mirrors through logical placement and classes.
- **Accessibility:**
  - The tooltip is an `alertdialog` labelled by its title.
  - Tab stays inside it.
  - Escape ends the guide.
  - Focus returns to the button.
- **Improves on legacy:** legacy has no guidance beyond column definitions. Nothing is dropped.

## Prototype Result

Joyride 3.2.0 kept. Checked headless on test.openlmis.org as administrator (writes stubbed),
`.screenshots/FM-200/tour-*.png`:

- Both tours walk end to end at 1440 and 390 without the tooltip leaving the screen.
- In Arabic the tooltip and placements mirror.
- Missing targets skip: View Menu before a search, Actions without a footer.
- Escape ends the tour and focus returns to Show Guide.
- Ctrl/Cmd+K does not open the palette mid-tour, because the tooltip counts as an open modal.
- The button is absent on Home.
- Known limit: progress counts skipped steps, so a tour can end at "Step 3 of 4".

## Decisions

- **Joyride 3.x:** uncontrolled `useJoyride` with a custom tooltip. driver.js remains the fallback
  if the prototype fails the dialog, RTL or suspense checks.
- **Lazy-loaded runner:** loaded on first click, so the bundle cost falls only on users who open a
  guide.
- **Anchor constants in `src/lib/tour-anchors.ts`:** not inside the feature as FM-199's description
  says, because feature boundaries forbid `requisitions` importing `onboarding`.
- **Tours select themselves by route id inside the module:** route files stay untouched apart from
  wrapper divs.
- **Composition:** the shell gains a header actions slot, and `_protected.tsx` fills it with the
  launcher. The shell never imports the feature.
- **Ending a tour:** Escape and Close end the tour. Joyride's default "Close means next step" is
  overridden.
- **Mid-tour:** the user cannot interact with highlighted elements, and tours end on navigation,
  page hide or a modal opening.

- `ONBOARDING` defaults to on; administrators can turn it off.
- Step wording ships as drafted here; product reviews it once the pilot tours are built.
