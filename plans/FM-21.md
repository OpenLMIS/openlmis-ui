# FM-21: Period + date pickers

https://openlmis.atlassian.net/browse/FM-21 · Parent: [FM-9](https://openlmis.atlassian.net/browse/FM-9) Shared form widgets

## Scope

Let users type dates into every date control: `DateField` in forms, `DatePicker` in toolbar and
Filters, inline table and card cells, and Receive's new-lot expiry. Dates are typed in the
deployment's date format, as legacy does, with a calendar shortcut at the logical start.
Text that is not a real date never reaches the server or the URL.

Not in scope: period selection (shipped), date-time controls, and read-only dates elsewhere
(tables, cards, summaries keep the page language's medium format).

## Summary

Today the new UI's date controls only open a calendar. Legacy lets users type a date such as
31/12/2018 into a text box, with a calendar alongside, and refuses to save text that is not a real
date.

Each date control becomes a text box showing the date in the deployment's format (DD/MM/YYYY on
test), as in legacy. Clicking or tabbing to the text box opens the calendar, and the calendar
follows what is typed. Focus stays in the text box while typing. Text that is not a real date says "This text
is not a valid date" when the user tries to save, and the form does not save until it is fixed or
cleared. Filters apply a typed date when the user presses Enter or leaves the field, and keep the
last applied date if the text is not valid.

## Legacy Today

- `openlmis-ui-components` `openlmis-datepicker`: an unmasked text input plus Bootstrap calendar.
  Parses typed text strictly with the build-time picker format (`dd/mm/yyyy`) and displays bound
  values with the deployment `dateFormat`; the two agree on test. Stores `yyyy-MM-dd`. Malformed or
  impossible dates fail the `invalidDate` validator ("This text is not a valid date"), which blocks
  submit. Min/max only constrain the calendar. Unpadded `1/2/2026` is rejected.
- Checked hands-on on test (Edit Lot expiry and manufacture dates, Lots Earliest Expiry filter;
  screenshots in `.screenshots/FM-21/legacy/`):
  - Text box with no placeholder, showing `dd/MM/yyyy`. Focus opens the calendar beside it, below
    or above depending on space, also on phones (an in-page popover, about 213 x 288 px). Typing moves the calendar to the typed day.
  - Tab commits a valid date and moves on. Unpadded `1/2/2030`, ISO `2030-12-31`, impossible
    `31/02/2030`, partial `12/2030` and `abc` stay as typed and are invalid; no message while typing
    or on blur. Save stays enabled; trying to save shows "This text is not a valid date" under the
    field. Enter in a dialog submits the dialog.
  - Filters: Enter searches with a valid date; with invalid text the search is refused ("This form
    is invalid") and the previously applied date stays.
  - Arabic: the box follows the page direction (RTL) with Western digits; Arabic-Indic digits are
    rejected. The calendar names months and weekdays in Arabic.
  - Stock event date fields could not be opened on test (the legacy editors stayed loading), so
    their bounds are taken from source.

## Agent Brief

- **API map**: `GET /localeSettings` (anonymous) through the existing reference-data settings query;
  `fetchCurrencySettings` already returns the whole JSON, so add `dateFormat` to its type. No new
  calls.
- **Format and parse** (`src/components/form/date-value.ts`, registry-safe, no date-fns, local digit
  map like `quantity-value.ts`): support numeric patterns built from `d`/`dd`, `M`/`MM`, `yyyy` and
  `/ . -` separators; any other deployment pattern falls back to `dd/MM/yyyy`. Accept the pattern,
  unpadded day and month and Arabic/Persian digits. Try the deployment pattern first and fall back to
  ISO `yyyy-MM-dd` only when the text does not match it; typing advances through the pattern (below),
  so in practice the ISO fallback serves pasted text. Reject two-digit years and impossible dates.
- **Typing advances** (follow-up, like the browser's date input): a character typed at the end
  completes a part at two digits (four for the year) and adds the pattern's next separator. A
  first digit that cannot start the part pads and moves on (day 4-9, month 2-9); the year never
  pads. One separator key right after an added separator is ignored. Paste, middle edits,
  removal and selections are untouched; IME and Android input advance when composition ends.
- **Format bridge**: add `dateFormat` to `FormMessagesProvider`. `TranslatedFormMessages` supplies a
  non-suspending settings subscription that is active only while date controls or their layout and
  filter helpers are mounted. Seed one module-level value synchronously from a supported stored pattern (localStorage,
  like the deployment time zone), keep it when the request fails, and use `dd/MM/yyyy` when nothing
  usable exists. Keep the format stable while a field is being edited. Tests (extend the settings
  tests): stored non-default format on first paint, failed fetch, a later successful refresh while a
  field is being edited. Update AGENTS.md's localStorage metadata list.
- **Picker** (`DatePicker` in `form-fields.tsx`): `InputGroup` with the text input (keeps the current
  control id), a named, click-only calendar button at the logical start after any filter label, and
  optional Clear at the logical end. Clicking the icon opens the calendar and focuses the text box.
  Pointer down on the input, Tab into the input and typing also open the calendar.
  Programmatic focus on mount, validation or field reveal leaves it closed. The calendar opens
  below by default. Lots Earliest Expiry opens above and can scroll within the available space,
  keeping Latest Expiry and the filter actions reachable. Local text while focused, never reformatted mid-typing; it is
  re-derived from `value` on outside changes (Clear, calendar pick, form reset, URL Back) and on
  blur. Text follows the page direction, as legacy. No placeholder text beyond what legacy shows,
  except the filters' label (see Filters). No `inputMode="numeric"` (iOS keypad lacks `/`).
  Ideas taken from the DFQT date field (DFQT-256): keep half-typed text inside the field and only
  report a whole date to filters; the calendar button never submits the surrounding form.
- **Year range**: one rule for typing, calendar picking and submit validation: the calendar's
  existing navigation range (1900 to the current year plus 100). Typed or pasted dates outside it,
  including canonical ISO such as `9999-01-01`, are invalid in the picker and in the Zod helper.
  Existing stored values outside it still display. Tests: the calendar's last selectable year is
  accepted; a pasted out-of-range ISO date is rejected at submit.
- **Focus and month**: no automatic focus into the popup or a day when it opens from focus or
  typing. ArrowDown from the input enters the calendar. Tab skips the calendar button and moves
  from the input or calendar to the next field. Reverse Tab can still reach Clear. The displayed
  month follows complete valid text, and the user can still page months manually. Escape and picking
  a day return focus to the input. A pointer press within the calendar keeps it open even when
  the browser blurs the input without focusing a calendar button. Sizes: add `InputGroup size="sm"` (28px) for inline
  table and card cells and keep `lg` (36px); add `InputGroup size` to the registry-allowed variants
  and the customization table in AGENTS.md.
- **Form value contract** (`DateField`): every edit reports empty, canonical ISO, or the entered
  invalid text. Invalid text that could be mistaken for a canonical value carries an internal
  prefix so validation rejects it. The input displays the exact entered text. While focused, the user's spelling is kept through the parent's echo of
  that edit (no reformatting or caret jumps); explicit resets and calendar picks replace it; on blur
  a valid value is shown in the canonical format and invalid text stays. Submit-first errors as
  today. Schemas check canonical validity first, then their existing required and range messages.
  Tests: submit without blur, invalid text surviving a row unmount and remount, external reset while
  editing.
- **Forms**: a shared Zod helper in `src/lib/` (`dateValue({ optional })`, message `form.date-invalid`
  "This text is not a valid date"). Add it where schemas do not reject non-dates today: Facilities
  (go-live, support start, program start), Lots (expiry, manufacture), CCE decommission date,
  Receive and edit lot (`new-lot.ts`), report parameter dates. Fix the messages in
  `stock-count-date-dialog.tsx`, `inventory-occurred-date-dialog.tsx` and
  `physical-inventory-products.ts`, which currently call a bad date "in the future" or "expired".
  Period, stock event and POD schemas already reject it.
- **Stock events**: raw text is part of the draft (restored on reopen), never of the posted event
  (submit validates the whole form, including rows on other pages; the pager marks those pages). A
  new line copies the previous line's date only when it parses, else today. The editor shell
  tracks row layout. Editable fields and derived quantity totals read only their own line.
  Autosave publishes the saving status once per transition.
  The open calendar retains its month and selection while text is incomplete. A valid edit
  updates the selection, and clearing the field clears it.
- **Receive new lot**: the expiry draft holds the raw text so `newLotSchema` rejects it on Add,
  closing the calendar and focusing the first invalid field. Enter in the lot code or expiry
  input runs the same guarded Add and never submits the stock event. Reset pending text when
  the product or lot choice changes. The phone New Lot dialog closes its calendar and focuses
  the first invalid field through its own submit.
- **Filters**: a filter-side adapter outside the registry-bound folders (`src/components/form`,
  `src/components/data-table`), e.g. `src/components/pickers/date-filter.tsx`, owns commit and
  discard, hooking into the Filters popover's existing flush on close.
  The text box, its buttons and the calendar count as one control, so moving into the calendar is
  not leaving it. A valid pending date is applied once, on Enter, after focus finishes leaving the
  control or when the Filters popover closes. A calendar pick or Clear replaces any pending text and applies at once.
  Invalid text keeps the applied date and shows a translated message linked to the input when the
  user leaves the control, and is discarded on popover close, Clear Filters or Back (the adapter is
  told explicitly; an unchanged date prop alone cannot signal a reset). Recheck when the paired bound
  changes. Tests assert URL changes: typed date then a different calendar pick (one apply, the pick),
  popover close without blurring the input, Clear Filters with an unchanged date prop. Keep the
  filter's label visible as a start add-on and in the input's accessible name; drop the "Pick A
  Date" placeholders (legacy shows none).
- **Sizing**: stock event `DateSizer` measures the deployment format with two digits for both day
  and month and uses the widest Geist digit, 0, for every digit position. It includes space for the
  calendar button. `ExpirySizer` keeps the month measurement for the read-only Expiry column.
- **Translations**: `form.date-invalid` and the calendar button name in
  every catalog; `sync-translations`, `pnpm sort-messages`.
- **Tests** (tests first): parser units; schema helper; `DateField` typing stores ISO and blocks
  submit; stock event bad date on another page blocks submit and is correctable; Receive Enter with
  invalid expiry, correction and no parent submit; filter invalid edit keeps the applied date and a
  correction applies once; keyboard-only selection. Update shared keyboard, load-retry and bounds
  tests and feature tests for Lots, Facilities, Processing Schedules and Receive to type into the
  textbox and use the named calendar button. Update `lot-form-dialog.test.tsx` for the new form
  format. Also migrate `pod-editor.test.tsx` (validation focus lands on the textbox, not a button),
  `offline-events.test.tsx` (end-date filter opened by the calendar button) and
  `event-editor.test.tsx` (the next line inherits the date, read from the textbox), and add the
  invalid-previous-date fallback case.
- **Docs**: AGENTS.md DateField contract, date column sizing lines, allowed variants.
- **Risks**: 28 call sites; filters committing at the wrong time; offline format.

## UI/UX

- Port: typed entry in the deployment format, calendar opening with user input and following the typed
  date, strict validation with "This text is not a valid date" shown on save, Enter submitting the
  form, page-direction text in Arabic.
- Improve (quick wins, additions only): pasted ISO dates, unpadded numbers and Arabic-Indic digits
  are accepted instead of rejected; typed dates outside a field's existing bounds get the existing
  bound messages; filters show the reason inline instead of a generic alert.
- Drop: nothing.

## Decisions

- Place the calendar icon at the logical start, after any filter label, as a click-only shortcut
  that opens the calendar and focuses the text box. Tab skips the icon (user, 2026-11-20).
- Dates are typed in a plain text box in the server's format: the deployment `dateFormat` (DD/MM/YYYY
  on test), which legacy uses to display bound values, with `dd/MM/yyyy` as fallback. Legacy's typing
  format is a build-time setting that matches it on test. The browser's own date input was ruled out
  (user, 2026-11-20): its order follows the browser language, not the server format.
- This reverses FM-143's "same format in the Lots table, filters and dialog": date inputs now use
  the typed format, read-only Lots dates keep the page-language format.
- Filters keep the new UI's live filtering (no Search button, unlike legacy): a typed date applies on
  Enter, on leaving the field or when the Filters popover closes, not on each keystroke, so editing
  a date cannot fire a search for an intermediate date (user, 2026-11-20).
- Typed text lives in the form value until it parses, the pattern Number and Quantity fields use,
  so form-level validation covers rows that are not mounted.
