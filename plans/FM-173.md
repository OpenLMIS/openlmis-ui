# FM-173: Branding Settings Page (Logo & App Name)

https://openlmis.atlassian.net/browse/FM-173 · Parent: FM-170 Global app configuration
(branding, theme & feature flags)

## Scope

This PR adds **Settings**, a page with tabs at `/settings` opened from the account menu, and its
first tab, **Branding**: upload or remove the logo, set the app name, choose whether the name shows
beside the logo, see a preview, save, or reset to the built-in branding. It adds the
`SYSTEM_SETTINGS_MANAGE` right to `RIGHTS`, a Settings entry in the account menu, and an image
field to `src/components/form/`.

It builds on FM-172's store. Theme (FM-174) and Feature Flags (FM-176) become tabs of the
same page in their own PRs.

## Summary

An administrator opens Settings from the account menu and lands on Branding.
They pick a logo file, type the app name (or leave it empty for the built-in OpenLMIS), and
see straight away how the browser tab, the sidebar and the sign-in page will look. Save stores it; the administrator sees the new branding at once,
everyone else on their next page load. Reset to Defaults, after a confirmation, brings back
the OpenLMIS logo and name.

A file of the wrong kind or too large is refused before anything is sent, with a message
that says what is allowed. Leaving with unsaved changes asks first. People without the
System Settings right never see the menu entry, and get the no-access page if they open the
address directly.

Legacy has no such page: rebranding means rebuilding the UI.

## Legacy Today

No branding page exists. The closest admin form, System Notifications, opens as a modal,
shows a blocking "This form is invalid" alert on submit, and discards a draft on Cancel with
no warning (`.screenshots/FM-170/legacy-system-notification-*.png`). This page follows the
new app's settings-page pattern instead (Profile).

## Agent Brief

### API Map

| Step | Method and path | Params | Fields used | Right |
|---|---|---|---|---|
| Open page | `GET /api/appConfiguration` (axios, with token) | | all, `version`, `modifiedDate` | `SYSTEM_SETTINGS_MANAGE` (page) |
| Save name | `PUT /api/appConfiguration` | `If-Match: W/"<v>"`, full body with `appName`, `showAppName` | response body, `ETag` | `SYSTEM_SETTINGS_MANAGE` |
| Save logo | `PUT /api/appConfiguration/logo` | multipart `file`, `If-Match` | response `logo`, `version` | `SYSTEM_SETTINGS_MANAGE` |
| Remove logo, Reset | `DELETE /api/appConfiguration/logo` | `If-Match` | response `version` | `SYSTEM_SETTINGS_MANAGE` |

Save runs the logo call first, if the logo changed, then the `PUT` if the name or the
Show Name Beside Logo switch changed, each with the version the previous one returned. Only the calls that are needed are made.

### Data Flow

- Layout route loader: `Promise.all([requireRight(...), ensureQueryData(appConfigurationOptions())])`,
  blocking, since it is a permission check and the form cannot render without the values.
- Query key `queryKeys.appConfiguration.detail()`; a new scope in `src/lib/key-factory.ts`.
- After a successful save: `setQueryData` with the response, then write it to the FM-172
  store so the admin's own sidebar, title and favicon update at once.
- The draft logo is a `File`; the preview uses an object URL, revoked when it changes or the
  page unmounts.
- The tab is the index route, `/settings`; Theme and Feature Flags are `/settings/theme` and
  `/settings/feature-flags`. The header and tabs render once in the layout
  (`SystemSettingsLayout`), the footer comes in through `WorkspaceFooterPortal` and Reset To
  Defaults through `WorkspaceActionsPortal`, as on Profile.

### Rules

- Accepted: `image/png`, `image/jpeg`, `image/webp`, at most 512 KB, checked on the client
  before upload (nginx answers larger bodies with an HTML 413). The server checks again.
- App name: optional, trimmed, at most 20 characters, which fit the sidebar beside the logo; the
  input stops at 20. The server still accepts up to 64, so a longer saved name stays valid while it
  is left unchanged. It may be empty: that stores `null`, so the built-in OpenLMIS names the browser
  tab and the sign-in text. Typing the default name stores it as given.
- Show Name Beside Logo (`showAppName`, default true, and true when a server omits it) hides the
  name in the sidebar, for a logo that already shows it.
- Reset To Defaults is disabled whenever the built-in name, logo and shown name are in use, stored
  or not (`isBrandingDefault`).
- A `409` means someone else saved: show an `Alert` above the form, "Settings Changed
  Elsewhere", with Reload, which resets the draft to the server's values. The draft stays and
  Save is disabled until Reload. Never retry the save with the new version silently.
- A `404` on the page load means the server has no configuration endpoint yet: show an
  `Empty` state, not an error with retry.
- A `413` or `400` on the logo call shows the server's message in the error alert, not a toast.
- If the logo call succeeds and the `PUT` then fails, the stored logo is kept as the new saved
  state, the error alert says the settings were not saved, and a retry sends only the name. The
  draft logo is cleared only when the upload was the step that succeeded, so a Reset that fails
  part way keeps a picked logo.
- A refused file shows its error but never replaces the preview; Save with a refused file moves
  focus to the invalid field.

### Risks and Edge Cases

- test.openlmis.org has no endpoint until FM-171's backend ships: every browser check
  stubs `GET /api/appConfiguration` too, and the page shows "not available" unstubbed.
- A very tall logo would stretch the sidebar bar; `Logo` is height-capped already.
- The object URL must be revoked, or repeated picks leak memory.

## UI/UX

- **Page, not dialog:** the settings grow into several tabs, which AGENTS.md gives a page.
- **Layout:** the form as a `SettingsList` of rows (App Name, Logo, Show Name Beside Logo), each
  description under its label, then the preview below it, at every width.
- **Logo row:** Upload and Remove icon buttons with tooltips next to the Logo label, the current
  image on the end side.
- **Preview:** three panels, Browser Tab, Sidebar and Sign-In Page, side by side on a wide page,
  in the current light or dark mode, using the real `Logo` so it cannot drift from what ships.
- **Footer:** Cancel at the start puts the saved values back; Save at the end stays on the
  page (settings page opened from no list). Reset To Defaults is an outline button in the page
  header, so it is never mistaken for Cancel.
- **App-wide:** select lists open below their input (`alignItemWithTrigger` false by default in
  `ui/select.tsx`); a focusable disabled button is dimmed (`data-disabled` in `ui/button.tsx`);
  every `layout="row"` field shows its description under the label.
- **Improve over legacy:** errors show inline under the field as soon as a file is picked;
  unsaved work is protected; a conflicting save is explained instead of overwritten.
- **States:** loading (the route's pending component, holding a block for the header button
  except on Feature Flags), not available (`404`), no access, error with retry.

## Decisions

1. **One page named System Settings with tabs**, after the right that guards it; more
   settings become tabs. Reversed as built; see As Built: the page is named Settings.
2. **Reset saves at once after confirming**, rather than filling the draft, so "reset" means
   what it says.
3. **`FileField` joins the shared form fields**, since nothing in the app uploads a file yet
   and other screens (data import) will. Reversed as built; see As Built: it is `ImageField`.
4. **The admin sees the change immediately**, everyone else on reload, as the AC asks.

5. **The favicon uses the same logo**, as the AC says; a separate square icon is a follow-up
   if deployments ask, since a wide logo makes a poor favicon.

## As Built

- Branding is the index route, `/settings`, like Profile's first tab;
  Theme and Feature Flags join as `/theme` and `/feature-flags`.
- The field is `ImageField` in `src/components/form/form-fields.tsx`, not a separate
  `file-field.tsx`: a row with the current image, Upload Logo and Remove. Its value is
  `undefined` (keep), `null` (remove) or a `File`, checked on change so a refused file is flagged
  at once.
- The page reads the configuration with `getIfExists()`, so a server without the endpoint renders
  "Settings Not Available" instead of throwing.
- The upload sends `Content-Type: multipart/form-data`: the shared client defaults to JSON, which
  made axios turn the `FormData` into JSON and the server answer `415`.
- `rememberAppConfiguration()` in `src/lib/app-configuration.ts` stores a saved configuration for
  the next boot and shows it at once, so the admin's own sidebar, title and favicon update on Save.
- `isConflict()` joins `src/lib/http.ts`.
- All three tabs save through `useConfigurationSave()` in `hooks/`: one success toast, the store
  and the cache updated, a `409` kept as a conflict until Reload. The draft saves against the
  version it started from, so a refetch under unsaved changes ends in a conflict, not a silent
  overwrite; a clean form follows the refetch. A save that stored its first steps before failing
  (`PartialSaveError`) keeps them. A Reload that fails offline says so in the alert and runs again
  once the connection is back; a successful one puts focus on the form.
- The page header, tabs, pending and "not available" states share one `SystemSettingsPage` in
  `system-settings-workspace.tsx`; `SystemSettingsLayout` picks between `SystemSettingsWorkspace`
  (the tabs) and "not available", and `SystemSettingsPending` holds a block for the header button
  except on Feature Flags.
- The header and tabs render once through the shared `WorkspaceTabs`; the footer goes in with
  `WorkspaceFooterPortal`, as on Profile.
- All three tabs set `staticData.crumbKey` to `system-settings.title`, so the breadcrumb is
  Home / Settings on each.
- Settings sits in the account menu below Account, not in the sidebar: no `NAV_GROUPS` entry and
  no nav key.
- Reset To Defaults is in the page header, through `WorkspaceActionsPortal`, on Branding and Theme,
  from `SettingsReset`, which owns the confirm dialog. It is disabled, and looks it, whenever the
  built-in name, logo and shown name are in use, stored or not.
- The page title and the account menu entry both read Settings.
- "Show Name Beside Logo" hides the name in the sidebar, for a logo that already shows it; the
  logo then carries the name as its alt text. It is stored as `showAppName` (default true),
  added to `/api/appConfiguration` in referencedata on `migration`.
- Each field's description fits one line. The logo shows its preview on the end side only, with
  Upload and Remove icon buttons, each with a tooltip, next to the Logo label.
- The name is optional, at most 20 characters; the only error keys are `name-too-long`,
  `logo-type` and `logo-too-large`.
- The preview is three small panels: the browser tab with the favicon, the sidebar header, and
  the sign-in heading.
