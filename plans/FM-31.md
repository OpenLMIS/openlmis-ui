# FM-31: Login

https://openlmis.atlassian.net/browse/FM-31 · Parent: FM-30 General: auth, home, profile

## Scope

The sign-in page shipped earlier; returning to the page the user asked for came with FM-14.
What was left is the "Forgot Password?" link, which needs the page from [FM-32](FM-32.md), so
it ships in the same PR. That plan holds the shared card layout and the brief.

## Summary

Sign In gets a "Forgot Password?" link at the end of the password label's line, opening the
new Forgot Password page. Legacy has the same link beside its Sign In button.

## Acceptance Criteria

| AC | How it is met | How it is checked |
| --- | --- | --- |
| The page shows Username, Password, the language switcher, the "Forgot password?" link and Sign In | Link added; the rest unchanged | Browser |
| Both fields are required. Submitting empty fields shows validation messages | `loginSchema` (shipped) | Existing tests |
| The eye icon shows and hides the password | `PasswordField` (shipped) | Browser |
| Wrong credentials show an error message and the user stays on the page | `useAuthActions` (shipped) | `use-auth-actions.test.ts` |
| Valid credentials log the user in and open the home page (or the page they tried to open) | `safeRedirect` (FM-14) | `redirect.test.ts` |
| Changing the language updates the page text right away and is kept after login | i18next with its stored language (shipped) | Browser |
| "Forgot password?" opens the forgot password page | Link to `/forgot-password` | Browser |
| i18n, RTL, same API calls, no console errors | `login.forgot-password` in all locales | Browser |

## Agent Brief

- `src/routes/login.tsx`: render inside `AuthPage`/`AuthHeader`/`AuthForm`
  (`src/components/auth-card.tsx`), and pass an `AuthLink` to `/forgot-password` as the
  password field's `action`, at the end of its label's line.
- Translation: `login.forgot-password` "Forgot Password?".

## UI/UX

- **Port:** the link, worded as legacy.
- **Improve:** it sits beside the Password label, where people look for it;
  the session dialog gets the same link in the same place, opening in a new tab.
