# FM-16: Cache current user, roles, home facility, programs

https://openlmis.atlassian.net/browse/FM-16 · Parent: [FM-7](https://openlmis.atlassian.net/browse/FM-7) Auth & session plumbing

## Scope

Read the signed-in user's record from one shared cache entry everywhere (Home, avatar menu,
Profile), refresh that entry from the server after the user saves their own profile, and show a
clear message when a stock editor opened by link needs a home facility the user does not have.

Not in scope: the deliberate refresh rules below, and the sign-in warmup rules in AGENTS.md.

## Summary

After sign-in the app already loads the user's rights, roles, programs and record once and clears
them when someone else signs in. Two gaps remain:

- The user's own record is fetched under three separate cache entries: the Home greeting, the
  avatar menu and Profile pages, and the shared record other screens use. Moving between Home,
  the avatar menu and Profile asks the server for the same user again and again.
- Opening Issue, Receive, Adjustments, Unpack or a Physical Inventory draft by link, for a user
  with no home facility, shows the generic No Access page. The program lists already say "No Home
  Facility"; the editors should say the same, with a link back to the program list.

Legacy shows a generic "Internal application error" in that case, even on its program lists, and
does not refresh its cached user after a profile save. Both changes go a little beyond legacy.

## Acceptance Criteria

| AC | How it is met | How it is checked |
|---|---|---|
| Fetched once per session, read from the cache afterwards | Routine reads share the cache: Home, avatar menu and Profile read `userRecordOptions`, which never goes stale in a session. Deliberate refreshes stay: rights every 30 minutes, the home facility every 10 minutes, BUQ and requisition authorization reads on entry, offline download/upload access reads, and the fresh read right before a profile save | Route test: with a warm record, Home, then the avatar menu, then Profile make no `GET /users/{id}` |
| Any screen reads user, rights, home facility, programs without its own call | Shared `userRecordOptions`, `permissionsOptions`, `homeFacilityOptions`, `userProgramsOptions`, `rolesOptions`; `firstNameOptions` and the user half of `profileOptions` removed | Code read |
| A different user replaces the cache without reload | Unchanged: the query client clears on identity change | Existing `tanstack-query.test.ts` |
| Saving the own profile updates the cached user | After a confirmed user write, refetch `userRecordKey` from the server (`staleTime: 0`), guarded by `isCurrent()` | Profile save tests, including a late response after a user switch and a name saved before a failed contact write |
| No home facility shows a clear message | `NoHomeFacilityError` carrying the program list destination, rendered by one `ErrorFallback` branch | Updated stock editor test and a new Physical Inventory draft case |
| Same API calls as legacy | Same endpoints: `GET /users/{id}`, `/users/{id}/permissionStrings`, `/users/{id}/programs`, `/roles`, `/facilities/{id}`, `/userContactDetails/{id}` | Code read |

## Legacy Today

- Legacy caches the current user in memory and local storage at login (`currentUserService`,
  referencedata-ui) and clears it only on logout. After a profile save it reloads the profile page
  from the server, but the cached current user is not refreshed.
- Issue, Receive, Adjustments, Unpack and Physical Inventory resolve
  `facilityFactory.getUserHomeFacility()`, which rejects without a home facility; the state change
  error interceptor then shows "Internal application error" and the page does not open.

## Agent Brief

- **Home**: `dashboard-greeting.tsx` reads `userRecordOptions(userId).firstName` (non-blocking
  `useQuery`, title falls back to "Home" while absent). Delete `firstNameOptions` and
  `fetchFirstName`. Home's Refresh also refetches `userRecordKey(userId)`; navigation cancellation
  stays scoped to dashboard queries. Offline, Home now greets by name from the saved access
  snapshot (an improvement); check it with and without a saved snapshot.
- **Avatar menu**: `nav-user.tsx` `SignedInAs` reads `userRecordOptions` for the full name.
- **Profile**: split `profileOptions` into the shared user record plus a `contactDetailsOptions`
  query (`GET /userContactDetails/{id}`, under `queryKeys.profile`) for the tabs that show email
  and phone. Layout, Basic Information, Roles and Notifications read the user from
  `userRecordOptions`.
- **Save**: `saveProfile` keeps its fresh `GET /users/{id}` right before `PUT /users`. After the
  user write succeeds, refetch `userRecordKey` with `staleTime: 0` even if the later contact write
  fails; refetch contact details after a contact write. Check `isCurrent()` after every await and
  before any cache write or form reset. Do not publish the local `applySaved` fallback into the
  shared entry (it could restore stale roles or home facility); if the refetch fails, invalidate
  instead. Replace the route's `queryKeys.users.all` invalidation with the Users admin list and
  detail keys only, so the save does not also refetch user programs.
- **No home facility**: in `-stock-event-editor.tsx` and
  `_protected.stock-management.physical-inventory_.$programId.tsx`, split `!homeId ||
  !hasProgramGrant(...)` and throw `NoHomeFacilityError({ back })` for the first part, where `back`
  is the kind's program list route. `ErrorFallback` gets one branch for it: title
  `stock-programs.no-home-title`, description `facility-program.no-home`, and a Back link labelled
  `physical-inventory.back` ("Back To Programs"; rename it to a shared `stock-programs.back` and
  run `sync-translations`). Permission failures, unsupported programs and offline data keep their
  current paths. No facility or draft request is made.
- **Tests**: update `-stock-event-editor.test.tsx` ("shows No Access without a home facility") and
  add the Physical Inventory draft case (message, Back destination, no facility request); a Home →
  avatar → Profile request-count test with a seeded `userRecordKey`; extend
  `-profile-completion.test.tsx` so a delayed old-session response after a user switch cannot
  repopulate the shared key; a save where the name succeeds and the contact write fails; update
  `src/lib/user-queries.test.ts` and `basic-information.test.tsx` for the removed keys.

## Decisions

- Profile reads the session-fresh shared record. The whole-record save stays safe because
  `saveProfile` reads the user fresh right before writing.
- Refetch the shared record after a save instead of writing a locally merged copy, so roles and the
  home facility always come from the server.
- Keep the existing refresh windows; "once per session" means routine reads share the cache.

## Open Questions

- None blocking.

## Steps

2. Home and avatar read the shared record; remove `firstNameOptions`; Home Refresh covers it.

4. `NoHomeFacilityError`, its `ErrorFallback` branch and the shared Back key.
5. Run `pnpm check`, `pnpm lint:ds`, `pnpm tsc --noEmit` and the touched tests; check Home offline.
