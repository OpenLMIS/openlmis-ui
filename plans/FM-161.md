# FM-161: Manage BUQ

https://openlmis.atlassian.net/browse/FM-161 · Parent: FM-154 Admin: system & integrations

## Scope

Adds Administration > Manage BUQ, with Remarks and Sources Of Funds tabs. Each tab lists its
records with Add, Edit and Delete.

The remark and source-of-funds lookups move from `src/features/buq` into `reference-data`, so the
admin page and the forecast screens share them. The forecast screens change only their imports.

One shared component gains small options: `DeleteRecordDialog` gets a read-only state and a
refresh after a server error.

Out of scope:

- Forecast screens beyond those imports (FM-103..FM-110, another developer's).
- Backend changes.

## Summary

Remarks explain a forecast line whose verified consumption differs from the forecast. Sources Of
Funds are the funders listed in a forecast's funding details. An administrator with the Manage BUQ
right keeps both lists.

How legacy works:

- **Lists:** the two lists show as tabs, ten rows per page, in server order. Switching tabs or
  reloading starts again on page 1 of Remarks.
- **Read-only records:** records the server marks as part of the standard setup have Edit and
  Delete greyed out.
- **Add and Edit:** a small dialog with a required Name and an optional Description. A duplicate
  name opens a global error box over the form.
- **Delete:** asks first. The server allows deleting a remark or source that forecasts still use,
  and those forecasts, and any forecast list that includes them, can then fail to load.

What the new page does:

- Each tab keeps its own page and sort in the address, so links and Back work.
- Both lists sort by name.
- A duplicate name shows on the field.
- The Delete confirmation warns about forecasts that use the record.
- Phones get one card per record. Standard records carry a small lock badge in both layouts.
- Descriptions wrap in full.
- If a refresh fails, the current list stays visible with an inline Try Again action.

## Legacy Today

Screenshots are in `.screenshots/FM-161/legacy-*.png`. The source is
`openlmis-referencedata-ui@777e31d` `src/admin-buq/`, a React module inside the AngularJS app.

- **Route** `#!/administration/manage-buq` (`openlmis.administration.buq`), gated by `MANAGE_BUQ`.
  The administrator on test has it through the Manage BUQ role.
- **Tabs**: Remarks (default) and Sources Of Funds.
  - Switching tabs and reloading reset to Remarks page 1; the URL never changes.
    `lastViewedTab` is written to localStorage but never read back.
  - Both tables page locally at 10 rows, in server order, with no sort.
  - Edit and Delete follow each row's `editable` flag. On test all 9 remarks and 8 of 11 sources
    are not editable.
- **Columns**:
  - Remarks: Remark, Description, Actions, with Add Remark above.
  - Sources: Source Of Fund, Description, Actions, with Add Source of Fund above.
- **Form**: Name (required, 255 characters) and Description (optional, 4,000 characters).
  - Only leading spaces are stripped. A blank Name shows "This field is required".
  - Add sends `description: ''` when it is empty.
  - Titles are Create remark, Edit remark, Create Source of Fund and Edit Source of Fund. Buttons are
    Create or Save, and Cancel.
  - Edit starts from the row, with no detail read.
- **Duplicate name**: opens a global "Bad Request" box over the form ("Remark name duplicated." or
  "Source of fund name duplicated.").
- **Toasts**: plain English; the source create toast says "Source of Found".
- **Delete** asks `Are you sure you want to delete "<name>" Remark?` (or Source of Fund), with
  Cancel and Delete. A refusal leaves the confirmation open under a global error box.
- **Empty and failed loads**: an empty list blanks the whole page, tabs included. A failed list read
  shows a global Internal Server Error box.
- **Phone**: Delete is clipped, and the Add dialog overflows the screen with Cancel off-screen.
- **Translation**: all component text is hard-coded English; only the menu label is translated.
- **Timings**: page 0.3 s; create 0.7 s; edit and delete 0.2 to 0.3 s.

## Agent Brief

### API map

Both resources live in the BUQ service (openlmis-buq@9a1ec57). They need only a signed-in user,
with no named right checked on the server; the page itself is gated.

| Step | Method and path | Params / body | Fields used | Legacy ref |
|---|---|---|---|---|
| Remarks list | `GET /api/remark` | none; returns a plain array and ignores paging and sort | `id`, `name`, `description`, `editable` | `admin-buq.service.js` |
| Sources list | `GET /api/sourcesOfFunds` | every page, as today's lookup reads it, with no sort (server order) | `content[]` as above | same, with no params |
| Edit read | `GET /api/remark/{id}`, `GET /api/sourcesOfFunds/{id}` | none | record | not used by legacy |
| Add | `POST` to the collection | `{ name, description }`, trimmed, with an empty description sent as `null` (a departure from legacy's leading-only trim and `''`) | `201` record | same |
| Remark save | `PUT /api/remark/{id}` | `{ id, name, description }` | `200` record, or 404 if missing | same |
| Source save | `GET /api/sourcesOfFunds/{id}`, then `PUT /api/sourcesOfFunds/{id}` | `{ id, name, description }` | `200` record | same, without the check read |
| Delete | `DELETE` on the collection `/{id}` | none | `204` | same |

The Source save reads first because the server's PUT re-creates a missing source under its old id
instead of answering 404. A 404 on the check read is treated as "this record no longer exists". The
save captures the session scope before the GET and asserts it before the PUT (AGENTS.md
multi-request rule). A delete by someone else between the GET and the PUT can still re-create the
source; that narrow race is accepted.

Errors (`{ messageKey, message }`):

| Condition | Status | Key | UI |
|---|---|---|---|
| Duplicate remark name (case-sensitive) | 400 | `buq.error.remark.name.duplicated` | Name field error |
| Duplicate source name (case-insensitive) | 400 | `buq.error.sourceOfFund.name.duplicated` | Name field error |
| Remark missing on Edit read or Save | 404 | `buq.error.remark.notFound` | Edit read: `DialogNotFound`. Save: toast, refresh, close |
| Source missing on Edit read, Save check read or Delete | 404 | `buq.error.sourceOfFund.notFound` | the same |
| Delete of a missing remark (stale row or repeat) | 500 (server has no existence check) | none | Generic `apiErrorText` toast; the dialog closes and the list refreshes, through a new `refreshOnError` predicate on `DeleteRecordDialog` (it refreshes only on 404 today) |
| Source id mismatch | 400 | `buq.error.sourceOfFund.id.mismatch` | Cannot happen (body id equals path id); generic |
| Blank name (never sent) | 400 / 500 | Spring text | Prevented by the form |

The server keeps names and descriptions as `TEXT` with no length limit, so the form keeps legacy's
255 and 4,000 as native `maxLength` caps plus the schema rule.

### Data flow

- **Route** `src/routes/(protected)/_protected.administration.manage-buq.tsx`:
  - `staticData.rights: [RIGHTS.manageBuq]`.
  - `loaderDeps: ({ search }) => ({ tab: search.tab })`, keeping paging, sorting and dialog keys
    out of the loader dependencies.
  - The loader awaits `requireRouteRights`, then prefetches the active tab's lookup without
    awaiting it.
  - A `pendingComponent` shows the real header, tabs and skeleton.
- **URL**:
  - `tab`: `remarks` by default, kept out of the URL.
  - Per-tab `<tab>Page`, `<tab>Size`, `<tab>Sort` and `<tab>Dir`, built from
    `tableSearchSchema(['name']).shape` with transforms that drop defaults, as Supervisory Nodes
    does in `features/supervisory-nodes/lib/edit-search.ts`.
  - A small adapter in `buq-admin/lib/search.ts` maps one tab's keys to and from the plain table
    search, used once through `usePagedTableSearch`, which already wraps `useTableSearchState`.
    - Each table's updates are bound to the tab that rendered it, and functional updates apply to
      that tab's keys in the latest search.
    - `replace` and the navigation options pass through.
    - The clamp uses `replace` with `{ resetScroll: false }`, and is skipped when the tab has
      changed before it runs.
  - A tab change sets only `tab` and clears the dialog keys; each tab keeps its paging. User Roles'
    reset behaviour is not reused.
  - `edit` (`'new'` or a lowercased guid) and `delete` (a lowercased guid) are scoped to the active
    tab; `edit` wins over `delete`.
  - The route renders the Edit and Delete dialogs keyed by the active tab (`key={tab}`), so
    switching tabs, including through history, unmounts the other kind's dialogs. No draft, opening
    or row hint carries across kinds, and a late completion from one kind cannot close the other's
    dialog. Delete row hints store the record and are reset when the tab changes.
- **Lookups move to `src/features/reference-data`**: the remark reader and options, and the
  source reader with its own every-page loop. The loop checks the session between pages, as
  `fetchValidAssignments` does, and sends no sort.
  - The query functions take `signal`.
  - Keys stay `['buq', 'remarks']` and `['buq', 'sources']`. The records widen to
    `{ id, name, description, editable }`, which still fits the forecasts' `NamedItem` props.
  - Buq's private `fetchEveryPage` stays for its other readers. The forecast screens and
    `src/routes/-buq-access.ts` change only their imports.
- **Both tabs** read their lookup and sort and page locally by name, with FM-162's local pattern
  and past-end clamp (the clamp waits for the dialog to close and replaces history). This follows
  AGENTS.md's rule to reuse a lookup's query when a management list uses the same endpoint;
  Sources has 11 rows on test.
- **Edit**:
  - Reads the record fresh per opening (`useOpening(target)`), under
    `[...queryKeys.buq.all, 'remark', id, opening]` or `'source'`. These keys sit off the list
    prefixes and off `queryKeys.buq.detail`, which belongs to forecasts.
  - Uses FM-163's pending-save guard and reread. The dialog subscribes to pending saves of
    its kind and checks the displayed target on each render. A pending Add Remark does not
    lock Edit Remark or Add Source.
- **After a save or delete**: cancel, then invalidate `['buq', 'remarks']` or `['buq', 'sources']`,
  covering the admin list and the forecast lookup, with `isCurrent()` after each await. If
  this read fails with cached data, show an inline list error with Try Again above the table
  or cards, through `useOfflineFailure` (retry on reconnect), the shared error reporter and a
  refused message. Keep the cached rows visible until a retry succeeds. When the connection
  drops, the protected layout's offline screen covers this online-only page, as on every other
  admin page, and reconnecting refreshes the list.
- **Text cells** use `CellText overflow="wrap"` (new mode: full text wrapping between words), so
  names and descriptions never spill into the next column.
- **Delete** uses `DeleteRecordDialog` and `useDeleteRowHint`, as FM-162. A refusal closes the
  dialog and toasts.
- **Read-only rows** (`editable: false`):
  - Edit and Delete are disabled, as legacy, with no tooltip or explanation (user decision).
  - A small badge with only a lock icon sits beside the name in both the table and the card band;
    screen readers hear "Read-only".
  - A direct `?edit=` link to such a record shows a read-only notice with Close instead of the
    form.
  - A direct `?delete=` link shows the same notice through `DeleteRecordDialog`'s new `blocked`
    option, checked on both the row hint and the direct read.
  - The server never checks `editable`, and no call can change it, so this guard is UI-only, as in
    legacy.

### Rules

- Name is required after trimming, at most 255 characters. Description is optional, at most 4,000,
  sent as `null` when empty.
- A duplicate name is caught by the server and shown on the field. Remarks compare case-sensitively,
  sources case-insensitively.
- Non-editable records cannot be edited or deleted. This is UI-only, as legacy.
- Saves happen at once. Deletes confirm, and the confirmation warns that forecasts and forecast
  lists using the record may stop loading.
- Toasts say Added, Saved or Deleted with the kind named, fixing legacy's "Source of Found".

### Risks

- **Deleting a record that forecasts use** makes those forecasts, and any forecast list page that
  contains them, fail to load. The server has no foreign key and no in-use check, the same as
  legacy. Blocking needs a server change, tracked in FM-214.
- **Renaming** changes the name shown on existing forecasts after reload (the server joins by id).
- **A source deleted elsewhere** would be re-created by a plain PUT; the check read prevents that,
  except for a delete landing between the check read and the PUT.
- **Deleting a missing remark** answers 500 (a server bug); it is handled as a generic error.

## Decisions

1. **Per-tab paging in the URL** (an acceptance criterion); legacy resets it on every switch.
2. **Lookups move to `reference-data`**, so the admin page and the forecast screens share one cache
   and saves refresh both.
3. **Both tabs reuse their lookup and page locally**, following AGENTS.md's rule for management
   lists that share a lookup's endpoint. Both lists are small, and legacy reads them whole too.
4. **Delete behaves as legacy, with no forecast warning** (user decision after review). Legacy and
   the server allow the delete, and checking usage needs a new endpoint; the backend fix is tracked
   in [FM-214](https://openlmis.atlassian.net/browse/FM-214). Read-only rows show only a lock
   badge, with no tooltip or explanation, as legacy.
5. **Edit reads fresh, and a Source save checks first**: the whole-record save rule, and the
   server's PUT re-creates missing sources.
