## Summary

Managers register new cold chain equipment: pick the facility, program and catalog model, then
fill in identification, history and installation details.

Legacy does this in three modals: choose facility, program and model; fill in details; pick a
functional status. Only the last one saves. Required fields are only flagged after a blocking
"This form is invalid" dialog, reloading the second modal loses the work, and models whose energy
source is "Not Applicable" probably cannot be saved at all.

The new UI uses one page, like the other editors in the app: the model choice at the top, the
details and the functional status below, and one Save. After saving, the equipment appears in the
inventory list.

## Legacy Today

- Step 1 `#!/cce/inventory/add` (`CCE_INVENTORY_EDIT`): Facility Type, Program and Facility (EDIT
  grants), Equipment Type (distinct catalog types, unsorted), Make/Model (`manufacturer model`,
  substring type filter, auto-picked when single). Pre-filled from the list query. Cancel asks
  when dirty. Next always enabled; empty fields show a blocking "This form is invalid" dialog.
- Step 2 `#!/cce/inventory//edit`: read-only District, Facility, Program, Type, Make/Model; then
  Equipment Identification (Serial Number*, Reference Name*), Equipment History (Utilization*,
  Year of Installation/Commission* 1000 to 9999, Source, Year of Warranty Expiry 1000 to 9999),
  Equipment Installation (Voltage Stabilizer*, Voltage Regulator*, Backup Generator*, Manual
  Temperature Gauge*, Remote Temperature Monitor*), Additional Notes. Power fields disabled for
  SOLAR and NOT_APPLICABLE energy; prefilled `NOT_APPLICABLE` only for SOLAR. 1500.5 accepted as a
  year. Reload loses the item and returns to step 1 without the search.
- Step 3 `#!/cce/inventory//statusUpdate`: Functionality Status*, Reason* (Awaiting Repair,
  Unserviceable), Decommission Date* (Unserviceable). Update sends the POST, toast "Inventory Item
  saved successfully!", back to the list.
- vsrmanager1: no Add Equipment; direct link shows "You are not authorized". wclerk1: no CCE menu.

## Agent Brief

### API Map

| Step | Method And Path | Params | Fields Used | Right | Legacy Ref |
|---|---|---|---|---|---|
| Enter | permissions (`requirePermissions`) | user | grants | `CCE_INVENTORY_EDIT` and `CCE_INVENTORY_VIEW` | `cce-add-inventory-item.routes.js:29-45` |
| Picker | existing `useFacilityProgramOptions` lookups | none | home facility, programs, facilities | none | `facility-program-cache.service.js` |
| Catalog | `GET /catalogItems` | `archived=false`, `visibleInCatalog=true`, no size | `id, type, manufacturer, model, energySource` + whole item for the body | authenticated | `cce-catalog-item.service.js:120-125` |
| Save | `POST /inventoryItems` | body below | 201 `InventoryItemDto` | `CCE_INVENTORY_EDIT` for the pair, else 403 | `status-update-modal.controller.js:193-213` |

- Body: `facility {id}`, `program {id}`, full `catalogItem` (uniqueness reads its model and type),
  `equipmentTrackingId`, `referenceName`, `utilization`, `yearOfInstallation`,
  `yearOfWarrantyExpiry`, `source`, `voltageStabilizer`, `voltageRegulator`, `backupGenerator`,
  `manualTemperatureGauge`, `remoteTemperatureMonitor`, `additionalNotes`, `functionalStatus`,
  `reasonNotWorkingOrNotInUse`, `decommissionDate` (`yyyy-MM-dd`). Empty optionals left out.
- Enums (`openlmis-cce` domain): Utilization `ACTIVE | NOT_IN_USE | IN_STORE_FOR_ALLOCATION`;
  power `YES | NO | UNKNOWN | NOT_APPLICABLE`; gauge `BUILD_IN | PAIRED | NO_GAUGE`; RTM
  `BUILD_IN | PAIRED | NO_RTM`; energy `ELECTRIC | SOLAR | GASOLINE | NOT_APPLICABLE`.
- Errors `{messageKey, message}`: 400 `cce.error.inventory.*.required`,
  `cce.error.inventory.item.alreadyExists` (serial, type and model taken), 403 without EDIT.

- Route `src/routes/(protected)/_protected.cce.inventory_.new.tsx`, as Reasons new: loader awaits

  (`staleTime: 0`, a catalog upload does not invalidate it); `crumbKey` under CCE Inventory.
- URL: the pair (`mode`, `programId`, `facilityId`, `facilityProgramSearchSchema`) pre-fills the
  form, so links and reloads keep it. History state (`inventoryListSearch`) holds the list's page,
  size, sort and filter for Cancel and Save.
- Query keys: `catalogItems.list()` (new scope, no params); save invalidates `inventoryItems.all` and
  `home.all`.
- Draft guarded by `useDiscardGuard`; save through `useSessionMutation`.

### Rules

- Pickers offer pairs with both `CCE_INVENTORY_EDIT` and `CCE_INVENTORY_VIEW`; the pair from the
  URL is kept when offered, otherwise left blank.
- A required list with one option is picked automatically (programs, facilities, Equipment
  Type, Make/Model). When the home facility offers no program, My Facility is off and the form
  starts on Supervised.
- Make/Model by exact `type`; types and models sorted by label.
- Power fields: `NOT_APPLICABLE` and read-only when energy is SOLAR or NOT_APPLICABLE.
- Required: Serial Number, Reference Name, Utilization, Year of Installation, the five
  installation fields, Functional Status; Reason for Awaiting Repair and Unserviceable;
  Decommission Date for Unserviceable; Make/Model once a type is chosen. These show along with
  the other missing fields. Changing the status clears reason and date, changing the type clears
  the model; picking the same one again keeps them.
- Years: whole numbers 1000 to 9999.
- Server errors shown in an `ErrorAlert` at the top of the page, scrolled into view; the draft
  stays. One request per Save, also on a double click.
- No code comments; exact types from `openlmis-cce`.
- Controls: Facility Type `RadioGroupField segmented`; Program, Facility (supervised), Equipment
  Type, Make/Model `ComboboxField`; Facility (My Facility) a disabled `SelectField` with the home
  facility; Utilization, power, gauge, RTM, Functional Status and Reason `SelectField`; Decommission Date
  `DateField`; Additional Notes `TextareaField`. Selects show Select An Option, as stock events do.
  Two-column grid; the form in one
  `QueryBoundary` (its defaults need the pair options, its rules the catalog); footer Save targets
  the form. Add Equipment is a `role="link"` button carrying the list search in history state;
  the route has `preload: false`, so the catalog is read once per opening.

### Risks And Edge Cases

- Uniqueness is checked across all facilities (serial, type, model); its message is shown as sent.
- 226 catalog types in the demo data: Equipment Type is searchable.
- A real save writes to the local instance only; the item stays in demo data.

## UI/UX

**Port**: all legacy fields, sections, option sets, notes and rules; pre-fill from the search;
EDIT-only access.

**Improve**: one page instead of three modals; functional status in the same form; inline
messages instead of the blocking dialog; exact type filter; sorted, searchable lists; years as
whole numbers; NOT_APPLICABLE items saveable; reload keeps the page; leave prompt instead of a
Yes/No modal.

**Drop**: the separate status modal and its read-only header (the same data is on the page);
the "This form is invalid" dialog; the read-only District on the add step (shown again in FM-100
details). Not ported: `remoteTemperatureMonitorId`, which legacy has no field for.

States: rights pending (real header, skeleton), ready, saving, server error, no catalog items.
RTL: logical classes; names `dir="auto"`. Phone: one column.

## Decisions

- **Page, not modal** (user, 2026-11-02): AGENTS.md puts multi-step, many-field forms on a page;
  FM-100 reuses the editor.
- **Functional status in the form** (user, 2026-11-02): the server requires it on create.
- **Submit-first validation** (user, 2026-11-02), as in the repo and FM-98.
- **Power fields filled for NOT_APPLICABLE energy too**, so those models can be saved.
- **EDIT and VIEW required** (user, 2026-11-03), so a save never returns to a list the user
  cannot open.
- **Selects, not radios** (user, 2026-11-03): `RadioGroupField` shows no validation error; no
  change to the shared component.
- **Return after Save**: the saved pair, first page, sort and size kept; a status filter that
  would hide the new item is dropped. Cancel returns to the list as it was.
- **Status order as Home** (FM-98): Functioning, Needs Attention, Awaiting Repair, Unserviceable;
  legacy lists Needs Attention last.
- **Labels as legacy** (user, 2026-11-03): section Equipment Functional Status, field
  Functionality Status.
