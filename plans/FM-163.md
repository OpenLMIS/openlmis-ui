# FM-163: Report Categories

https://openlmis.atlassian.net/browse/FM-163 · Parent: FM-154 Admin: system & integrations

## Scope

Adds the Administration > Report Categories page: a list of categories with Add, Edit and Delete.
It replaces the `#` nav placeholder and adds the `REPORT_CATEGORIES_MANAGE` right to `RIGHTS`.

Out of scope:

- The dashboard report form and its Category picker belong to FM-162. That ticket moves the shared
  category lookup into `reference-data` when a second feature needs it.
- Backend changes. The report service on master already has every call this page needs.

## Summary

Report categories group the dashboard reports and report templates on the Reports page. An
administrator with the Manage Report Categories right can list them, add one, rename one or delete
one.

Legacy shows every category on one page in the order the server returns them. The Name header
always shows a sort arrow, but clicking it does nothing. Add and Edit open a small dialog with one Name field.
Delete asks for confirmation. Legacy also has these problems:

- The dialog's breadcrumb shows a raw message key.
- A blank name in Add freezes the dialog behind a loading overlay.
- Every save says "created", even an edit.
- A refused delete only says "Failed to delete report category", without the reason.

The new page lists categories sorted by name, and the user can reverse the order. It is paged by the
server. Add and Edit open a dialog with one required Name. A duplicate name is shown on the field.
Delete asks for confirmation. When the server refuses because a report or template still uses the
category, the dialog closes and an error message says so in plain words. After a save, the Reports page shows the change.

## Legacy Today

Screenshots are in `.screenshots/FM-163/legacy-*.png` at 1440 and 390 px. The legacy source is
`openlmis-referencedata-ui@777e31d`, folders `admin-report-category-list`,
`admin-report-category-add` and `report-category`.

- **List** `/#!/administration/adminReportCategories`, gated by `REPORT_CATEGORIES_MANAGE` (menu
  and route).
  - Columns are Name and Actions (Edit, Delete), with Add Category above the table.
  - There is no pager or filter. The route declares `page`, `size` and `sort=name,asc`, but the
    resolver calls `GET` with no params and shows the rows in server order.
  - The Name column is set to `sortable: false`. The header always shows an ascending arrow, set
    from the route's default `sort=name,asc`, but clicking it does nothing (openlmis-ui-components
    `openlmis-table-sorting.service.js:145`).
  - The empty list shows "No Report Categories found.". A failed list read redirects to Home with
    "Internal application error".
- **Add** `/#!/administration/adminReportCategories/add/` and **Edit** `.../add/{id}` open one
  modal state.
  - Edit reads `GET /{id}`.
  - There is one required Name. A blank Add throws a `TypeError` and leaves a loading overlay over
    the dialog. A blank Edit shows "This field is required". Long names are accepted, since the
    column is `text`.
  - Add sends `POST {name}`; Edit sends `PUT /{id} {id,name}`. Either then reloads the list.
  - A duplicate name keeps the modal open with a generic toast, "Failed to create report category".
  - Both Add and Edit toast "Report category created successfully".
  - The breadcrumb shows the raw key `adminReportCategoryAdd.title`.
- **Delete** asks "Are you sure you want to remove `<name>` category?" with Delete and Cancel. It
  sends `DELETE /{id}`, then reloads.
  - Success toasts "Report category deleted successfully.".
  - A refusal drops the server body and toasts "Failed to delete report category.".
- **A missing Edit id** returns 404. Legacy goes back to the list with a global error dialog
  reading "Report category with id {0} not found." with the placeholder left in.
- **Uses elsewhere.**
  - Administration > Reports shows `category.name`.
  - The dashboard report Add/Edit modals read `GET` on open for the required Category picker.
  - Reports > View Reports (openlmis-report-ui `report-list.controller.js`) groups by category
    name, with `Default Category` as the home for reports without one.
- **Timings** once signed in: list 0.4 to 1.1 s, Add 0.1 s, Edit 0.4 s. Saves take 0.9 to 1.6 s
  including the list reload.

## Agent Brief

### API map

`C` = `/api/reports/reportCategories` (openlmis-report@6b33ad6 `ReportCategoryController`).

| Step | Method and path | Params / body | Fields used | Right | Legacy ref |
|---|---|---|---|---|---|
| List | `GET C` | `page` (0-based), `size`, `sort=name,asc\|desc` | `content[].id`, `content[].name`, `totalElements`, `totalPages` | Signed in (OAuth); the page itself requires `REPORT_CATEGORIES_MANAGE` | `report-category.service.js` `getAll` (no params) |
| Edit read | `GET C/{id}` | none | `id`, `name` | `REPORT_CATEGORIES_MANAGE` | `get` |
| Add | `POST C` | `{ name }` (trimmed) | `201 {id,name}` | `REPORT_CATEGORIES_MANAGE` | `add` |
| Edit save | `PUT C/{id}` | `{ id, name }` (trimmed) | `200 {id,name}` | `REPORT_CATEGORIES_MANAGE` | `update` |
| Delete | `DELETE C/{id}` | none | `204` | `REPORT_CATEGORIES_MANAGE` | `remove` |

Errors (`{ messageKey, message }`):

| Condition | Status | `messageKey` | UI |
|---|---|---|---|
| Duplicate name (POST/PUT) | 400 | `report.error.reportCategory.name.duplicated` | Name field error "A category with this name already exists." The PUT message keeps a literal `{0}`, so never show it raw |
| In use by a dashboard report or Jasper template | 400 | `report.error.reportCategory.already.assigned` | Error toast "This category is used by a report or template, so it can't be deleted." The raw message ends in a UUID |
| Not found | 404 | `report.error.reportCategory.notFound` | Edit and Delete reads show a not-found message with shared copy. PUT or DELETE: `apiErrorText` gives the translated `api-error.report.error.reportCategory.notFound` "This category no longer exists." and the list refreshes. The raw message can hold a literal `{0}` |
| PUT body id differs from the path id | 400 | `report.error.reportCategory.id.mismatch` | Cannot happen, since the UI always sends the path id; generic `apiErrorText` |
| No right | 403 | `report.error.permission.no.permission` | Edit and Delete reads show an in-place no-access message. Writes use `apiErrorText` |

The server accepts empty and whitespace-only names (POST `201`, PUT `200`), so the form must refuse
them. There is no length limit. Without `size`, or with `size=0`, the list returns every row. An
unknown sort field answers 500, so the search schema allows only `name`.

### Data flow

- Route `src/routes/(protected)/_protected.administration.report-categories.tsx`:
  - `staticData: { rights: [RIGHTS.reportCategoriesManage] }`.
  - The loader awaits `requireRouteRights`, then calls `prefetchQuery` on the list without
    awaiting it.
  - Since the loader blocks on rights, the route gets a `pendingComponent`
    (`ReportCategoriesPagePending`): the real header, a disabled toolbar and the table or card
    skeleton, as Service Accounts does.
- The URL holds `tableSearchSchema(['name'])` with the default `name` ascending kept out of the
  URL, plus optional `category` (`z.union([z.literal('new'), z.guid()])`) and `delete`
  (`z.guid()`), each falling back to `undefined` when invalid, as Service Accounts'
  `lib/search.ts` does. When both are present, `category` wins and `delete` is ignored, as Service
  Accounts does. Use `useSearchNavigation(CLOSED_DIALOGS)`.
- Query keys sit under `queryKeys.reportCategories`:
  - The admin list uses `list({ page, size, sort })`.
  - The Edit detail uses `[...detail(id), 'edit', opening, reread]` (`reread` 0 or 1) with
    `useOpening()`, so every opening reads fresh. It is not prefetched. Dialog ids in the URL are
    lowercased, as the server returns them.
  - The save mutation key includes the category id. A reopened Edit keeps its fields, Cancel and
    Save disabled while a save for that id is still pending, tracked by one fixed filter over all
    pending category saves so switching categories never leaves a stale flag. When that save
    settles, the reopened dialog rereads the category under a new key (loading skeleton, then the
    server's current name), so neither a stale read nor a delayed PUT response can unlock with an
    old name. A failed reread shows the usual load error. The saving dialog itself never waits on
    a reread.
  - The Reports catalog keeps its own `list({ userId })`.
  - Every successful save and delete, and every PUT or DELETE that answers 404, cancels and then
    invalidates the list keys, `[...queryKeys.reportCategories.all, 'list']`. That covers this list
    and the Reports catalog. Delete leaves its detail cache alone so the closing dialog keeps its
    name. This is FM-155's `notificationListsKey` pattern.
  - A rename also cancels and then invalidates `queryKeys.dashboardReports.all` and
    `queryKeys.reportTemplates.all`, so a read already in flight cannot return the old name. Both
    embed `category.name` in their responses. These are shared key roots, so no feature import is
    needed.
  - After each cancel, an await, so `isCurrent()` is checked before invalidating, as FM-155 does.
- Rows read `useDeferredValue(search)`. The toolbar sits outside `QueryBoundary`.
- When a delete leaves a page past the end, clamp it to the last page, as FM-155 does
  (`notifications-table.tsx:246`). The clamp reads `totalPages` from the current, non-deferred
  result and replaces history after the dialog has closed, so it never competes with the dialog's
  Back. An empty list falls back to page 1.
- The Delete dialog's name:
  - Opened from a row, the dialog captures the row name at mount and sends no read, as legacy
    does. The route clears the hint as soon as the URL leaves that Delete target. The dialog keeps
    displaying the captured name during its close animation.
  - A direct link or browser Forward mounts fresh content with a new
    `[...detail(id), 'delete', opening]` key, even if Forward interrupts the close animation.
    It reads `GET C/{id}` and keeps Delete disabled until that read succeeds. This adds the
    existing detail call, which legacy used only for Edit, to a path legacy did not have.
- Focus:
  - Delete opens with focus on Cancel.
  - Cancel returns focus to the row's opener when that row is still there.
  - After a successful DELETE or a DELETE that returns 404, focus goes to the toolbar's Add button.
    That button also receives focus when a dialog closes without a row opener.
  - Add and Edit return focus as FM-155 does.
- The Delete dialog is an `AlertDialog` modelled on `products/components/remove-approval-dialog.tsx`:
  - It draws its own loading, connection failure (with Retry), no-access, not-found and found
    states. Edit uses `FormDialog` parts and shares the load-error, not-found and no-access copy.
    A refused read offers Close and explains that managing categories requires the Manage Report
    Categories right.
  - The confirmation sentence is capped at four lines so a long name leaves the actions visible
    on phones. Status descriptions can wrap to their full length.
  - On success it keeps the deleted name until that opening finishes closing.

### Risks

- Postgres collation decides the order of names that differ only in case or accents. It matches
  legacy's server, so it is acceptable.
- Deleting from another tab: DELETE answers 404. The dialog closes, focus returns to Add Category,
  the list refreshes and a toast says "This category no longer exists."
- Renames are allowed while reports use the category, as in legacy. Reports link to it by id and
  follow the rename. Template upload (`POST /api/reports/templates/common`, API only, no UI) finds
  its category by name, so callers using the old name break.
- `Default Category` is the fallback group for reports without a category, both in legacy View
  Reports and in our catalog (`src/features/reports/lib/report-categories.ts:11`). Renaming or
  deleting it moves those reports into the Other group. This matches legacy and is not blocked.

## Decisions

1. **Server paging and sort.** The endpoint supports `page`, `size` and `sort`, so the list follows
   AGENTS.md's server-paged list rather than legacy's single unsorted page. The calls are the same as
   legacy's, with params added.
2. **Own feature, lookup stays.** The admin page lives in `src/features/report-categories/`. The
   Reports catalog keeps its category lookup. Both share the `reportCategories` key root, so a save
   refreshes both. FM-162 moves the lookup into `reference-data` when its form needs it.
3. **The in-use refusal is translated.** The raw server text ends in a UUID, so the known key gets a
   translated sentence. Unknown refusals still show the server's message, which meets "its error is
   shown".
4. **Trim names.** Whitespace-only names are refused and the trimmed name is sent, so " Stock"
   cannot sit beside "Stock".
5. **No search or filters.** Legacy has none, and categories are a short list.

## Open Questions

None. Decision 1 departs from legacy only by adding sort and paging params to the same call.
