# FM-189: Issue and Receive Table Fit

https://openlmis.atlassian.net/browse/FM-189

## What Ships

User decisions: Fit Doses only; ship the two-line dropdown trial as is, accepting English
Receive's remaining 77px of horizontal scroll. Packs uses the same dropdown sizing, so it
scrolls less than before but does not fit.

Issue and Receive size destination/source and reason dropdowns to the largest of each
option's smallest two-line widths, splitting only at spaces. Selected values wrap onto at
most two lines without splitting words. Headers and every other column keep their existing
behavior. Adjustments and Unpack have no compact dropdown policy; Unpack's measured fit
branches remain untouched.

`twoLineSelectMinWidth` is 1100px: 19px below the 1440 layout's 1119px table width, with at
least 139px of separation from the 1280 layout's approximately 961px content width.
It applies in both units so switching units does not resize the dropdowns. Undefined widths and narrower containers retain existing
sizing. One pure test checks the threshold and all four kinds.

## API Calls

No API changes. Reuse existing GET lookups for rights, facility/program, stock cards,
products, lots, valid sources/destinations and reasons. Headless verification replays real
test-server responses and stubs every non-GET request under `/api/`. No records are saved.
