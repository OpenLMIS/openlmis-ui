## Scope

The online Transaction History list, the event detail page it opens, and the links to that
page from the Stock Card's Document Number, Reversing and Reversed By (the three FM-76 `TODO`s
left by [FM-70](FM-70.md)).

Not in scope:

- Reverse transaction ([FM-77](https://openlmis.atlassian.net/browse/FM-77)), the only part that
  writes. It gets its own PR right after this one. Until then the detail page has no Reverse
  button. FM-71 stays open until FM-77 ships.
- Offline. All of Stock ships online first. Legacy does not offer these pages offline either; the
  app's existing offline notice already says the page needs a connection (checked, not built).
- Backend changes. Every call below is on stockmanagement master and identical in v5.4.1.

## Summary

Transaction History lists the stock events recorded for one facility and program: every issue,
receipt and adjustment, newest first, with who recorded it and how many lines it had. Opening one
shows the whole event: each product and lot it touched, where stock came from or went to, the
reason, the quantity and the stock on hand right after it, and which events reversed it.

In legacy the user picks a facility and program, can filter by type, dates and document number,
and pages ten at a time. The detail page prints the event as a PDF and offers Reverse to users
allowed to cancel stock events. Legacy accepts an end date before the start date and silently
shows nothing, its detail page has no way back to the filtered list, and links from a Stock Card
lose where the user came from. Errors appear as pop-up alerts that leave the user on the old page.

The new pages keep the same picker, filters, columns, order, paging, Packs or Doses and Print. An
impossible date range is refused with a message, the breadcrumb leads back to the list with its
filters, every state (loading, empty, no matches, not found, no access, error) is shown in the
page, and a link from a Stock Card opens the event directly. Physical inventories and kit unpacks
are not listed, as in legacy, because the server only records issues, receipts and adjustments
here.

Server facts: list order is fixed (`processedDate DESC, id DESC`, `sort` ignored); an unknown
`type` is a 400; an inverted date range is a 200 with no rows; an unknown event is a 404
(`stockmanagement.error.event.notFound`), a malformed id a 400. Old seeded events have `type` and
`documentNumber` null and `reversible` false; their line count can far exceed `entriesCount`.

### Data flow

- **List route** `/stock-management/transaction-history`, copying Stock On Hand: loader awaits
  `requirePermissions`, prefetches the picker lookups and, once the selection is complete,
  granted and the date range valid, the events page, all deferred. Toolbar outside the
  `QueryBoundary`; rows read `useDeferredValue(search)`.
- **Detail route** `/stock-management/transaction-history/$eventId` (file
  `_protected.stock-management.transaction-history_.$eventId.tsx`), copying the Stock Card: loader
  blocks on `requirePermissions` and the header (fresh on enter, as the card), checks
  `hasProgramGrant(STOCK_CARDS_VIEW, event.facilityId, event.programId)`, and prefetches the
  current lines page deferred. Header renders at once; only the lines suspend. `preload: false`.
- Query keys: new `stockEvents` scope with `list(params)` and `detail(id)`; an event's lines sit
  under its detail key, so invalidating the scope refreshes both.
- URL: list `mode`, `programId`, `facilityId`, `type`, `startDate`, `endDate`, `documentNumber`,
  `page`, `size` (no sort). Detail: the same plus `detailPage`, `detailSize`.
  `crumbParentSearch` parses the list schema.
- A user change reloads as on the Stock Card (`useReloadForUser`; move it to `src/hooks/` now that
  two routes use it).

### Rules

1. List only for a complete, granted selection, as Stock On Hand.
2. Type labels: `ISSUE` Issue, `RECEIVE` Receive, `ADJUSTMENT` Adjustment; null shows `EMPTY_VALUE`.
3. List Date is `processedDate` as a date; header Date is `processedDate` with time and seconds,
   both in the deployment's time zone (`timeZoneId` from `/localeSettings`), as legacy's
   `openlmisDatetime` does; line Date is `occurredDate`, a calendar date that never shifts.
4. Product is "Name (Code)", as legacy's detail shows it; no lot shows "No Lot Defined".
5. Source, Destination and Reason use `namedWithFreeText`, so a physical inventory line keeps its
   recorded reason name, as legacy's detail does.
6. Quantity and Stock On Hand both convert with `cardQuantity(value, orderable.netContent, unit)`.
7. Reversing links to `reversedEventId`, Reversed By to `cancellationEventId`, labelled with the
   other event's document number or "View", as legacy; following one resets `detailPage` and keeps
   `detailSize`. On the Stock Card a Document Number without one still reads "No Number".
8. End date before start date: no request, inline message with Clear Dates.
8a. The list shows 20 a page by default, legacy's first page (user, 2026-10-08); Type offers All,
   Issue, Receive and Adjustment; Document Number is sent as typed; the filters can be set before
   Search, as legacy's are, and the request still waits for the facility and program.
9. Print disabled when the event has no lines.
10. Detail opens only with the exact `STOCK_CARDS_VIEW` grant for the event's facility and program.
11. `canReverse` = exact `STOCK_EVENTS_CANCEL` grant and `reversible` (used by FM-77).
12. Stock Card links: Document Number only when the line has `eventOrigin`, to `originEventId`.

### Risks and edge cases

- Old events (null type, null document number, thousands of lines) must render and page.
- A Stock Card or reversal link opens an event of any facility and program; the grant check uses
  the event's own pair.
- An event whose facility and program differ from the list search in the URL still opens; the
  crumb returns to the list the user came from.

## Decisions

- Feature folder `stock-events`, after the API resource, like `stock-card`.
- No sort controls: the server's order is fixed, as legacy.
- Physical inventory and unpack are not offered as types: the server does not list them (legacy
  same).
- Stock Card links carry the card's `mode`, `programId` and `facilityId`, so the detail's crumb
  leads to Transaction History for that same facility and program; legacy drops them.
- Shared label helpers move to `src/lib/stock-labels.ts` rather than duplicating them.
- The shared picker searches its programs like legacy's, with "Select Program" and "Select
  Facility" placeholders and a clear action, and a Supervised link to a program the user holds at
  home opens as My Facility, as legacy lists it (user, 2026-10-08).
- The shared picker leaves a linked program or facility it does not offer blank, instead of showing
  its raw id or picking another one, while the page says the link is refused. Stock On Hand gets
  the same fix.
- No Reverse button until FM-77, which comes next; the right check is built and tested here
  (user, 2026-10-07).
- Real data on test: record an issue, a receipt, an adjustment with document numbers and one
  reversal through legacy at Comfort Health Clinic, Family Planning, as `administrator`, and check
  the new pages against them (user, 2026-10-07). Routine checks still stub every write.
