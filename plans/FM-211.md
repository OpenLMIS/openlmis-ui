# FM-211: Onboarding Tour: Reverse, CCE Inventory And Reports

https://openlmis.atlassian.net/browse/FM-211 · Parent: [FM-199] Guided onboarding tours for new users
(React Joyride, isolated module)

Stacked on FM-210 (PR #164).

## Scope

- **In:** four tours, one per screen: Reverse Transaction, CCE Inventory, View Reports, Generate Report.
- **In:** `data-tour` attributes and plain wrappers on those screens, new keys in `TOUR_ANCHORS`; reuse of
  the shared `list-*` anchors and `onboarding.list.*` steps.
- **In (all tours):** no pager step anywhere (user, 2026-11-20): removed from the Administration list and
  editor, requisition workflow and Orders tours, with `pagerStep`, the `list-pager` anchor in
  `data-table-pagination.tsx` and its copy. Separate commit.
- **Out:** dialogs (CCE item details, status, transfer, add; Reverse confirm, signature, summary; the
  invalid-form alert): portalled, so steps describe them. No screen changes beyond attributes and
  wrappers, per the block rule.

## Summary

Four more screens get a Show Guide button. Reverse walks through ticking the lines to cancel, choosing
why, the new stock balance and Submit. CCE Inventory explains choosing a facility and program, the
toolbar (export, filters, view, add), the equipment list, what each functional status badge means and
how to open an item. View Reports explains the categories and opening a report; Generate Report explains
the report's options, the file format and Generate. Each page plays only the steps for the parts it
shows, so a user without edit rights or before searching sees fewer steps. Legacy has no guide.

### Rules

  the grant (vault A70, FM-204).
- No anchor on skeletons; every loading part these steps need is already busy (lists, catalog, picker).
- Copy is generic per screen and true on table and cards; server-named labels (report names, categories)
  are not quoted.

## UI/UX

- **Improve:** a guide where legacy has none.
- **Phone:** cards; column steps fall back to the list.
- **Arabic:** placements mirror through the module; server names stay in English.

## Decisions

1. **One tour per screen:** the four screens share no parts.
2. **CCE status legend** (as Orders and Offline Events): badges drawn as the list draws them, so the step
   reads true on any page of results.
3. **Reports catalog:** steps hang from the first category heading and first link, since the number of
   groups varies and the whole catalog would leave no room for the tooltip.
4. **No pager steps:** paging is self-evident (user, 2026-11-20).
5. **No `aria-busy` on late lookups:** no step targets them; adding it would delay every tour by up to
   20 s on Generate.
